# 产品愿景

## 一句话

**FlyCut Caption 帮口播创作者把录好的视频变成可发布的成片：自动出字幕、去掉停顿和口癖、翻译配音，再从长视频里剪出短视频。**

## 要解决的问题

一切从「把视频/音频里的话转成带时间戳的文字」（ASR）开始，在这份文字上长出两条线：

- **字幕线**：添加字幕 → 字幕样式与特效 → 多语字幕（字幕翻译）→ 配音（TTS 语音翻译、声音克隆）
- **剪辑线**：按文字剪视频 → 去静音、去口癖 → 长视频自动剪成短视频

两条线共用同一份带字词时间戳的转写结果，所以**转写质量决定两条线的上限**。能力拆分见 [capability-map.md](capability-map.md)，排期见 [roadmap.md](roadmap.md)。

## 目标用户

**首批：口播创作者。** 来源：维护者 2026-11-04 确认。

| 项目 | 描述 |
|---|---|
| 是谁 | 对着镜头讲的个人创作者：知识分享、产品测评、课程讲解、Vlog 口播；发 B 站、抖音、小红书、视频号、YouTube |
| 典型素材 | 单人、单机位、10–60 分钟的长录制，中文为主，夹杂英文术语（维护者 2026-11-04 确认） |
| 现在怎么做 | 剪映「智能字幕」出字幕，手动逐段删停顿、口误和重录；想出海就再找翻译、配音工具；切短视频靠手动挑片段 |
| 最痛的地方 | 粗剪（删停顿、口癖、重复）花的时间比录制还长；字幕校对累；多平台、多语言版本要重复做 |
| 在意什么 | 省时间；剪辑点准、不吞字；字幕准确；素材不想随便上传；价格 |

后续用户（暂不针对性设计）：课程/访谈运营者、需要批量处理的团队、通过 MCP / CLI 调用的 Agent 用户。

## 平台

**先桌面端（Tauri），再 Web，两端功能对齐。** 新功能先在桌面端发布，Web 端随后补齐，最终两端能力一致；暂不考虑 npm 组件库。来源：维护者 2026-11-04 确认。

原因：口播素材大，桌面端可以本地识别、本地导出，不用上传，所以先做；Web 端免安装，同样要能完成完整流程。

对齐的含义：Web 端的识别、导出等依赖 Host，需要连接远程 Host（FlyCut Cloud 或用户自己部署的 Host）；每个需求的需求说明都要写明两端各自如何满足验收标准，桌面端先发时注明 Web 端补齐的计划。

### 开源与 Agent 方向

| 项目 | 情况 | 启发 |
|---|---|---|
| [VideoCaptioner](https://github.com/WEIFENG2333/VideoCaptioner)（卡卡字幕助手） | GPL-3.0，约 1.6 万星；识别、断句、LLM 校正、翻译、烧录一条龙 | 字幕线最直接的开源竞品；它没有剪辑线 |
| [AutoCut](https://github.com/mli/autocut) | 约 7.8 千星，按文字剪视频，2024 年后不再更新 | 需求存在，但没人持续做成产品 |
| 小映视频助手（XYCut） | 让 Codex 等 Agent 找出重复、口误、气口，人工在剪辑页确认，生成剪映草稿 | **Agent + 人工确认 + 剪映草稿** 已经有人在做，和我们的方向一致 |
| A-Roll-Roughcut（开源 Skill） | 云端 ASR + LLM 判断口误、气口、重复，网页审片面板，导出视频或 SRT | 口播粗剪正在变成 Agent Skill，MCP / Skills 是获客渠道 |

### 我们的差异

1. **中文口播优先**：针对中文口播调识别、断句、口癖词表，这是 Descript、Gling 等英文产品的空位。
2. **本地优先**：桌面端离线识别、本地导出，素材不出机器；需要时再用 FlyCut Cloud 或自己的 Provider。
3. **一条龙**：同一份转写贯穿字幕、翻译、配音、粗剪、短视频，不用在多个工具之间导来导去。
4. **可被 Agent 调用**：MCP / CLI 让 Codex、Claude Code 等直接调用，同时保留人工确认。
5. **开放**：Provider 可替换，源码可见。

风险：剪映免费且用户基数大。应对：粗剪和字幕做到明显更准、更快，并支持导出剪映草稿，让用户在剪映里继续精剪。

## 获客方式与途径

以下是待验证的假设，每个渠道上线后在 [roadmap.md](roadmap.md) 的度量里跟踪。

| 渠道 | 做法 | 对应能力 |
|---|---|---|
| 内容平台（B 站、小红书、抖音、视频号） | 发「口播 10 分钟粗剪」类教程和前后对比；用 FlyCut 剪出来的视频本身就是案例 | 去静音、去口癖、字幕特效 |
| 开源社区（GitHub、V2EX、少数派、即刻、X） | README 演示动图、版本更新帖、技术文章 | 全部 |
| Agent 生态（MCP 市场、Skills 市场） | 发布 FlyCut MCP Server 和 Skill，让「用 Agent 剪口播」的用户找到我们 | E-08 |
| 创作者社群与课程作者 | 找口播类博主、课程作者试用，换取反馈和推荐 | 全部 |
| 剪映生态 | 导出剪映草稿，让 FlyCut 成为剪映用户的粗剪前置工具（维护者 2026-11-04 确认要做） | E-06 |

后续再考虑：把 Web 版拆成「在线生成字幕」「视频去静音」等单一功能的工具页，承接搜索流量。

## 成功指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 激活 | 新用户首次成功导出一个视频或字幕文件的比例 | 待定（上线基线后设定） |
| 粗剪省时 | 处理一段 20 分钟口播的总耗时，对比手动粗剪 | 待定 |
| 剪辑准确 | 去静音 / 去口癖建议被用户接受的比例 | 待定 |
| 留存 | 首次使用后 30 天内再次处理视频的比例 | 待定 |

这些指标需要先有数据来源。桌面端目前没有使用统计，是否加入匿名统计要单独决定（见 E-08）。

## 不做

文生视频、图生视频、素材生成平台、多轨剪辑器、通用可视化工作流画布。

口型同步不自研，作为 E-05 配音的后续候选需求，通过 Provider 接入第三方服务（维护者 2026-11-04 确认）。
