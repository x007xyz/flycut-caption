# E-02 项目与字幕编辑

## 要解决的问题

口播创作者通常是一个主题、一个系列录好几段视频，但现在一次只能处理一个视频，关掉应用后字幕和剪辑结果就丢了：`appStore` 只把设置存到浏览器本地，字幕、剪辑都不保存。校对也缺工具，字幕编辑器里没有查找替换。

## 做完是什么样

- **项目管理**：一个项目里可以放多个视频；有项目列表，可以新建、重命名、删除项目，在项目里添加、切换、移除视频。参考 OpusClip 的项目管理方式。
- **数据由 Host 保存**：Web 端和桌面端都通过 Host 保存项目数据和媒体，同一套接口和数据格式。桌面端连本机 Host，Web 端连远程 Host（E-08/6）。重新打开应用或换一台连同一个 Host 的设备，项目都在。
- **不丢工作**：编辑自动保存到 Host（F-0002）；异常退出后能恢复（E-02/7）。
- **校对高效**：快捷键、查找替换、批量替换；AI 纠错以差异形式逐条确认。
- 项目数据是后续 CLI / MCP（E-08/1、E-08/2）的数据来源。

## 不做

多人协作编辑；导出剪映草稿（属于剪辑线，见 E-06/5、E-06/6）；FlyCut Cloud 的账号、权限和计费（另行建设，不在本仓库）。

## 设计要点

立项后在设计阶段（02-design）处理，并写 ADR：

- **数据模型**：项目 → 视频 → 每个视频的转写、字幕、编辑决策、样式；项目级共享的设置（字幕样式、口癖词表、术语表、目标语言）；产出物（导出的成片、字幕文件、以后的短视频）。带格式版本号，旧版本数据可迁移。
- **Host 存储**：项目元数据存在 Host（`hostConfig.home` 下），通过 RPC 读写；前端不再是数据的来源。现有资产存储有 24 小时自动清理（`assetTtlHours`），**项目里的媒体和产出物必须排除在自动清理之外**，只在用户删除视频或项目时删除。
- **桌面端的媒体**：60 分钟的素材复制进 Host 会占双份磁盘。是复制、移动，还是只记录原文件位置（需要遵守「RPC 不接收任意本地路径」的决定，由 Tauri 外壳登记），要在 ADR 里定。
- **一致性**：多个窗口或设备同时打开同一个项目时，用版本号检测冲突，不静默覆盖。
