# E-04 多语字幕

## 要解决的问题

想出海或面向多语言观众的口播创作者需要多语言字幕。现在只支持一条副字幕（双语），长视频翻译容易失败，翻错了也不容易发现。

## 现状（2026-11-05）

翻译在 `shared/text/OpenAICompatibleEngine.ts`，走已配置的 OpenAI 兼容模型：

- **一次请求发出全部字幕。** 返回条数不一致就整体报错，长视频容易撞上模型上下文或输出长度限制。
- **按字幕条逐条翻译，没有上下文。** ASR 的字幕条常把一句话切成几条，逐条翻容易翻错、语序别扭。
- **缺失的译文静默回退成原文。** 返回结果缺某个 id 时直接填原文，用户看不出哪条没翻；AI 纠错共用这段逻辑。
- **字幕字体只内置 Noto Sans SC 和 Inter。** 日文、韩文、泰文、阿拉伯文等烧录时会缺字。

## 目标用户与竞品

- **目标用户**：想出海的口播创作者。在 YouTube 上传多语言字幕轨；在 B 站、抖音用中英双语烧录。
- **竞品**：剪映（字幕翻译、双语字幕）、YouTube 自动翻译、Rask.ai / HeyGen（翻译与配音一体）。
- **差异**：基于已校对的原文翻译，术语一致，逐条可改，与剪辑结果同步（共用编辑决策的时间映射）。

## 做完是什么样

- 一个项目可以有多条语言轨道，旧项目和双语导出继续可用。
- 长视频翻译稳定：按语义句带上下文翻译，分批、严格校验、单批失败可重试；结果逐条可改。
- 原文修改后，对应译文标为过期，可以只重翻这几条。
- 项目术语表保证专有名词翻译一致；可以按语言分别导出字幕，或导出多条软字幕轨。

## 不做

人工翻译协作平台。专用机器翻译接口（DeepL、Google 翻译等）暂不接入，只用已配置的 AI 模型：大模型能带上下文和术语表，口播口语翻得更自然；以后需要时作为 Provider 能力接入。
