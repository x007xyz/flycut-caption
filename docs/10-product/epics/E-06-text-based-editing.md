# E-06 按文字剪辑

## 要解决的问题

口播创作者花最多时间的是粗剪：删停顿、删「嗯、啊、那个」、删说错重说的地方。现在已有：

- 删字幕剪视频。
- 智能剪空白：编辑器插件注册表里的 `delete-silence`，按**字幕句子之间的空隙**判断，默认 ≥1.5 秒（`smartCutSilenceThreshold`）。句子内部的停顿找不到，阈值对口播偏大，切点不留余量，也没有淡入淡出。

问题：时间映射分散在前端，导出、字幕、以后的配音没有统一的剪辑结果；去口癖还没有。

## 成熟做法（2026-11-05 调研）

**去静音**：[auto-editor](https://github.com/WyattBlue/auto-editor)（响度阈值 + 切点前后各留 0.2 秒）、[Silero VAD](https://github.com/snakers4/silero-vad)（MIT）、FunASR FSMN VAD（MIT，sidecar 已内置）。共同要点：

1. 用 VAD 或音量判断有没有人声，字词时间戳只用来保证切点不落在字中间。
2. 切点前后留余量，不吞字头字尾。
3. 长停顿压缩到 0.2–0.3 秒，而不是全部删掉，保留说话节奏。
4. 切点处做几毫秒的淡入淡出，避免爆音。

**去口癖**：没有现成的单一方案，中文口播工具都是组合做法。[videocut-skills](https://github.com/hobart9527/videocut-skills) 用纯规则（语气词、叠词卡顿、相邻句开头重复、「不对」改口）；[touge-spoken-cut](https://github.com/touge1618/touge-spoken-cut)（Apache-2.0）用 LLM 语义判断 + 程序校验，拿不准的交给人工。结论：**规则处理能确定的，LLM 处理要看上下文的，最后由人确认。**

不能用：CrisperWhisper（权重禁止商用）、PodcastFillers（英文数据集，禁止商用）。

**前提**：ASR 要把口癖原样转写出来。现有 SenseVoice 基线保留了语气词（`zh-podcast` 3 分钟里「啊」24 次、「呃」9 次、「额」9 次），但「额」「呃」混用，词表要两个都收。召回率和短词时间戳误差由 E-01/1 量化。

## 做完是什么样

- 所有剪辑操作产出同一份编辑决策（保留 / 删除区间），字幕、译文、配音、导出都基于它变换时间，不会错位。
- **去静音**：按音频判断人声（VAD），句内停顿也能找到；可调最短静音时长、前后余量、压缩停顿还是删除；切点不落在字中间，切点有淡入淡出；预览后应用，桌面端导出准确。
- **去口癖**：
  - 规则层：单独出现的嗯、啊、呃、额，叠词卡顿（「那个那个」）。内置词表，离线可用。
  - 语义层：要看上下文才能判断的「就是 / 那个 / 然后」，句内重复、口误改口（「A…不对…B」删 A）、说一半重来的残句。由 LLM 返回要删的字词编号，程序校验后才成为建议，拿不准的标出来。
  - 每条建议带原文、时间范围、类别和原因，可以逐条或按类别批量接受。
- 可以导出剪映草稿：字幕和剪辑结果写入草稿，用户在剪映里继续精剪。

## 不做

多轨剪辑、转场、B-roll 素材。去重录（同一段话录了好几遍，从中选最好的一遍）暂不做，以后按需求立项；去口癖语义层只处理一句话内部和相邻句之间的重复与改口。

## 验收素材要求

去静音和去口癖必须用**未剪辑的原始口播录制**验收（至少 2 段，含明显停顿、语气词和改口）。现有的 `bili-BV1Rex26dEWF` 已粗剪过，停顿少，只能作对照。缺少原始素材时，由 E-01/1 一并补充。
