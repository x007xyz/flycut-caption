# 路线图

各阶段内部按顺序推进；跨阶段的先后由需求依赖决定（`pnpm feature` 的依赖门禁），没有依赖关系的需求可以并行开发。规划（立项、PRD、设计）可以提前做。每个 Epic 的候选需求和依赖见各 Epic 文档；立项后编号为 `F-NNNN`，并把编号回填到 Epic 文档里。

## 阶段一：把口播粗剪做到可用（P0 + P1 剪辑线）

目标：口播创作者导入一段长录制，几分钟内得到字幕准确、去掉停顿和口癖的成片或剪映草稿。

| 顺序 | 候选需求 | Epic |
|---|---|---|
| 1 | 中文口播转写质量基准（调研） | E-01/1 |
| 2 | 项目数据保存到 Host：字幕和剪辑结果保存与重新打开 | E-02/1 |
| 3 | 项目管理：一个项目多个视频 | E-02/6 |
| 4 | 崩溃恢复（自动保存已并入 E-02/1） | E-02/7 |
| 5 | 统一时间映射与编辑决策（EDL） | E-06/1 |
| 6 | 去静音：VAD、余量、压缩停顿、预览、桌面导出 | E-06/2 |
| 7 | 去口癖·规则层：语气词、叠词卡顿，建议 + 确认 | E-06/3 |
| 8 | 去口癖·语义层：LLM 判断重复、改口（调研 → 功能） | E-06/7、E-06/8 |
| 9 | 导出剪映草稿（调研 → 功能） | E-06/5、E-06/6 |
| 10 | 校对体验：快捷键、查找替换、批量替换 | E-02/2 |
| 11 | AI 纠错按差异确认 | E-02/3 |
| 12 | Web 端连接远程 Host，阶段一功能在 Web 端补齐 | E-08/6 |

## 贯穿各阶段

E-08：

- 安装包签名与公证（E-08/8）在第一次公开发布桌面端之前完成。
- AI 模型设置存到 Host（E-08/7）在 MCP / CLI 之前完成。
- MCP / CLI（E-08/1、E-08/2）在阶段一结束后开始，同时作为获客渠道。
- 崩溃收集与匿名统计（E-08/5）待调研后决定。
