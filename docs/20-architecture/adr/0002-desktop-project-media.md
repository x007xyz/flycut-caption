# ADR-0002 桌面端项目媒体的保存方式

## 背景

项目重新打开时要能播放和导出原视频（F-0002 AC-5、AC-6）。现状：

- 桌面端通过 `pick_media_file` 拿到本地路径，播放用 `convertFileSrc`；识别时前端解码出 16k WAV 上传；导出时把整个源文件上传到 Host 的 `assets/`。
- Host 的 `assets/` 有 24 小时自动清理，不能当项目存储。
- 已拍板：**RPC 不接收任意本地路径**（[decisions.md](../../decisions.md#架构)）；E-02 设计要点写明，如果选择「记录原文件位置」，路径只能由 Tauri 外壳登记。
- 口播素材 10–60 分钟，1080p 约 1–6 GB，4K 可达 20 GB 以上。
- Web 端的媒体本来就在浏览器里，只能上传给 Host。

## 决策

**Web 端：上传后存进项目目录。桌面端：记录原文件位置，不复制；路径只能由 Tauri 外壳登记。**（维护者 2026-11-05 选定）

桌面端的做法：

1. Tauri 外壳记下用户**亲自选择**的文件：`pick_media_file` 返回的路径（以后加上窗口拖入事件里的路径）放进一个只在本次运行有效的允许列表。
2. 新增 Tauri command `link_project_media(path)`：只接受允许列表里的路径；由 Rust 用启动 Host 时生成的**外壳密钥**调用 Host 的登记接口，Host 记录路径、文件大小、修改时间和首尾各 1 MB 的指纹，返回一个 `mediaRef`。前端只拿到 `mediaRef`，RPC 里不出现路径。
3. Host 的登记接口只认外壳密钥，不认前端 token；`server` Profile 下整个接口关闭，并通过 `ctx.rpc.capability` 告知前端（符合 [cordis-host.md](../../subsystems/cordis-host.md) 对「读取本地路径的插件」的要求）。
4. 打开项目时，Host 检查文件是否还在、大小和指纹是否一致；不一致就报「媒体丢失」（AC-7），用户重新选择文件后重新登记。
5. 播放仍用 `convertFileSrc`；导出时 Host 直接读原文件，不再整份上传（这一点可以留到后续需求，F-0002 先保持现有导出方式）。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **桌面端记录原文件位置，外壳登记（选定）** | 不占双份磁盘，打开项目不用等复制；导出以后可以免上传 | 要改 Rust（允许列表、外壳密钥、登记调用）和 Host（只认外壳密钥的接口）；用户移动或删除原文件后项目会「媒体丢失」 |
| 桌面端也复制进项目目录 | 实现最简单，沿用现有 `/assets` 上传，不碰「RPC 不收路径」的决定；项目自成一体，移动原文件不影响 | 占双份磁盘（60 分钟 4K 素材 20 GB 以上）；新建项目要等复制完成 |
| 移动原文件进项目目录 | 不占双份磁盘，项目自成一体 | 用户的文件「不见了」，违反直觉；跨磁盘时实际是复制 + 删除，失败时有丢文件风险 |
| 前端把本地路径直接传给 RPC | 实现最省事 | 违反已拍板的决定：远程 Host 下等于让网页指定 Host 读任意文件 |

## 后果

- 选「记录位置」时：F-0002 的任务里要加 Rust 和 Host 两侧的登记通道，以及对应的安全测试（非允许列表路径被拒绝、前端 token 调登记接口被拒绝、`server` Profile 下接口不存在）。
- 选「复制」时：新建项目前要检查磁盘空间，复制过程显示进度；AC-7 的「媒体丢失」只在项目目录被手动改动时出现。
- 无论哪种，`project.json` 的 `media` 字段都区分 `stored`（项目目录里）和 `linked`（外部文件），以后可以在两种方式之间迁移，例如 E-02/8 导出项目时把 `linked` 的媒体一并打包。
