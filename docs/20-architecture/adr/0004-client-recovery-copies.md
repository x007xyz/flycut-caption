# ADR-0004 客户端临时恢复副本

## 背景

F-0004 立项和 PRD 已获维护者确认。Host 无法恢复从未收到的修改，因此维护者批准客户端临时恢复副本的受限例外。Host 仍是正式项目数据来源。需要同时应对进程崩溃、响应丢失和多窗口版本冲突，不能靠更新时间判断副本是否已提交。

原设计（2026-11-05）打算在 Host 加持久的操作回执和可恢复项目事务（`saveRecoverable`、`recoveryOperation`）。开发时 F-0003 已经按 ADR-0003 实现并验收，项目写入**没有**事务恢复记录。下面按实际实现写（2026-11-06，提交 6ea6049、9022672、39c010f），与原设计的差别在最后一节，验收时请维护者确认。

## 决策

- **存储**：两端都用 IndexedDB（库 `flycut-recovery`，表 `copies`，键 `hostId|projectId|videoId|sessionId`，索引 `scope = hostId|projectId|videoId`）。每个编辑会话一份记录，每次写入是一个事务、整份替换，事务失败时上一份完整副本保留。不写 localStorage，不新增 Tauri command。副本内容：字幕（含译文、删除标记）、删除的字词编号、样式来源、主副样式（含画幅），以及这份编辑基于的视频修订号和项目样式修订号。不含媒体、转写原文、API Key / token、撤销栈。
- **记录时机**：停止编辑 250ms 后记录，连续编辑时最多等 1 秒（PRD 边界是停止后 1 秒内、连续编辑每 2 秒至少一次）。Host 保存成功后马上重记一次：没有未保存的修改就删除副本，还有就换成新的基准修订号。写入失败显示「崩溃恢复暂不可用」，不影响 Host 自动保存。
- **Host 身份**：`projects.identity` 返回 Host home 里 `host-id.json` 的随机 ID，独占创建，重启和换 token 不变，文件损坏时 Host 启动失败。客户端每个连接读一次并缓存，重连后重新读。
- **还开着的窗口**：每个会话占一把 Web Lock（`flycut-recovery-session:<id>`），窗口关闭或崩溃时浏览器自动释放；打开项目时跳过仍被占用的会话。
- **已经写进 Host 的副本**：按内容比较副本和 Host 当前状态（与键顺序无关，分「这个视频的修改」和「项目样式」两部分）。两部分都相同就是已经写入，不再提示，顺手删除。这同时覆盖「保存成功但副本没来得及删」和「恢复写入成功但响应丢失」。
- **冲突**：只看副本与 Host 不同的那部分；那部分的基准修订号不是 Host 当前修订号就是冲突，让用户选择覆盖（`force`，仍然不能写进不存在的项目或视频）、另存为新项目（`projects.duplicate` 带客户端生成的 `copyId`，重试返回同一个副本）或取消。
- **恢复写入**：复用 F-0003 的 `projects.saveVideoEdits`、`projects.saveProjectStyle`，不新增保存接口。请求失败时先重新读 Host：内容已一致就按成功处理；读不到 Host 显示「暂时无法确认保存结果」，副本保留。
- **放弃**：二次确认后按序号条件删除选中的副本，只删用户看到的那个版本。
- 未处理的副本不按时间清理；解析不了的记录保留并报告「无法完成恢复」，不删除、不强行迁移。

## 备选方案

- 只在 Host 记日志：保护不了客户端尚未发送的编辑。
- 桌面新增原生业务存储 command：增加原生接口与双端差异，违反「Tauri 只做外壳」。
- Host 持久操作回执 + 项目事务（原设计）：能精确回答「某次保存是否已提交」，但 F-0003 已经决定不做事务恢复记录（ADR-0003），要为它补一套事务层和回执格式。按内容比较只需要读一次 Host，不改项目存储格式。
- 比较客户端时间或收到响应就清理：不能覆盖响应丢失及旧回执删除新副本的竞态。
- 操作日志及自动合并：增加重放和语义冲突成本，超出主动选择完整副本的范围。

## 后果

- 项目存储格式不变（没有新增字段，不需要迁移）；新增的只有 Host home 的 `host-id.json` 和 `projects.duplicate` 的可选参数。
- 已知的小窗口：本窗口保存成功到副本换成新基准之间（几毫秒）如果崩溃，下次打开会把自己的修改当成冲突提示。用户选择覆盖即可，不会丢数据，也不会静默覆盖。
- 两个窗口恰好改成完全相同的内容时，会被当成已经写入，不再提示（本来也无需恢复）。
- 测试：`tests/architecture/projects-f0004.test.ts`（身份稳定、损坏身份、幂等另存、半成品副本）；`tests/e2e/features/F-0004.spec.ts`（真实 IndexedDB 上的记录、崩溃重开、隔离、还开着的窗口、检查中 / 失败 / 冲突 / 放弃 / 记录失败的界面状态，明暗、中英文）。

## 与原设计的差别（请维护者确认）

1. 没有 Host 操作回执和项目事务，用内容比较判断副本是否已写入（理由见上）。
2. 没有新的 `projects.saveRecoverable` / `projects.recoveryOperation` / `projects.duplicateRecoverable`，复用 F-0003 的保存接口；`projects.duplicate` 加可选 `copyId`。
3. 没有单独的 `ctx.recovery` 插件和 recovery store：恢复逻辑和自动保存都在 `ctx.projects`（它们共用编辑器状态、保存起点和队列），状态放在 `stores.project.recovery`。
4. 原设计说 F-0003 上线后再适配多视频：F-0003 已经先合入，所以副本按视频保存，含样式来源和项目样式；切换视频时上一个视频的会话结束（修改已保存或被放弃）。
