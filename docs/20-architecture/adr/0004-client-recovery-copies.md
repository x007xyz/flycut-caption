# ADR-0004 客户端临时恢复副本与幂等恢复保存

## 背景

F-0004 立项和 PRD 已获维护者确认。Host 无法恢复从未收到的修改，因此维护者批准客户端临时恢复副本的受限例外。Host 仍是正式项目数据来源。需要同时应对进程崩溃、响应丢失和多窗口版本冲突，不能靠更新时间判断副本是否已提交。

## 决策

- 两端以 IndexedDB 适配器保存每会话最近的完整编辑副本，不保存正式项目库、源媒体、API Key/token 或撤销历史。记录保护时限和清理边界以 PRD 为准；需真实验证桌面 WebView 强退与性能。
- Host home 保存稳定随机身份，通过 projects 插件 RPC 返回；身份不依赖 URL、凭证或进程 generation。记录按 Host、项目、视频、独立会话隔离，损坏记录保留并报告。
- 正常保存和恢复保存使用新增幂等 RPC；旧 RPC 的 revision 语义不变。提交前客户端持久化 operationId/snapshotId，Host 持久回执与 edits/修订号通过可恢复项目事务协调，响应丢失时先对账。
- 清理副本按 sequence/snapshotId 条件执行；确认旧快照不删除更新编辑。同窗口已提交前序版本可以推进更新副本基准，不推进到其他窗口未知修改。
- 用户主动恢复、放弃或稍后处理；冲突必须显式选择，不静默覆盖。另存同样幂等，原目标不存在或无权限不能借 force 绕过。
- 未处理副本不按时间清理；本地存储失败显示保护不可用但不阻止 Host 自动保存。未知 schema 不强行迁移或删除。

## 备选方案

- 只在 Host 记日志：保护不了客户端尚未发送的编辑。
- 桌面新增原生业务存储 command：增加原生接口与双端差异，先用统一适配并实测。
- 比较客户端时间或收到响应就清理：不能覆盖响应丢失及旧回执删除新副本的竞态。
- 操作日志及自动合并：增加重放和语义冲突成本，超出主动选择完整副本的范围。

## 后果

需新增稳定身份、事务和幂等回执，故障注入应验证进程重启后的真实文件状态。能力尚未实现；本 ADR 保持 proposed，维护者在测试验收时审阅技术选择。F-0002 验收前不开发；F-0003 多视频/回收站另行适配，后续复用一个项目事务层。详细契约、风险、实现清单与全部 AC 映射在 F-0004/02-design.md。
