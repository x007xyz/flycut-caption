# ADR-0003 多视频项目格式、并发保存与回收站

## 背景

F-0003 已确认：一个项目多个视频，视频独立编辑；同视频或同项目样式并发修改要冲突提示；项目删除进入 30 天回收站。格式 1 的项目级冲突检测无法让不同视频独立保存，跨文件写入也需要中断恢复。

## 决策

作为 ADR-0001 的格式 2 扩展提出，维护者在 F-0003 验收时一并审阅，不修改已接受的格式 1 契约。

- 保留项目级 revision 和旧保存接口的 baseRevision 含义。新增 videoRevision、styleRevision、metadataRevision，新保存方法按修改目标比较版本；项目内实际磁盘写入仍串行。
- 主、副字幕样式放在项目层，视频选择跟随或独立；画幅只在视频层。迁移格式 1 单视频项目时保留原效果、字幕、剪辑和媒体，并保留未知字段。
- 使用项目事务恢复记录协调 edits 与项目元数据等多文件更新，重启先幂等恢复再提供读写；迁移备份 v1，最后提交版本号。
- 回收站用 deletedAt/purgeAfter 标记，不移动媒体目录。普通读取、媒体播放和写入统一拒绝回收站项目；恢复、保存和清理在同一项目队列中重新检查生命周期。
- 到期清理只在 Host 运行时执行；永久删除限定受控项目目录，不跟随 linked 引用或外部符号链接。中断清理记录可恢复，清空回收站返回部分失败结果。
- UI 编辑状态属于当前视频会话，切换前保存，旧异步结果不得落到新视频。永久删除后另存保留可恢复的编辑快照；已经销毁的媒体按缺失媒体处理，不能保证恢复原媒体。

## 备选方案

- 项目级冲突：实现简单，但不满足不同视频独立保存的已确认 AC-14。
- 整目录移动到回收站：便于物理区分，但媒体地址与并发写入要额外协调。
- SQLite：有事务能力，但超出当前无原生数据库依赖的存储方案，本次沿用 JSON 并补恢复机制。

## 后果

需要故障注入验证文件事务和迁移、两窗口验证冲突粒度、竞态验证删除恢复顺序、原始媒体保护测试。旧程序看到格式 2 必须拒绝写入。设计细节和 AC 映射见 F-0003 的 02-design.md。实施依赖 F-0002 验收完成；若其最终契约变化，开发前更新本提案。
