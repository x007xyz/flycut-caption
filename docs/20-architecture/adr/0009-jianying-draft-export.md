# ADR-0009 剪映 Windows 5.9.0 候选草稿的受控导出

## 背景

F-0010 只在本机找到可完整读取的 **Windows 5.9.0 明文草稿**结构。没有 Windows 5.9.0 应用实机导入证据；本机 macOS 11.7.0 使用私有封装的 Timelines 格式，不能生成。F-0011 需要把 F-0005 EDL 和当前字幕写成新草稿，同时保持原媒体、不覆盖用户草稿、不让普通 RPC 接收任意路径。

## 决策

**F-0011 只提供 Windows 5.9.0 的实验性候选导出，不声明正式支持。Host 唯一生成草稿，媒体复制进草稿目录；Tauri 通过 shell-only、短生命周期目录 grant 授权输出父目录，真实剪映导入仍是验收门禁。**

具体边界：

- 目标只包含 Windows 5.9.0 明文格式；macOS 11.7.0、其他 build 和 CapCut 返回 `Unsupported draft version`。候选界面和测试报告必须显示 `verifiedByImport: false`。
- 首版只生成单时间线、单视频轨、单主字幕轨；副字幕、双语、字体、精确定位和根索引更新不承诺。所有降级在导出前展示。
- 用户用原生目录选择器选父目录。桌面外壳立即用 shell secret 向 Host 登记，普通 RPC 只使用 opaque grant；grant 绑定本次选择、TTL 15 分钟、一次性消费，Host 重启后失效。
- Host 校验 realpath、目录可写、最终名和 staging 的 `lstat`，拒绝符号链接、路径穿越和同名目标；临时目录在同一父目录中生成，回读验证后原子改名。取消和失败只清本次临时产物。
- 媒体固定复制进 `<draft>/materials/`，写入最终绝对路径并核对 SHA-256。原媒体只读。
- 不读写 `root_meta_info.json`，不自动打开或上传剪映账户。
- 没有真实 Windows 5.9.0 剪映打开、播放、改字幕、保存、搬迁/重开时，功能不能验收通过，也不能在界面或文档中称正式支持。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| shell-only 目录 grant + Host 原子生成（选定） | 最终路径由 Host 写对；安全边界沿用 ADR-0002；业务全在 Host | 新增短生命周期授权通道 |
| 前端把目录路径直接传给普通 RPC | 改动少 | 推翻「RPC 不接收任意本地路径」，远程 Host 可被网页指定任意目录 |
| Host 生成 zip，Tauri 解压并改绝对路径 | 前端不接触路径 | 格式改写落到外壳，容易产生半成品，Host 不再是唯一生成者 |
| 引用原媒体 | 省空间 | 原文件移动/删除即失联，F-0010 也没有证明可搬迁 |
| 生成 macOS 11.7.0 私有封装 | 可能覆盖本机 | 核心时间线不可读，不在 F-0010 批准范围 |

## 后果

- 实现必须同时维护候选格式生成器和回读校验器；任何缺失引用、时间越界、媒体哈希不一致或半成品都按失败处理。
- 真实导入前，用户只能得到明确标记为实验性的候选目录。产品成功指标和 AC-7/9/10 保持阻塞。
- 移动草稿目录后绝对路径可能失效；是否支持重联只能由真实剪映实验确认。
- 目录 grant 被复用、过期、资产/名称改变、目录替换或前端尝试登记都会被拒绝。server profile 没有 shell token 时整条通道不存在。
- 后续若要正式支持，必须先补 Windows 5.9.0 实机回归，再决定是否进入 accepted；不得凭生成器单测把本 ADR 改为 accepted。
