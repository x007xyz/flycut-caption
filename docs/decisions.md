# 已拍板的决定

这里记录维护者已经确定的产品与架构决定。PR 不要推翻这些决定；确实需要改，先在 PR 描述里说明理由，等维护者确认后再动手，并同步更新本文件。

格式：一句决定 + 原因 + 来源（commit / issue / 文档）。

## 架构

- **Tauri 只做桌面外壳。** 业务（ASR、模型管理、导出）都在 Host 插件中，不新增执行业务的 Tauri command。来源：`docs/architecture-current.md`、`docs/subsystems/funasr-tauri.md`。
- **使用 vendored 的真实 Cordis 源码。** 不用自行实现的兼容类替换 `core/cordis`、`core/cosmokit`。来源：`core/UPSTREAM.md`。
- **桌面导出只走 Host。** Web 端的 WebAV/FFmpeg 只是明确的本地回退引擎，桌面端不回退到它们。来源：`docs/subsystems/cordis-host.md`。
- **RPC 不接收任意本地路径。** 桌面媒体通过 `/assets` 上传给 Host。来源：`docs/subsystems/funasr-tauri.md`。
- **FFmpeg 随安装包内置。** 优先使用 `src-tauri/binaries` 中的副本，不依赖用户系统里装的 FFmpeg。来源：`scripts/fetch-ffmpeg.sh`。

### 模型 Provider

来源：维护者 2026-11-02 确认。规范细节见 [subsystems/providers.md](subsystems/providers.md)。

- **一个 Provider 对应一个推理后端。** 例如 sherpa-onnx、FunASR、Qwen、某个 HTTP 服务。同一后端的运行环境、模型下载和鉴权配置只有一份，不按能力拆成多个 Provider。
- **Provider 声明能力，调用按能力分开。** 一个 Provider 可以同时提供 ASR、VAD、标点、说话人识别、对齐、TTS 中的若干项，没有的能力就不声明，不写抛 "not supported" 的空实现。流水线每一步各自选择 Provider，不要求所有步骤来自同一个 Provider。
- **调用统一使用 `{ providerId, modelId }`（`ModelRef`）。** 前端、流水线、Agent 工具都只传 `ModelRef` 和该模型声明过的选项，不再有引擎类型（`ASREngineType`）、`webModelId` 之类的平行字段，也不在调用方按 Provider 写分支。
- **模型清单属于 Provider。** 每个 Provider 通过 `models()` 返回自己的模型和能力（角色、语言、时间戳级别、可选项、就绪状态）。Host 只汇总，不维护跨 Provider 的全局清单；界面上的语言、时间戳、选项都从这里读取。
- **只有两种接入方式。**
  1. **Provider 插件**：写在代码里、随版本发布，由维护者开发。内置模型就是插件 Provider 自带的模型，下载、加载由 Provider 自己负责。
  2. **HTTP Provider**：用户自己运行一个实现 [FlyCut Provider 协议](provider-http-protocol.md) 的服务（或 OpenAI 兼容服务），在界面里填地址即可接入，不需要改 FlyCut 代码。
- **不再支持用户手写模型文件清单。** 用户填写 `files`、`family`、`recognizer_config` 的自定义模型、本地模型目录扫描登记都移除。用户自己的模型一律通过 HTTP Provider 接入。原因：这套方式只能接入已有后端支持的格式，却带来大量校验代码和本地路径安全面。
- **FunASR 是完整的 Provider，通过 HTTP 协议调用。** FunASR 服务实现 FlyCut Provider 协议，提供 ASR、VAD、标点、说话人识别；Host 可以在本机托管它，也可以连接远程（例如 GPU 服务器）上的同一个服务。内置的 FunASR 和用户接入的 HTTP Provider 走同一套协议客户端。
- **Provider 的能力声明不能直接打开破坏性编辑。** 字词级剪切只看识别结果里是否有通过校验的字词时间戳，不看 Provider 或模型的声明。

## 产品定位与优先级

FlyCut Caption 是**字幕优先**的视频工具，长期目标是成为剪辑视频的 Agent。功能按下面的顺序建设，排在前面的能力是后面能力的地基：前面的没做稳之前，不为后面的功能牺牲它，也不跳级开发。

| 优先级 | 能力 | 状态 |
|---|---|---|
| P0 | 添加字幕：识别 → 编辑 → 导出 | 已有，持续打磨 |
| P1 | 字幕特效：样式、预设、动画 | 已有样式与预设，特效持续扩展 |
| P2 | 双语 / 多语言字幕 | 已有双语（主字幕 + 副字幕），向多语言演进 |
| P3 | 语音翻译：翻译字幕 + 配音 | 已有字幕文本翻译，配音规划中 |
| P4 | 剪辑 Agent：从长视频自动产出短片（对标 OpusClip） | 规划中 |

来源：维护者 2026-10-29 确认；首发范围另见 `docs/PRODUCT-EXECUTION-PLAN.md`。

### P0 添加字幕（基础功能）

- **字幕是一切功能的数据基础。** 特效、翻译、剪辑 Agent 都读写同一份带时间戳的字幕（`SubtitleTranscript`：句子级 `chunks` + 可选字词级 `wordChunks`），不另建平行的数据源。原因：编辑、裁剪、导出和后续 Agent 都依赖同一套时间映射，分叉就会不同步。
- **识别结果可以逐条核对和修改。** ASR、AI 纠错、翻译产出的都是可编辑字幕，不直接写死进成片。原因：识别和翻译都会出错，用户要能在导出前改。
- **ASR Provider 可以切换。** 本地 Provider（sherpa-onnx、FunASR、Qwen、Transformers）和用户接入的 HTTP Provider 都要保留，新功能不能只在其中一种 Provider 上可用。
- **字幕可以单独导出。** SRT / VTT / JSON / ASS 导出和硬烧 MP4 并存，不能为了视频导出砍掉纯字幕导出。

### P1 字幕特效

- **特效以样式预设交付。** 新特效在 `src/subtitle`（`subtitlePresets.ts`、`subtitleStyle.ts`）里扩展为预设或样式字段，用户一键套用后可以再微调，不做只能写死、不能编辑的效果。
- **预览与导出一致。** 播放器预览和导出成片（ASS 硬烧）的样式效果必须一致；新增特效必须同时支持两端，只做了预览的特效不算完成。
- **画幅自适应。** 特效需要在横屏、竖屏 9:16、方形 1:1 三种画幅（`AspectPreset`）下都可用。原因：P4 的短片主要是竖屏。

### P2 双语 / 多语言字幕

- **主字幕是原文，副字幕是译文。** 当前数据模型是 `SubtitleChunk.text` + `secondText`，显示模式为主 / 副 / 双语（`SubtitleDisplayMode`）。
- **向多语言演进时保持兼容。** 将来把单一 `secondText` 扩展为多语言轨道时，现有项目、双语导出和 `secondText` 字段要继续可用（读取时兼容迁移），不要直接删掉旧字段。
- **译文和原文共用时间轴。** 删除、裁剪原文片段时，对应的译文同步删除或移动，不单独维护译文时间。
- **首发保证中文、英文和中英双语。** 其他语言按所选服务商的实际能力展示，不承诺未验证过的语言。

### P3 语音翻译

- **语音翻译 = 翻译字幕 + 配音。** 流水线固定为 ASR → （可选）纠错 → 翻译 → （可选）配音。翻译产出 P2 的多语言字幕；配音再根据译文字幕用 TTS 生成目标语言音频。来源：维护者 2026-10-29 确认包含配音。
- **翻译走 Host 的文本 Provider**（`server/plugins/text.ts`），不在前端直接调用模型 API。
- **翻译结果可逐条核对。** 和 P0 一样，翻译是可编辑的建议，用户能看到并修改每一条，单条翻译失败不影响其他条目。

#### 配音

- **配音以译文字幕为输入。** 每条字幕生成一段音频，时间对齐到这条字幕的时间戳。用户先确认译文，再生成配音；改了某条译文，只重新生成这一条的配音，不整段重做。
- **TTS 是 Host 的 Provider。** 和 ASR 一样在 Host 注册，支持本地引擎、官方服务和自定义 API 切换，前端不直接调用 TTS 接口。
- **配音是一条单独的音轨，不覆盖原视频。** 导出时可以选择：只保留原声、只用配音、配音叠加压低音量的原声。原始音频始终保留，可以随时切回。
- **配音不能比字幕时间段长。** 译文读出来比原句时长长时，先调整语速；超出可接受语速范围的条目标出来让用户处理（缩短译文或调整时间），不能自动截断，也不能让后面的字幕被顺延错位。
- **配音跟随剪辑。** 原文片段被删除或裁剪后，对应的配音同步删除或移动，和 P2 的译文规则一致。

#### 声音克隆

用原说话人的音色生成目标语言配音。来源：维护者 2026-10-29 确认要做。

- **克隆前必须有授权确认。** 每次用某段声音创建音色前，用户要明确确认「这是我本人的声音，或我已获得说话人授权」，确认记录（时间、音色、来源素材）随音色保存。没有确认就不能创建音色；Agent 和 MCP / CLI 调用也不能跳过这一步，必须由用户本人确认。
- **只克隆项目内素材里的声音。** 音色样本取自当前项目视频中的说话人片段（可结合 `SubtitleChunk.speaker` 选出），不提供「上传任意录音克隆」的独立入口。原因：把能力限定在「给自己的视频配自己的声音」这个用途上。
- **克隆音色归用户所有，可随时删除。** 音色和样本存在用户本地或其账户下，不在用户之间共享，不用于训练；删除音色时同时删除样本。
- **克隆走 TTS Provider。** 声音克隆是 TTS Provider 的一项能力，Provider 在描述中声明是否支持；不支持的引擎回退到自带音色，不能静默失败。
- **样本上传要提前告知。** 使用云端克隆服务时，发送音频样本前要明确告诉用户会上传什么、传给谁，与 `docs/PRODUCT-EXECUTION-PLAN.md` 中「提交任务前显示发送内容」的规则一致。
- **成片默认标注 AI 配音。** 只要成片用了配音（克隆音色或 TTS 自带音色），导出时「AI 配音」标注（字幕或画面角标）默认开启，用户可以手动关闭；PR 不要把默认值改成关闭。来源：维护者 2026-10-29 确认。

### P4 剪辑 Agent（后续）

目标是对标 OpusClip：输入一段长视频，自动产出多条可发布的短片。

- **基于字幕做剪辑。** Agent 通过字幕和时间戳理解内容，用来挑选片段、确定剪辑点，复用 P0–P3 的数据和能力（每条短片自带字幕、特效和译文），不另起一套视频理解流水线。
- **Agent 给建议，人确认。** 精彩片段推荐、裁剪、去口癖等先给出带原文和时间范围的建议，用户确认后才应用；验证可靠后再开放自动应用。
- **走 Host 的 Agent 能力实现。** 剪辑能力注册为 Host 的编辑分析器 / Agent 工具（`ctx.editorPlugins.register`、`ctx.agentTools.register`，在 LangGraph Workflow 与 Agent Loop 中运行），并通过 MCP / CLI 供外部 Agent 调用；不把 React Hook 直接暴露成 API。
- **范围内：** 精彩片段挑选与评分、竖屏重构图（主体跟随）、自动加字幕和特效、批量导出短片。
- **范围外：** 文生视频、图生视频、素材生成平台、多轨剪辑器、通用可视化工作流画布。原因：保持专注于「已有视频 → 字幕 → 短片」。
