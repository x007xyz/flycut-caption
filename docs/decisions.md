# 已拍板的决定

这里记录维护者已经确定的产品与架构决定。PR 不要推翻这些决定；确实需要改，先在 PR 描述里说明理由，等维护者确认后再动手，并同步更新本文件。

格式：一句决定 + 原因 + 来源（commit / issue / 文档）。

## 架构

- **Tauri 只做桌面外壳。** 业务（ASR、模型管理、导出）都在 Host 插件中，不新增执行业务的 Tauri command。来源：`docs/architecture-current.md`、`docs/subsystems/funasr-tauri.md`。
- **使用 vendored 的真实 Cordis 源码。** 不用自行实现的兼容类替换 `core/cordis`、`core/cosmokit`。来源：`core/UPSTREAM.md`。
- **桌面导出只走 Host。** Web 端的 WebAV/FFmpeg 只是明确的本地回退引擎，桌面端不回退到它们。来源：`docs/subsystems/cordis-host.md`。
- **RPC 不接收任意本地路径。** 桌面媒体通过 `/assets` 上传给 Host。来源：`docs/subsystems/funasr-tauri.md`。
- **FFmpeg 随安装包内置。** 优先使用 `src-tauri/binaries` 中的副本，不依赖用户系统里装的 FFmpeg。来源：`scripts/fetch-ffmpeg.sh`。

### 模型 Provider

来源：维护者 2026-11-02、2026-11-03、2026-11-04 确认。规范细节见 [subsystems/providers.md](subsystems/providers.md)。

- **一个 Provider 对应一个推理后端。** 例如 sherpa-onnx、FlyCut Cloud、某个 HTTP 服务。同一后端的运行环境、模型下载和鉴权配置只有一份，不按能力拆成多个 Provider。
- **Provider 声明能力，调用按能力分开。** 一个 Provider 可以同时提供 ASR、VAD、标点、说话人识别、对齐、TTS 中的若干项，没有的能力就不声明，不写抛 "not supported" 的空实现。流水线每一步各自选择 Provider，不要求所有步骤来自同一个 Provider。
- **调用统一使用 `{ providerId, modelId }`（`ModelRef`）。** 前端、流水线、Agent 工具都只传 `ModelRef` 和该模型声明过的选项，不再有引擎类型（`ASREngineType`）、`webModelId` 之类的平行字段，也不在调用方按 Provider 写分支。
- **模型清单属于 Provider。** 每个 Provider 通过 `models()` 返回自己的模型和能力（角色、语言、时间戳级别、可选项、就绪状态）。Host 只汇总，不维护跨 Provider 的全局清单；界面上的语言、时间戳、选项都从这里读取。
- **只有两种接入方式。**
  1. **Provider 插件**：写在代码里、随版本发布，由维护者开发。内置模型就是插件 Provider 自带的模型，下载、加载由 Provider 自己负责。
  2. **HTTP Provider**：用户自己运行一个实现 [FlyCut Provider 协议](provider-http-protocol.md) 的服务（或 OpenAI 兼容服务），在界面里填地址即可接入，不需要改 FlyCut 代码。
- **不再支持用户手写模型文件清单。** 用户填写 `files`、`family`、`recognizer_config` 的自定义模型、本地模型目录扫描登记都移除。用户自己的模型一律通过 HTTP Provider 接入。原因：这套方式只能接入已有后端支持的格式，却带来大量校验代码和本地路径安全面。
- **客户端只内置 sherpa-onnx。** 安装包里的离线识别只有 sherpa-onnx（`funasr-asr` sidecar），Host 不启动、不打包 Python。原因：Python、PyTorch 和模型依赖没法可靠地随安装包分发给普通用户，内置一个大多数人用不起来的 Provider 不如不内置。来源：维护者 2026-11-04 确认。
- **FunASR Provider 是独立仓库。** FunASR 服务（`flycut-funasr-provider`）单独发布，用户自己安装 Python 环境运行，在「添加服务」里按 FlyCut Provider 协议接入。它用完整的 FunASR 实现：模型都通过官方 `funasr.AutoModel` 加载，覆盖离线 ASR 模型（Paraformer、SenseVoice、Fun-ASR-Nano、Qwen3-ASR、Whisper 等）和配套的 VAD、标点、说话人、对齐模型；不用 FunASR 自带的 `funasr-server`（只有句段时间戳，模型不给时间戳时按字数均分时间，也没有鉴权）。FlyCut 主仓库只保留一篇接入说明。来源：维护者 2026-11-03、2026-11-04 确认。
- **不执行模型仓库附带的代码。** FunASR Provider 加载模型时不开 `trust_remote_code`；只能靠远程代码加载的模型（例如 GLM-ASR-Nano、MOSS-Transcribe-Diarize）不进它的清单。原因：模型仓库里的 Python 代码会在用户机器上执行。来源：维护者 2026-11-03 确认。
- **内置官方付费服务 FlyCut Cloud。** 客户端内置 `flycut-cloud` Provider，走同一个 FlyCut Provider 协议，用 API Key 鉴权；服务地址由发行配置决定（`FLYCUT_CLOUD_URL`），没有配置时不出现。服务端、账号和计费另行建设，不在本仓库。来源：维护者 2026-11-04 确认。
- **移除 Transformers.js Provider。** Host 不再内置 Transformers.js 推理，开箱即用的离线识别由 sherpa-onnx 提供。来源：维护者 2026-11-03 确认。
- **Provider 的能力声明不能直接打开破坏性编辑。** 字词级剪切只看识别结果里是否有通过校验的字词时间戳，不看 Provider 或模型的声明。

## 开发流程

- **需求流程没有交互原型阶段。** 需求说明把每个界面状态写成 AC，开发直接写真实界面代码，验收阶段用端到端测试覆盖每个状态和明暗主题并截图。原因：AI 写代码后改界面成本很低，原型和正式代码重复确认不划算。来源：维护者 2026-11-05 确认。
- **技术设计、开发、验收由 agent 连续推进。** 需求说明确认后，技术设计和开发阶段检查通过即自动确认，维护者只在测试与验收时看测试报告、截图和录屏，一并审阅设计和实现；agent 自己决定的事记进报告的「自行决定的事项」。改需求说明范围、推翻已有决定或共用契约、需求做不完、不可逆操作仍要先问。来源：维护者 2026-11-05 确认。
- **每个需求只有两个确认点，发布按版本做。** 维护者一个人从需求做到开发：立项和 PRD 合成一份需求说明（`01-spec.md`），可以一批一起确认；之后只在测试与验收时再确认一次。发布、运维观察和复盘不再按需求逐个写和确认，按版本写在 `docs/40-ops/releases/vX.Y.Z.md`。原因：原来每个需求要确认 6 次，适合多人协作，不适合一个人推进。来源：维护者 2026-11-05 确认。
- **需求内部不拆任务。** 产品层把需求拆到能单独发布的大小后，开发时整个需求在一个上下文里一次做完；技术设计里的实现清单只记录进度，不设门禁。阶段确认仍由维护者做；偏离设计、改共用契约、发现需求做不完时，agent 停下来问。原因：任务之间互相影响，拆开后上下文不完整、接口协调成本高，单人加 AI 开发并行收益小。来源：维护者 2026-11-05 确认。

## 产品定位与优先级

FlyCut Caption 是**字幕优先**的视频工具，长期目标是成为剪辑视频的 Agent。所有能力都建立在 ASR 转写之上，分成两条线：**字幕线**（字幕 → 特效 → 多语字幕 → 配音）和**剪辑线**（按文字剪辑 → 去静音、去口癖 → 长视频转短视频）。功能按下面的顺序建设，排在前面的能力是后面能力的地基：前面的没做稳之前，不为后面的功能牺牲它，也不跳级开发。同一优先级的两条线可以并行。

| 优先级 | 能力 | 线 | Epic | 状态 |
|---|---|---|---|---|
| P0 | 转写 + 添加字幕：识别 → 编辑 → 导出 | 底座 | E-01、E-02 | 已有，持续打磨 |
| P1 | 按文字剪辑：去静音、去口癖 | 剪辑 | E-06 | 已有删字幕剪视频和智能剪空白，去口癖规划中 |
| P2 | 字幕特效：样式、预设、动画 | 字幕 | E-03 | 已有样式与预设，特效持续扩展 |
| P2 | 双语 / 多语言字幕 | 字幕 | E-04 | 已有双语（主字幕 + 副字幕），向多语言演进 |
| P3 | 语音翻译：翻译字幕 + 配音 | 字幕 | E-05 | 已有字幕文本翻译，配音规划中 |
| P4 | 剪辑 Agent：从长视频自动产出短片（对标 OpusClip） | 剪辑 | E-07 | 规划中 |

平台与接入（E-08：MCP / CLI、TTS Provider、自动更新）贯穿各优先级，按其他 Epic 的需要排期。

来源：维护者 2026-10-29 确认字幕线顺序，2026-11-04 确认按文字剪辑提到 P1（口播创作者最痛的是粗剪），字幕特效与多语字幕并列 P2；Epic 拆分见 [10-product/capability-map.md](10-product/capability-map.md)。

### 目标用户与平台

- **首批目标用户是口播创作者。** 新需求的需求说明要写清楚面向哪类口播创作者、竞品怎么做、获客价值。用户画像、竞品和获客渠道见 [10-product/vision.md](10-product/vision.md)。来源：维护者 2026-11-04 确认。
- **先桌面端（Tauri），再 Web，两端功能对齐。** 新功能先在桌面端发布，Web 端随后补齐，最终两端能力一致；Web 端的识别、导出连接远程 Host。暂不考虑 npm 组件库。来源：维护者 2026-11-04 确认。
- **Web 端连接的远程 Host 由 FlyCut Cloud 托管。** 多用户、账号、鉴权、计费属于 Cloud，不在本仓库；本仓库只做客户端一侧，并保证 Host 能运行在 Cloud 的鉴权层后面。用户自己部署是次要场景，只支持单用户，并且必须挡一层带鉴权的反向代理。来源：维护者 2026-11-05 确认。

### P0 添加字幕（基础功能）

- **字幕是一切功能的数据基础。** 特效、翻译、剪辑 Agent 都读写同一份带时间戳的字幕（`SubtitleTranscript`：句子级 `chunks` + 可选字词级 `wordChunks`），不另建平行的数据源。原因：编辑、裁剪、导出和后续 Agent 都依赖同一套时间映射，分叉就会不同步。
- **识别结果可以逐条核对和修改。** ASR、AI 纠错、翻译产出的都是可编辑字幕，不直接写死进成片。原因：识别和翻译都会出错，用户要能在导出前改。
- **ASR Provider 可以切换。** 内置的 sherpa-onnx、FlyCut Cloud 和用户接入的 HTTP Provider（例如 FunASR Provider）都要保留，新功能不能只在其中一种 Provider 上可用。
- **字幕可以单独导出。** SRT / VTT / JSON / ASS 导出和硬烧 MP4 并存，不能为了视频导出砍掉纯字幕导出。

### 项目与数据

来源：维护者 2026-11-04 确认，参考 OpusClip 的项目管理方式。

- **一个项目包含多个视频。** 项目不是「一个视频一个项目」；项目里可以添加、切换、移除多个视频，字幕样式、口癖词表、术语表等可以在项目级共享。
- **项目数据由 Host 保存。** Web 端和桌面端都通过 Host 的接口读写项目、视频和产出物，使用同一套数据格式；桌面端连本机 Host，Web 端连远程 Host。前端只做展示和编辑，不作为数据的来源，也不在浏览器本地存业务数据。
- **崩溃恢复副本是唯一的本地例外。** 客户端可以在本机（IndexedDB）保存还没写进 Host 的临时恢复副本，Host 仍是正式项目数据的来源；副本在保存成功或用户放弃后删除，未处理的不按时间自动清理。副本不含媒体、API Key / token、撤销历史，不上传到其他 Host，不能借此在前端建第二套项目库。恢复前必须让用户选择，冲突时不静默覆盖。来源：维护者 2026-11-05 确认 F-0004 立项与需求说明；实现见 [ADR-0004](20-architecture/adr/0004-client-recovery-copies.md)。
- **项目里的媒体不会被自动清理。** Host 临时资产的过期清理不作用于项目里的媒体和产出物；只有用户删除视频或项目时才删除。
- **数据格式带版本号，可迁移。** 读到旧版本数据时迁移，不丢弃；格式变化要写 ADR。
- **并发修改不静默覆盖。** 同一项目在多个窗口或设备上修改时，用版本号检测冲突并提示用户。

### P1 按文字剪辑

- **自动剪辑建议先标记、预览，确认后才删除。** 时间轴待删除区间标红并有文字/图标，临时预览不改正式EDL、不进入正常导出；用户逐条或批量确认后才应用，取消只移除待确认标记。来源：维护者2026-11-05批量立项确认。
- **已确认剪辑保留可回退的操作历史。** 历史由Host随项目保存，重开后可预览/选择剪辑版本回退，回退作为新记录保留；不借回退剪辑静默撤回后续文字校对。具体历史加载、确认和失败状态在F-0005修订PRD统一审阅。原始媒体已被永久删除时不能承诺找回媒体。来源：维护者2026-11-05要求“同时存在操作历史记录可以随时回退”。

口播创作者最花时间的是粗剪。来源：维护者 2026-11-04 确认，「去静音、去口癖」为本优先级范围。

- **所有剪辑操作产出同一份编辑决策。** 删字幕、去静音、去口癖、以后的短视频剪辑都写入同一份相对原始媒体的保留 / 删除区间，字幕、译文、配音和导出都按它变换时间，不各自维护时间映射。
- **剪辑是建议，用户确认后才应用。** 去静音、去口癖先给出带原文和时间范围的建议，可以逐条或批量接受；原始媒体和完整转写始终保留，可以撤销。
- **字词级剪切只用通过校验的字词时间戳。** 没有可靠字词时间戳时只做句级剪切，不按字数均分时间伪造精度（与「模型 Provider」小节一致）。
- **AI纠错与剪辑建议统一采用先标记、再确认的交互。** AI建议先进入可编辑的待确认预览，局部有问题可手动修正或保留原文，最后一次确认应用；不强迫逐条接受。确认操作可从统一历史入口回退，但文字纠错不改时间戳/EDL，剪辑回退不撤销后来校对。来源：维护者2026-11-05要求“先标记，然后确认，而且是统一的，如果部分发现有问题就手动修改”。
- **纠错和剪辑分开。** AI 纠错只改文字、不改时间戳；删口癖属于剪辑操作，进入编辑决策。
- **去静音按音频判断。** 用 VAD 判断有没有人声，字词时间戳只用来防止切到字中间；切点前后留余量、切点淡入淡出，长停顿可以压缩而不是全删。不再只按字幕句间空隙判断。来源：维护者 2026-11-05 确认。
- **去口癖：规则处理能确定的，LLM 处理要看上下文的，最后由人确认。** 规则层（语气词、叠词卡顿）离线可用；语义层（「就是 / 那个」是否口癖、句内重复、口误改口、残句）用 LLM 返回字词编号，程序校验后才成为建议。未配置 AI 模型时只用规则层。来源：维护者 2026-11-05 确认。
- **不用禁止商用的模型和数据。** 例如 CrisperWhisper 权重、PodcastFillers 数据集。
- **范围内：** 删字幕剪视频、去静音、去口癖（含句内重复和「不对，重说」这类改口）。**暂不做：** 去重录（同一段话录了好几遍，从中选最好的一遍），以后按需求单独立项。

### P2 字幕特效

- **特效以样式预设交付。** 新特效在 `src/subtitle`（`subtitlePresets.ts`、`subtitleStyle.ts`）里扩展为预设或样式字段，用户一键套用后可以再微调，不做只能写死、不能编辑的效果。
- **预览与导出一致。** 播放器预览和导出成片的样式效果必须一致；新增特效必须同时支持两端，只做了预览的特效不算完成。渲染方案按 [ADR-0006](20-architecture/adr/0006-subtitle-graphics-layer.md)：预览和导出共用一份 Canvas 2D 图形层代码，页面在浏览器 Canvas 上画，Host 用 Skia（`@napi-rs/canvas`）画字幕条带后交给 FFmpeg 叠加（`overlay` 必须 `format=yuv420`）；不再用 ASS 做硬烧，ASS 只用于字幕文件导出。要求桌面端、Web 端、CLI / MCP 和 Cloud 都能导出（Windows、Cloud 待 E-03/7 补测）。来源：维护者 2026-11-05 确认调研范围，2026-11-06 确认 F-0016 调研报告。
- **画幅自适应。** 特效需要在横屏、竖屏 9:16、方形 1:1 三种画幅（`AspectPreset`）下都可用。原因：P4 的短片主要是竖屏。

### P2 双语 / 多语言字幕

- **主字幕是原文，副字幕是译文。** 当前数据模型是 `SubtitleChunk.text` + `secondText`，显示模式为主 / 副 / 双语（`SubtitleDisplayMode`）。
- **向多语言演进时保持兼容。** 将来把单一 `secondText` 扩展为多语言轨道时，现有项目、双语导出和 `secondText` 字段要继续可用（读取时兼容迁移），不要直接删掉旧字段。
- **译文和原文共用时间轴。** 删除、裁剪原文片段时，对应的译文同步删除或移动，不单独维护译文时间。
- **首发保证中文、英文和中英双语。** 其他语言按所选服务商的实际能力展示，不承诺未验证过的语言。
- **翻译和纠错失败要让用户看到。** 缺条、多条、空结果都标为失败，可以重试，不静默用原文填补。来源：维护者 2026-11-05 确认。
- **翻译只用已配置的 AI 模型。** 按语义句带上下文和术语表翻译；专用机器翻译接口暂不接入。来源：维护者 2026-11-05 确认。

### P3 语音翻译

- **语音翻译 = 翻译字幕 + 配音。** 流水线固定为 ASR → （可选）纠错 → 翻译 → （可选）配音。翻译产出 P2 的多语言字幕；配音再根据译文字幕用 TTS 生成目标语言音频。来源：维护者 2026-10-29 确认包含配音。
- **翻译走 Host 的文本 Provider**（`server/plugins/text.ts`），不在前端直接调用模型 API。
- **翻译结果可逐条核对。** 和 P0 一样，翻译是可编辑的建议，用户能看到并修改每一条，单条翻译失败不影响其他条目。

#### 配音

- **配音以译文字幕为输入。** 每条字幕生成一段音频，时间对齐到这条字幕的时间戳。用户先确认译文，再生成配音；改了某条译文，只重新生成这一条的配音，不整段重做。
- **TTS 是 Host 的 Provider。** 和 ASR 一样在 Host 注册，支持本地引擎、官方服务和自定义 API 切换，前端不直接调用 TTS 接口。
- **配音是一条单独的音轨，不覆盖原视频。** 导出时可以选择：只保留原声、只用配音、配音叠加压低音量的原声。原始音频始终保留，可以随时切回。
- **配音不能比字幕时间段长。** 译文读出来比原句时长长时，先调整语速；超出可接受语速范围的条目标出来让用户处理（缩短译文或调整时间），不能自动截断，也不能让后面的字幕被顺延错位。
- **配音保留背景声。** 导出「只用配音」时，提供配音 + 原背景声（人声分离后）的选项，不让背景音乐和环境声一起丢掉。来源：维护者 2026-11-05 确认。
- **配音跟随剪辑。** 原文片段被删除或裁剪后，对应的配音同步删除或移动，和 P2 的译文规则一致。

#### 声音克隆

用原说话人的音色生成目标语言配音。来源：维护者 2026-10-29 确认要做。

- **克隆前必须有授权确认。** 每次用某段声音创建音色前，用户要明确确认「这是我本人的声音，或我已获得说话人授权」，确认记录（时间、音色、来源素材）随音色保存。没有确认就不能创建音色；Agent 和 MCP / CLI 调用也不能跳过这一步，必须由用户本人确认。
- **只克隆项目内素材里的声音。** 音色样本取自当前项目视频中的说话人片段（可结合 `SubtitleChunk.speaker` 选出），不提供「上传任意录音克隆」的独立入口。原因：把能力限定在「给自己的视频配自己的声音」这个用途上。
- **克隆音色归用户所有，可随时删除。** 音色和样本存在用户本地或其账户下，不在用户之间共享，不用于训练；删除音色时同时删除样本。
- **克隆走 TTS Provider。** 声音克隆是 TTS Provider 的一项能力，Provider 在描述中声明是否支持；不支持的引擎回退到自带音色，不能静默失败。
- **样本上传要提前告知。** 使用云端克隆服务时，发送音频样本前要明确告诉用户会上传什么、传给谁，与 `docs/PRODUCT-EXECUTION-PLAN.md` 中「提交任务前显示发送内容」的规则一致。
- **口型同步是后续能力，不自研。** 作为配音之后的候选需求（E-05/6、E-05/7），通过 Provider 接入第三方服务；和声音克隆一样需要说话人授权确认，原视频始终保留。来源：维护者 2026-11-04 确认。
- **成片默认标注 AI 配音。** 只要成片用了配音（克隆音色或 TTS 自带音色），导出时「AI 配音」标注（字幕或画面角标）默认开启，用户可以手动关闭；PR 不要把默认值改成关闭。来源：维护者 2026-10-29 确认。

### P4 剪辑 Agent（后续）

目标是对标 OpusClip：输入一段长视频，自动产出多条可发布的短片。

- **基于字幕做剪辑。** Agent 通过字幕和时间戳理解内容，用来挑选片段、确定剪辑点，复用 P0–P3 的数据和能力（每条短片自带字幕、特效和译文），不另起一套视频理解流水线。
- **Agent 给建议，人确认。** 精彩片段推荐、裁剪、去口癖等先给出带原文和时间范围的建议，用户确认后才应用；验证可靠后再开放自动应用。
- **走 Host 的 Agent 能力实现。** 剪辑能力注册为 Host 的编辑分析器 / Agent 工具（`ctx.editorPlugins.register`、`ctx.agentTools.register`，在 LangGraph Workflow 与 Agent Loop 中运行），并通过 MCP / CLI 供外部 Agent 调用；不把 React Hook 直接暴露成 API。
- **范围内：** 精彩片段挑选与评分、竖屏重构图（主体跟随）、自动加字幕和特效、批量导出短片。
- **范围外：** 文生视频、图生视频、素材生成平台、多轨剪辑器、通用可视化工作流画布。原因：保持专注于「已有视频 → 字幕 → 短片」。
