# F-0013 AI 纠错按差异确认：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

### 要解决的问题

对照 `docs/10-product/vision.md`：10–60 分钟中文口播创作者，字幕校对、粗剪、导出并继续发布。范围内各操作应让用户能检查结果，不能为了自动化隐去失败或覆盖选择。

### 获客价值

对应愿景的创作者教程、开源社区与留存渠道：展示真实完成的字幕/粗剪工作流。核心是节省重复劳动、保持原始素材和用户确认权；调研结果不直接当成功能宣传。

frontmatter 的 depends_on 是脚本门禁；外部接口、真实配置和素材条件也必须在 PRD/研究计划列为前置条件，不能通过省略依赖绕过。

- 进度、取消、失败批次重试；分析后原文已变的建议标过期，不覆盖用户新校对。

## 产品需求

### 背景

2026-11-05维护者明确要求：「AI纠错 应该和 剪映一样的逻辑，先标记，然后确认，而且是统一的，如果部分发现有问题就手动修改」。该句作为本项目的交互要求，不作为已核实的剪映产品事实。

据此替换上一版“首版只逐条接受/拒绝、不做统一确认”的限制：AI只生成待确认修改，在字幕中标记差异；用户可在预览里手动修正局部、保留原文或排除个别建议，最后统一确认一次应用。本流程与剪辑建议共用“标记 → 预览/手动调整 → 确认 → 操作历史”的交互，不要求逐条点接受。

### 目标用户与竞品

10–60分钟中文口播的个人创作者，希望批量检查AI纠错，重点修正少数有问题的建议，再统一应用。竞品具体版本和操作细节未外部核实，本PRD以维护者给出的项目行为为依据。

### 范围

#### 做

- 当前视频未删除原文分批纠错，严格校验返回结果，不直接覆写正式字幕。
- 统一的待确认修改层：字幕中标记差异，可切换正式原文/修改预览；AI文本变更用文字差异和标记区分，不能把纠错删字画成剪视频的删除区间。
- 所有有效差异默认纳入待确认版本；用户可直接编辑建议文本、恢复某条原文或排除单条，然后统一确认剩余修改。
- 统一确认以一个编辑操作提交，保留可回退的操作历史；取消不改变正式字幕。时间戳、译文、字词ID和EDL不变。
- 分批进度、取消、失败批次重试、过期校验与两端验证。

#### 不做

模型返回即自动应用、强迫逐条接受、修改时间戳/EDL、去口癖、翻译重构、新模型设置体系、跨项目批处理。统一交互不意味着把文字校对和视频删除混成一个无法区分的命令。

### 用户故事

作为口播创作者，我希望AI先把拟修改的字幕标出来，让我预览整体效果、手动改正少数有问题的地方，再一次确认应用；发现问题时可以回退这次操作。

### 验收标准

桌面端优先，Web开发模式连接同一Host验证相同业务。每个新增界面状态覆盖明暗主题与中英文，测试名带F-0013/AC编号；模型不依赖某个固定Provider。

- **AC-1 未配置模型**：打开纠错但未选AI模型时，显示「请先配置AI模型 / Configure an AI model first」与设置入口，不自动选择收费服务或发送请求；字幕编辑继续可用。

- **AC-2 发送与正式基准**：用户主动启动前，显示当前视频未删除原文的发送范围与目标模型。请求保存原文基准、原ID及编辑版本，只发必要文本/上下文，不发原媒体；密钥不进入预览或日志。发请求不改正式字幕、保存状态或正常导出内容。

- **AC-3 分批与进度**：显示「正在生成纠错建议… / Generating corrections…」、批次进度和取消。完成的有效结果只进入待确认层；请求尚未结束时不能确认整个版本。取消停止后续批次并忽略迟到结果，已生成的有效预览保留并明确标为部分结果，只有用户显式选择「仅检查已完成结果 / Review completed results only」后才能继续确认这些修改，不把未完成部分假装成功。

- **AC-4 严格校验与失败批次**：返回ID须与请求一一对应，无缺条、多条、重复/未知ID或空结果；不合法整批显示「纠错结果无效 / Invalid correction result」，不静默补原文或错位匹配。提供「重试失败批次 / Retry failed batches」。用户可以明确「排除此批次 / Exclude this batch」，排除范围保留正式原文并显示数量；未处理失败批次存在时禁用统一确认。重试不得覆盖用户已经手动调整的预览文本，冲突时要求重新检查。

- **AC-5 统一标记与预览**：有效差异默认纳入待确认版本，直接在字幕对应位置标记新增/删改，辅以文字或图标，不只靠颜色；可切换「当前字幕 / Current subtitles」「修改预览 / Preview changes」，显示「预览，尚未应用 / Preview, not applied」。页面统一提供「确认应用 {count} 处修改 / Apply {count} changes」及「取消修改 / Cancel changes」，不要求逐条接受。时间轴可标记有文字纠错的字幕位置，但不得使用“待剪除音视频”含义的红色删除区间。没有差异显示「没有需要确认的修改 / No changes to review」，确认不可用。

- **AC-6 局部手动调整**：用户可在待确认版本中直接编辑任何有问题的建议，改后立即更新差异和修改数量，显示「已手动调整 / Manually adjusted」；不必重跑AI。每条可选「保留原文 / Keep original」或「恢复AI建议 / Restore AI suggestion」；保留原文把该条从本次变更中排除。预览内撤销恢复上一次局部调整，不撤销已确认的项目编辑。输入焦点与输入法组合期间不触发播放器或片段删除快捷键；本地调整不得即时写入正式字幕。

- **AC-7 统一确认**：点击统一确认时核对所有待应用条目的原文基准和目标身份；任何条目过期均不部分提交，标「原文已更新，请重新检查 / Original subtitles changed. Review again.」，用户可刷新该条预览、重新分析或保留当前原文后再确认。无冲突时一次原子应用最终预览中的AI修改与手工修正，保留未纳入条目的当前正式原文。提交中显示「正在应用修改… / Applying changes…」并禁用重复点击，成功提示「已应用 {count} 处修改 / Applied {count} changes」。同一提交重试不能重复应用或重复记历史。

- **AC-8 取消、失败与隔离**：取消清除本轮待确认层，正式字幕不变；若预览含手动修改，先确认「放弃未应用的修改？ / Discard unapplied changes?」，保留/放弃选择明确。网络/存储失败显示原因与重试，保留最终预览和正式旧结果；保存结果不确定时先查询核验，不盲目重发。切换视频/项目或关闭预览先处理未确认修改，旧响应不能应用到新目标；预览不得混入普通导出或F-0004正式编辑恢复副本。

- **AC-9 统一操作历史与回退**：一次统一确认产生一条「AI纠错 / AI correction」操作记录，包含目标、时间、修改数量及应用前后必要文字状态（含手工修正）；在统一操作历史入口可预览/回退，重开项目仍可访问，不需要把整次AI请求重发。回退前确认，回退作为新操作记录，不擦除原记录。回退只影响该操作对应的原文，保留时间戳、译文及EDL；其后相关原文已有修改时提示冲突并要求逐项核对，不静默抹掉后来的校对。历史加载/空/失败与重试复用统一历史交互；回退提交失败保留当前结果，不显示成功。剪辑回退也不得撤销AI文字校对，统一入口应能区分文字操作和剪辑操作。

- **AC-10 实测与两端**：真实API对含已知错误的口播返回建议，至少手工修正5条、保留原文5条，再一次确认，结果必须等于最终预览；重开及历史回退可复现。另用受控响应验证缺条/重复/空结果、取消、过期、部分批次排除及重试不覆盖手工调整。检查字幕ID、时间戳、译文、EDL均未被纠错改变。无真实API配置写Not run，mock不能替代真实验收。

### 成功指标

- 用户无需逐条点接受即可完成一次含至少10条差异的纠错；在预览中修正局部问题后，统一应用结果逐条等于最终预览，排除项保持原文。
- 统一确认前正式字幕及EDL变化数为0；统一确认只产生一次编辑操作和一条历史记录，重试不重复。
- 重开后预览和回退这条操作，原文恢复符合选择，后续文字修改有冲突保护，剪辑结果完全不变。

### 拆分检查

10条AC，围绕统一纠错审阅闭环。持久操作历史为同一确认/回退体验的一部分；不扩成全功能历史版本管理。技术设计评估共用待确认层与历史入口的复用成本，若超出约两周或需改变现有共用契约，先报告维护者，不直接拆多个不完整发布。

### 依赖与影响

复用Host文本Provider、当前项目服务及真实模型配置。统一交互契约与F-0005修订PRD保持一致，但原文修改与EDL采用不同类型的操作；不得为了复用界面而改变剪辑语义。技术设计需明确由哪个首个实现建立共用组件/历史存储，若必须依赖尚未完成的F-0005则通过feature depends明确增加依赖，开发前不得隐含依赖。

影响useAI直接batchUpdateText路径、差异预览、手动编辑、统一提交、持久化操作历史及相关项目格式迁移；格式变化写ADR，不擅改F-0002/3既有字段含义。翻译与模型设置不顺手重构。固定commit验证并包含Red check、真实API和双主题界面证据。
