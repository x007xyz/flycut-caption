## 自行决定的事项

1. **副本是否已写进 Host 按内容比较，不加 Host 操作回执和项目事务。** F-0003 已按 ADR-0003 决定不做事务恢复记录；内容比较只需读一次 Host，不改项目存储格式，同时覆盖「保存成功但副本没删」和「恢复写入响应丢失」（AC-1、AC-5、AC-6）。**请确认。**
2. **复用 F-0003 的保存接口**，只给 `projects.duplicate` 加可选 `copyId`（向后兼容），新增 `projects.identity`（AC-1、AC-7）。
3. **恢复逻辑放在 `ctx.projects`，状态放在 `stores.project.recovery`**，不另建 `ctx.recovery` 插件和 store：恢复和自动保存共用编辑器状态、保存起点和写入队列，拆开要在两个插件之间同步这些状态。
4. **F-0003 的多视频按视频适配**：副本按视频保存，含样式来源；跟随项目的视频恢复时也写项目样式，并按项目样式修订号判断冲突。需求说明写的是 F-0003 上线后再适配，但它已经先合入，不适配就会写错样式。
5. **还开着的窗口用 Web Lock 标记**，其他窗口打开同一项目时不把它当成待恢复副本（AC-3）。不支持 Web Locks 的环境会多提示，不会漏。
6. **「正在检查恢复内容…」超过 300ms 才显示，并且只在项目读取完成后出现**：读取期间沿用 F-0002 / F-0003 的打开中状态（否则会挡住卡片转圈和「正在打开…」，F-0002 AC-18、F-0003 AC-29/30 的测试会失败）。检查期间编辑器一直被挡住（AC-2）。
7. **Host 身份每个连接读一次并缓存**，重连后重读、失败不缓存。打开长视频时页面会忙 35–45 秒（已有问题，见 F-0017），之后再请求身份会超时，被误报成「无法完成恢复」。
8. **多个会话的副本显示为「会话 n · 时间」**，按记录时间倒序，默认选最新（AC-3 没规定会话怎么命名）。
9. **AC-9 失败后确认按钮的文字改为「重试」**（AC 要求「提供重试和取消」）。
10. **记录间隔：停止编辑 250ms、连续编辑最多 1 秒**，给 PRD 的 1 秒 / 2 秒边界留余量（实测见 04）。

## 与设计的偏差

1. 没有 `projects.saveRecoverable` / `projects.recoveryOperation` / `projects.duplicateRecoverable`，没有 Host 操作回执和项目事务（见自行决定 1、2）。
2. 没有单独的 recovery 插件和 store（自行决定 3）。
3. 「正在检查恢复内容…」不覆盖读取 Host 项目的阶段（自行决定 6）。
4. 已知小窗口：本窗口保存成功到副本换成新基准之间（几毫秒）崩溃，下次打开会把自己的修改当成冲突提示；选覆盖即可，不丢数据、不静默覆盖。原设计用持久 pending 标记消除它，本次没做。
5. 清单 6 的桌面端（Tauri）强退没有在开发阶段做，列入 04 的 Not run 交维护者。
