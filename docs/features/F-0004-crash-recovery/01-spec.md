# F-0004 崩溃恢复：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

## 立项

### 来源

- 已确认的 Epic E-02/7：「崩溃恢复：应用或 Host 异常退出时，找回尚未写入 Host 的修改（自动保存已并入 F-0002）」。
- 已确认路线图阶段一第 4 项，在项目管理之后推进。
- 维护者原话（2026-11-05）：「那先继续下一项的 PRD 吧」。按路线图顺序对应本候选；此话表示推进文档，不视为对本立项细节的确认。

### 要解决的问题

口播创作者校对、删字幕或调整样式后，修改可能还在自动保存等待窗口里，或因 Host 断开而未写入项目。应用崩溃、页面异常关闭或 Host 重启后，重新打开只能拿到上一次成功保存的状态，用户需要重做且不知道丢了多少工作。

要区分：Host 已收到但尚未写完的修改，可以由 Host 保护；只存在前端内存、尚未送达 Host 的修改，Host 无从恢复。仅完善 Host 写入原子性不能解决后一类问题。

### 目标用户与场景

- 对照 docs/10-product/vision.md：校对 10–60 分钟中文口播的个人创作者。
- 桌面应用意外退出，重启后找回最近校对；Host 异常退出后重新连接，不因重试覆盖另一窗口的新修改。
- Web 页面意外关闭后，回到同一浏览器、同一 Host 和项目时可发现待恢复内容；跨设备找回未送达 Host 的内容不在本次承诺内。

### 竞品怎么做

来源：项目 vision.md 中剪映、Descript、Gling、OpusClip 的定位信息（读取日期 2026-11-05）。这些产品对崩溃草稿的保留期限、恢复粒度和并发覆盖行为，本次未外部核实，均标为待核实，不作为范围或效果承诺的依据。

我们的重点是可理解的恢复选择、恢复前版本检查，以及不把已保存的内容静默替换成旧草稿。

### 获客价值

主要改善留存和信任，对应愿景中的留存指标；可在创作者教程中展示「异常退出后继续校对」，但只有真实故障恢复验收通过后才能用于宣传。不作为独立获客渠道建设。

### 优先级

P0，属于项目与字幕编辑底座的数据保护。按已确认路线图推进；保护字幕、剪辑与样式，支撑长口播持续编辑。

### 依赖

- F-0002：需要稳定的项目身份、自动保存状态、版本检测、冲突提示及媒体丢失处理。其验收通过之前不能开发。
- 不把 F-0003 列为硬依赖：恢复记录始终使用 Host 身份 + projectId + videoId 隔离；F-0003 上线后追加项目样式版本和项目生命周期适配，不依赖当前数组下标或当前选中视频。若 PRD 决定本次必须交付完整多视频/回收站恢复，则应增加 F-0003 依赖。

### 建议范围（待确认）

- 对字幕文本、删除标记、译文和样式等已进入编辑状态的修改保留临时恢复快照；不复制源媒体。
- 桌面优先，Web 在同一浏览器连接同一 Host 下提供对应恢复能力。
- 异常重启或重新打开项目后，存在比上次保存更新的恢复记录时，提示「恢复 / 放弃」；用户选择前不覆盖项目。
- 恢复必须校验项目/视频身份与保存版本；冲突复用 F-0002 流程，媒体缺失复用重新关联流程。
- 以「最近一次成功写入恢复记录的编辑状态」为保证边界；具体写入频率、最大可接受丢失窗口和保留期限在 PRD 中明确，不承诺任何故障下零丢失。
- 不做撤销历史持久化、历史版本管理、后台 ASR 任务自动续跑、导出任务续跑、源媒体备份、跨设备未同步草稿找回。

### 规模检查

- [x] 用户能感受到：异常退出后可以找回校对结果。
- [x] 可以单独发布：在 F-0002 基础上保护单视频项目，不必等待其他功能。
- [x] 预计 AC 约 10 条以内：围绕记录、发现、恢复、放弃、冲突、隔离和错误状态组织；PRD 再检查。
- [ ] 预计两周左右能做完：客户端临时存储规则未定，确认后再评估，不先承诺。
- [x] 无需新模型或算法选型；存储隔离与恢复测试在技术设计中解决。

### 不做的代价

F-0002 只能保证已成功保存的状态；前端内存中的待保存修改仍可能因异常退出丢失，长素材校对期间的风险更高。

### 已知约束与风险

- decisions.md 规定业务数据由 Host 保存，前端不在浏览器本地存业务数据。客户端恢复缓存包含字幕等业务内容，需要维护者明确批准一个受限例外，不能在技术设计中自行引入。
- 建议例外：客户端只保存待确认写入 Host 的临时恢复副本，Host 仍是正式项目数据来源；确认保存成功或用户放弃后清除对应副本。恢复副本不含 API Key/token，不混用 Host 身份，不自动上传到其他 Host。
- 不保证恢复尚未成功记录的最后一次输入、被操作系统清理的浏览器存储、损坏磁盘或被永久删除的媒体；必须让用户看见恢复记录失败，不能显示虚假的保护状态。
- 恢复不能绕过版本冲突、用户删除或权限校验；多窗口副本应按编辑会话区分，不互相覆盖。
- 原始媒体始终不改写或删除。

## 产品需求

### 背景

立项已于 2026-11-05 获维护者确认：允许客户端保存尚未成功写入 Host 的临时恢复副本；正式项目数据仍以 Host 为准。本需求先保护 F-0002 的单视频项目，F-0003 的多视频、共享样式及回收站在其上线后适配，不作为本次开发前置条件。

F-0002 自动保存不能恢复仅存在于前端内存的待发送修改。应用异常退出、Web 页面关闭或 Host 中断后，本需求让用户主动找回最近一次成功记录的编辑状态，不静默覆盖已保存的项目。

### 目标用户与竞品

目标是校对 10–60 分钟中文口播的个人创作者。竞品定位沿用立项引用的 vision.md；具体恢复机制未外部核实，不作为验收依据。用户价值是异常退出后少重做、知道恢复了哪个时间点、发生冲突时有选择权。

### 范围

#### 做

- 桌面端先交付；Web 在同一浏览器配置、同一站点和同一 Host 下验证同等编辑恢复行为。
- 已有项目、已有转写、进入编辑器后的字幕修改、删除标记、译文、主副字幕样式和画幅。恢复载入的是同一编辑快照，不能将不同时间点的部分状态拼合。
- 应用/Web 页面与 Host 同时中断后，在相同客户端恢复记录仍可读、Host 恢复且项目存在的条件下恢复；Host 暂不可达时保留副本，待重新连接后检查版本。
- 临时副本按 Host 的稳定身份、项目、视频及编辑会话隔离，不能只用 URL 或当前选中项识别。更换 token 不应误认成别的 Host；同 URL 上换了 Host 必须重新核验身份。
- 只保存每会话最近一次完整恢复状态及必要版本信息；不包含原媒体、音频、API Key/token，不用 localStorage 承载正式项目。不同窗口不能相互覆盖恢复记录。
- 本地记录目标：在存储健康且应用持续运行时，停止编辑后 1 秒内完成；连续编辑时至少每 2 秒尝试记录一次。保证仅覆盖已成功记录的状态，强退可能损失最后一段尚未记录的输入。
- 重新打开对应项目时先检查恢复记录；没有待恢复内容就正常进入编辑器，不额外弹提示。不新增全局恢复中心。
- 用户主动选择恢复或放弃；恢复前重新读取 Host 状态并校验版本。已由 Host 确认保存的同一快照不再提示；较新但版本冲突的副本仍保留，由用户决定。
- 成功保存对应快照或主动放弃后清除对应副本；保存过程中产生了更新编辑时，旧保存成功不能误删更新副本。未处理副本不按时间自动删除；浏览器/系统自行清理存储、清除应用数据不在保证范围。

#### 不做

- 自动恢复未完成的 ASR、AI 请求或导出任务；首次转写结果尚未成功保存时的恢复。
- 撤销/重做历史持久化、历史版本浏览、媒体备份、跨设备未同步修改恢复。
- 恢复用户已经永久删除的项目/视频、绕过权限或版本检查。目标不存在时副本保留并给出错误，不偷偷重建项目。
- F-0003 的多视频切换、项目级共享样式及回收站恢复；F-0003 上线前需专门适配验证，不能宣称本需求已覆盖这些场景。
- 防止磁盘损坏、操作系统强制清理或浏览器拒绝持久存储；这些情况要明确显示保护失败。

### 用户故事

- 作为口播创作者，我希望应用意外退出后找回已校对的字幕与剪辑，减少重做。
- 作为创作者，我希望知道恢复内容的记录时间，并选择恢复或放弃。
- 作为打开多个窗口的用户，我希望恢复旧草稿前检测冲突，避免覆盖另一个窗口保存的新工作。

### 验收标准

以下 AC 均适用于桌面端（Tauri + 本机 Host），Web 用 `pnpm dev` 连接同一 Host 验证；不依赖具体 ASR Provider，对已有字幕编辑生效。所有新增界面状态覆盖明暗主题、中英文。故障测试必须区分客户端崩溃、Host 中断和同时中断。

- **AC-1 临时记录与隔离**：当用户修改范围内的编辑内容时，系统应按上述时限记录完整副本，并保留最后一次成功记录，不能因新一次写入中断而把旧副本损坏。强制终止客户端后重新打开应能恢复最近一次成功记录的字幕、删除标记、译文、样式和画幅。Host 重启不改变副本归属；另一 Host、项目、视频或会话的内容不能混入。确认保存同一快照后不再提示；确认旧快照时不得清除尚未保存的新修改。测试需在可识别的多个编辑版本之间注入中断，核对恢复版本与实际记录版本一致。

- **AC-2 检查中**：当用户打开已有项目且系统尚在检查恢复记录或核验 Host 状态时，应显示「正在检查恢复内容… / Checking for recovery data…」，编辑区不可修改，返回首页可用。Host 不可达或检查失败时不得直接当作没有记录，转 AC-6。若确认无待处理记录，则正常显示 Host 保存的编辑内容，不弹恢复对话框。

- **AC-3 发现待恢复内容**：当同一项目有尚未处理的恢复记录时，应显示对话框「发现未保存的修改 / Unsaved changes found」，说明「发现此设备上 {time} 记录的修改。恢复前会检查项目的最新版本。 / Changes recorded on this device at {time} are available. The latest project version will be checked before recovery.」，按钮「恢复修改 / Recover changes」「放弃恢复 / Discard recovery」「稍后 / Later」。同时列明 Host 上最后保存时间；多个会话有副本时，按记录时间倒序列出并标记会话，只能选择一个完整副本，不自动合并。稍后或关闭对话框返回首页，不清除副本，不启动项目自动保存。

- **AC-4 恢复中**：当用户选择恢复时，应显示「正在恢复… / Recovering…」，恢复/放弃按钮不可重复点击，避免重复提交；此时编辑区不可修改。系统重新读取当前 Host 版本，目标不存在或无权限时进入 AC-6；版本不符时进入 AC-7。恢复不得对其他项目写入。

- **AC-5 恢复成功**：当副本的基准版本仍有效且恢复写入 Host 成功时，应进入编辑器，显示完整恢复结果及提示「修改已恢复并保存 / Changes recovered and saved」，保存状态沿用 F-0002，清除此次已恢复副本。若清除失败，副本应可被识别为已应用，下一次打开不重复写入。媒体丢失时保留恢复结果并沿用 F-0002 的媒体重新关联提示，不能声称媒体已恢复。恢复成功后再强退和重开，应从 Host 读到同样的结果。

- **AC-6 检查或恢复失败**：当读取副本、连接 Host、核验权限或恢复写入失败时，应显示「无法完成恢复 / Couldn't complete recovery」，说明「恢复未完成，现有项目没有被此操作覆盖。请重试或稍后处理。 / Recovery isn't complete. This operation has not overwritten the existing project. Try again or return later.」，按钮「重试 / Retry」「返回首页 / Back to projects」。恢复提交已送达但响应丢失时先查询确认，不得误报未写入或盲目覆盖；未能确认结果时说明「暂时无法确认保存结果，重新连接后检查。 / The save result can't be confirmed yet. Reconnect to check.」。可读副本及无法读取的原记录都不得因失败被删除。目标不存在时补充「原项目或视频已不存在，无法恢复到原位置。 / The original project or video no longer exists. Recovery to the original location isn't available.」。

- **AC-7 版本冲突**：当恢复记录的基准版本与 Host 当前版本不同时，应保留当前正式项目并沿用 F-0002 冲突选择：显式覆盖、另存为新项目、取消；提示「项目已有更新的修改，请选择恢复方式。 / The project has newer changes. Choose how to recover.」。只有用户明确选择后才提交，取消保留副本并返回恢复选择；操作失败进入 AC-6。另存成功只处理选中的副本，不能删除其他会话记录；覆盖不得绕过项目不存在或无权限错误。

- **AC-8 放弃确认**：当用户点击放弃恢复时，应二次确认：「放弃这些未保存的修改？ / Discard these unsaved changes?」，说明「只会移除此恢复副本，已保存的项目不受影响。 / Only this recovery copy will be removed. Your saved project won't change.」，按钮「放弃恢复 / Discard recovery」「取消 / Cancel」。取消返回恢复选择，副本不变。

- **AC-9 放弃处理**：当用户确认放弃时，应在处理期间显示「正在移除恢复副本… / Removing recovery copy…」并禁用重复操作；成功后加载 Host 已保存内容，提示「已放弃恢复 / Recovery discarded」，不得修改正式项目。失败时保持确认框，显示「无法移除恢复副本，请重试。 / Couldn't remove the recovery copy. Please try again.」，提供重试和取消，不能显示成功。仅移除用户选中的副本。

- **AC-10 临时记录失败**：当存储不可用、空间不足或副本写入失败时，应在编辑器显示持续提示「崩溃恢复暂不可用 / Crash recovery unavailable」，说明「临时恢复记录失败，异常退出可能丢失尚未保存的修改。请保存到 Host。 / Recovery data couldn't be recorded. A crash may lose changes not yet saved. Save to the Host.」，按钮「重试 / Retry」「立即保存 / Save now」。重试成功且最新副本完整记录后移除提示；保存按钮走 F-0002 的保存流程，Host 保存失败仍按其规则显示。恢复缓存失败不得让正式自动保存停止，也不得清空最后一份有效副本。

### 成功指标

- 用真实口播项目编辑至少 20 次，在健康存储下，停止编辑后临时记录耗时均不超过 1 秒；连续编辑时记录间隔不超过 2 秒。测试报告记录素材、修改数量和实际耗时。
- 对客户端强退、Host 强退、同时强退三种故障各执行至少 3 次：恢复状态与最近一次成功记录的完整快照一致，重新打开后正式项目数据一致。
- 真实双窗口冲突、两个 Host 同名项目、响应丢失与存储故障测试中，无静默覆盖、串项目或误清除更新副本。
- 维护者在一段真实长口播的校对中完成一次主动恢复和一次主动放弃；无匿名遥测，靠验收记录及后续用户反馈观察。

### 拆分检查

10 条 AC 围绕同一个「记录 → 发现 → 选择 → 恢复/放弃」闭环，成功与失败状态都属于同一能力，没有独立历史版本或任务续跑功能。预计可在一个需求内实现；开发前由技术设计评估存储与可重复故障注入成本。若无法满足约两周规模，应在开发前退回 Epic 拆分，不自动扩大范围或放宽恢复保证。
