# F-0002 项目数据保存到 Host：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

## 立项

### 来源

- Epic 候选 **E-02/1**（[E-02 项目与字幕编辑](../../10-product/epics/E-02-subtitle-editing.md)，2026-11-04 确认）：「项目数据保存到 Host：数据模型（支持多视频）与格式版本、Host 持久化存储与 RPC、单个视频的字幕和剪辑结果保存与重新打开；桌面端先发，写 ADR」。
- 维护者原话（2026-11-05）：「先立项 E-02/1」。
- 维护者 2026-11-04 的要求（E-02 讨论时）：「一个项目里面应该有多个视频，方案类似于 opusclip web端和 桌面端 都通过和后端交互把数据保存下来」。
- 路线图阶段一第 2 项（[roadmap.md](../../10-product/roadmap.md)）。

### 要解决的问题

转写和校对完一段视频，关掉应用就全丢了：

- **字幕和剪辑结果只在内存里。** 字幕条和删除标记在 `historyStore`（内存），字幕样式在 `FlyCutCaption.tsx` 的组件状态里；刷新或关闭窗口后都没有了。一段 20 分钟的口播，转写加校对可能要半小时以上，丢一次就要全部重来。
- **只有设置会保存，而且存在浏览器本地。** `appStore` 用 `localStorage`（`app-settings`）保存语言、模型选择、AI 模型配置、去静音阈值等，不保存任何项目内容。
- **媒体文件在 Host 上只活 24 小时。** 上传给 Host 的文件放在 `assets/`，按 `assetTtlHours`（默认 24 小时）自动清理，不能作为项目的长期存储。
- **后续功能没有数据来源。** 项目管理（E-02/6）、自动保存（E-02/7）、统一编辑决策（E-06/1）、CLI / MCP（E-08/1）都需要「项目数据在 Host 上」这个前提。

### 目标用户与场景

- **口播创作者**（[vision.md](../../10-product/vision.md)）：录完一段 10–60 分钟的口播，转写、校对、粗剪往往分几次完成，中途会关掉应用或者换天再做。
- 一个主题或系列会有多段视频（例如同一期内容分几段录），希望放在同一个项目里（多视频的管理界面在 E-02/6，本需求先把数据模型和存储做好）。

### 竞品怎么做

资料为产品公开说明和使用印象，具体行为待核实（2026-11-05）：

- **剪映**：草稿自动保存在本地草稿目录，重新打开继续编辑；素材引用原文件位置，原文件移动后需要重新链接。
- **Descript**：项目保存在云端，多设备打开同一项目；素材上传到云端。
- **OpusClip**：网页端项目，上传后的视频和生成的短片都在账号下的项目里。
- **我们的不同**：桌面端和 Web 端用同一套 Host 接口和数据格式（桌面连本机 Host，Web 连 FlyCut Cloud 托管的 Host）；桌面端素材不必上传到云端。

### 获客价值

间接。「做了一半不会丢」是留存的基本条件，对应 vision.md 的留存指标；也是 CLI / MCP（Agent 生态渠道）能操作项目的前提。

### 优先级

P0（[decisions.md](../../decisions.md#产品定位与优先级)：转写 + 添加字幕的底座，持续打磨）。现在做，是因为它不依赖其他需求，而阶段一的 E-02/6、E-02/7、E-06/1 以及后面的 E-08/1 都依赖它，越早定下数据模型，后面返工越少。

### 依赖

无。下游依赖它的：E-02/6、E-02/7、E-06/1、E-08/1。

与 F-0001（转写质量基准）没有依赖关系，可以并行。

### 规模检查

- [x] 用户能感受到：关闭后重新打开，字幕和剪辑结果还在
- [x] 可以单独发布：桌面端先发
- [x] 预计验收标准不超过 10 条左右
- [ ] 预计两周左右能做完：**有风险**。数据模型、Host 存储与 RPC、前端改为从 Host 读写、媒体保存方式的 ADR 加在一起偏大。建议把范围控制在「单个视频的项目能保存和重新打开」，项目列表界面、多视频切换留给 E-02/6
- [ ] 没有重大技术不确定性：**桌面端媒体怎么保存**还没定（复制进 Host、移动、还是只记录原文件位置），在设计阶段用 ADR 决定；不需要单独拆调研

### 不做的代价

用户每次关闭应用都要重新转写和校对，长视频基本没法分几次完成；E-02/6、E-02/7、E-06/1、CLI / MCP 都无法开始。

### 已知约束与风险

- **已拍板的决定**（[decisions.md](../../decisions.md)）：
  - 「项目与数据」：一个项目多个视频；数据由 Host 保存；项目媒体和产出物不受 24 小时自动清理；数据带格式版本、可迁移；冲突不静默覆盖。本需求要满足前四条，冲突检测可以先做最简单的版本号检查。
  - 「RPC 不接收任意本地路径」：如果桌面端选择「记录原文件位置」，路径只能由 Tauri 外壳登记，不能由 RPC 传入。
  - 「Tauri 只做桌面外壳」：存储逻辑放在 Host 插件，不新增执行业务的 Tauri command。
- **磁盘占用**：60 分钟的素材复制进 Host 会占双份磁盘。
- **隐私**：项目数据存在用户本机的 Host 目录（`hostConfig.home`）；Web 端连 Cloud 时存在 Cloud，不在本仓库范围。
- **现有设置**：`localStorage` 里的设置（语言、模型、AI 配置）不在本需求里迁移；AI 配置迁移到 Host 属于 E-08/7。
- **Web 端**：Web 连远程 Host 依赖 E-08/6；本需求桌面端先发，PRD 里写明 Web 端用开发模式本机 Host 验证同一套接口。

### 待澄清的问题

- [x] 1. **重新打开的入口**：E-02/6 才做项目列表界面。本需求是否带一个最简单的「最近项目」入口（例如启动页列出最近 10 个项目，可以打开），还是只在启动时自动恢复上一次的项目？ 维护者 2026-11-05 回答：「带最近项目列表」。
- [x] 2. **第一版保存哪些内容**：我的建议是转写结果（含字词时间戳）、字幕修改与删除标记、译文（`secondText`）、字幕样式、用于导出的画幅设置；撤销历史不保存。还有要加或去掉的吗？（2026-11-05 按建议处理，维护者未提异议）
- [x] 3. **已经打开中的旧流程**：没有项目概念的「直接拖入视频」用法要保留吗？我的建议是保留，拖入视频时自动创建一个项目。（2026-11-05 按建议处理，维护者未提异议）

### 结论

**建议做**，范围收窄为「单个视频的项目能保存到 Host、关闭后重新打开」，数据模型从一开始支持多视频；项目列表和多视频切换留给 E-02/6。桌面端媒体保存方式在设计阶段写 ADR。重新打开的入口是启动页的「最近项目」列表（最近 10 个，可打开）。待澄清问题已回答。

## 产品需求

### 背景

现在转写和校对的结果只在内存里，关掉应用就全丢了；只有设置存在浏览器 `localStorage`，上传给 Host 的媒体 24 小时后自动清理（见 [01-spec.md](01-spec.md)）。立项结论：范围收窄为「单个视频的项目能保存到 Host、关闭后重新打开」，数据模型从一开始支持多视频；拖入视频时自动创建项目。重新打开的入口原定为启动页的「最近项目」列表，交互原型阶段维护者要求改为独立的「我的项目」页面（2026-11-05）。

### 目标用户与竞品

- **口播创作者**：一段 10–60 分钟的口播，转写、校对、粗剪分几次完成，中途会关掉应用。
- **竞品**：剪映草稿自动存在本地，素材引用原文件；Descript、OpusClip 的项目存在云端（具体行为待核实，见立项文档）。
- **我们的不同**：桌面端和 Web 端用同一套 Host 接口和数据格式；桌面端素材不必上传云端。

### 范围

#### 做

- **项目数据模型**：项目 → 视频 → 每个视频的转写、字幕修改、编辑结果、样式。模型支持一个项目多个视频，但本需求的界面只处理单个视频。数据带格式版本号。
- **Host 存储与接口**：项目数据存在 Host（`hostConfig.home` 下），通过 RPC 读写；项目里的媒体不受 24 小时自动清理。
- **保存的内容**：
  - 转写结果：句级字幕、字词时间戳、是否有字词时间戳、语言、时长、所用模型（`ModelRef`）；
  - 字幕文本修改、删除与恢复标记、译文（`secondText`）；
  - 字幕样式（主 / 副）、画幅设置。
- **自动保存**：修改后自动保存到 Host（短暂停顿后合并保存，不是每次按键都写）；界面显示「保存中 / 已保存 / 保存失败」；`Cmd/Ctrl+S` 立即保存；保存失败时保留修改并重试。
- **创建项目**：拖入或选择视频时自动创建项目，默认名称为文件名（不含扩展名）。
- **项目首页**：打开应用先进入独立的「我的项目」页面（左侧导航 + 新建区 + 项目卡片网格，参考 OpusClip），按最后修改时间倒序列出全部项目，可搜索、切换网格 / 列表视图，点击进入编辑器；编辑器顶栏显示「我的项目 / 项目名」和保存状态，可返回项目首页。
- **冲突检测**：保存时检查版本号，发现被别处修改过就提示，不静默覆盖。
- **桌面端媒体保存方式**：复制、移动或记录原文件位置，在设计阶段写 ADR 决定。

#### 不做

- 项目管理操作（重命名、删除项目、排序）、项目内添加 / 切换 / 移除多个视频（项目详情页）、项目级共享设置：E-02/6。交互原型已一并设计，本需求不实现。
- 崩溃恢复（应用或 Host 异常退出时，尚未写入 Host 的修改如何找回）：E-02/7。
- 项目导入导出、备份迁移：E-02/8。
- 撤销历史的保存：重新打开后从保存时的状态开始，撤销栈为空。
- 设置（语言、模型选择、AI 模型配置）迁移到 Host：仍在 `localStorage`；AI 配置迁移属于 E-08/7。
- Web 端连接 FlyCut Cloud：E-08/6。本需求在 Web 端用开发模式连接本机 Host 验证同一套接口。
- 导出产物（成片、字幕文件）作为项目产出物保存：先保持现状（导出到用户选择的位置）。

### 用户故事

- 作为口播创作者，我想要关掉应用后再打开还能接着校对，而且不用记得手动保存，以便长视频可以分几次做完。
- 作为口播创作者，我想要一打开应用就看到我的全部项目，以便一键回到上次的工作。
- 作为口播创作者，我想要拖入视频就自动有一个项目，以便不用先学「建项目」这一步。
- 作为口播创作者，我想要在两个窗口不小心同时改一个项目时得到提示，以便不会丢掉其中一边的修改。

### 验收标准

除特别注明外，在桌面端（Tauri，本机 Host）下成立，与 ASR Provider 无关；验收至少用内置 sherpa-onnx 和一个 HTTP Provider 各跑一遍 AC-2。

- **AC-1**：当用户拖入或选择一个视频时，系统应在 Host 上创建一个项目（默认名称为文件名，不含扩展名），并把视频加入该项目；创建过程不通过 RPC 传入本地文件路径。
- **AC-2**：当转写完成时，系统应把转写结果（句级字幕、字词时间戳、`hasWordTimestamps`、语言、时长、所用 `ModelRef`）保存到该项目，不需要用户手动保存。
- **AC-3**：当用户修改字幕文本、删除或恢复字幕、修改译文、主 / 副字幕样式或画幅设置后停止操作，系统应在 3 秒内自动保存到 Host，并显示「已保存」；按 `Cmd/Ctrl+S` 时立即保存。连续修改时不应每次按键都写一次。
- **AC-4**：当自动保存失败时（例如 Host 未响应），系统应显示「保存失败」并保留修改、自动重试；在仍有未写入的修改时关闭窗口或打开另一个项目，系统应先尝试保存，仍失败则提示「重试 / 放弃修改 / 取消」，选择取消时停留在当前项目。
- **AC-5**：当用户打开应用时，应进入「我的项目」页面，按最后修改时间倒序列出全部项目（缩略图、名称、视频时长、最后修改时间，转写中 / 媒体丢失等状态），可按名称搜索、切换网格和列表视图；点击某个项目后，应直接进入编辑界面，字幕文本、删除标记、译文、样式、画幅与最后一次保存时一致，不重新转写；编辑器顶栏可返回项目首页。
- **AC-6**：当应用和 Host 都重启（例如重启电脑），并且超过 Host 临时资产的清理期限（验收时把 `assetTtlHours` 调小来模拟）后，AC-5 仍应成立，视频可以正常播放和导出。
- **AC-7**：当项目的媒体不可用时（例如按 ADR 记录的原文件被移动或删除），打开项目应提示媒体丢失并允许重新选择文件；在此期间字幕仍可查看、编辑并导出字幕文件，应用不崩溃。
- **AC-8**：当读到旧格式版本的项目数据时，系统应迁移后打开且不丢内容；当读到比当前程序更新的格式版本时，应拒绝打开并提示升级，且不修改该项目的文件。
- **AC-9**：当同一项目在两个窗口中打开，其中一个已保存后另一个再保存（包括自动保存）时，系统应检测到版本冲突、暂停该窗口的自动保存并提示用户（例如「项目已在别处修改，覆盖 / 另存为新项目 / 取消」），不静默覆盖。
- **AC-10**：在 Web 端（开发模式，`pnpm dev` 连接本机 Host）下，AC-2、AC-3、AC-5 应同样成立，使用与桌面端相同的 RPC 和数据格式；桌面端保存的项目在连接同一 Host 的 Web 端能打开。

#### 界面状态

> 2026-11-05 补充：需求流程取消了交互原型阶段，界面状态改由 PRD 的 AC 把关。下面 AC-11 到 AC-27 从原型记录（[ux.md](ux.md)）和 `src/locales/{zh_CN,en_US}.ts` 的 `components.project` 整理而来，是 AC-3、AC-4、AC-5、AC-7、AC-8、AC-9 在界面上的细化，不增加范围。

以下各条在桌面端和 Web 端都成立（AC-24 注明的除外），明暗主题、中英文界面下都要成立；文案写成「中文 / English」，`{…}` 是占位符。E-02/6 的控件（排序、卡片「更多」菜单、重命名、删除、项目详情页）本需求不显示。

**我的项目（首页）**

- **AC-11 加载中**：读取项目列表期间，项目区显示卡片骨架屏（读屏标签「正在读取项目… / Loading projects…」），不显示项目数量；新建区（拖入、「选择文件」、「用示例视频试试」）照常可用。
- **AC-12 读取失败**：读取项目列表失败时（例如 Host 未响应），项目区显示「读取项目失败 / Couldn't load projects」和「没能连接到 FlyCut Host，请稍后重试 / Couldn't reach FlyCut Host. Please try again.」以及「重试」按钮；点击「重试」重新读取，并回到加载中状态。
- **AC-13 空**：没有任何项目时，显示「还没有项目 / No projects yet」和「拖入一个视频或音频，就会自动创建项目，转写和修改都会自动保存。 / Drop a video or audio file to create a project. Transcripts and edits are saved automatically.」，新建区是唯一的操作入口。
- **AC-14 有项目**：标题显示「我的项目 / My projects」和「{count} 个项目 / {count} projects」。网格视图每张卡片显示缩略图（截图失败时显示占位图）、名称、视频时长、最后修改时间（1 分钟内显示「刚刚 / just now」）；正在转写的项目在缩略图底部显示进度条和「转写中 {progress}% / Transcribing {progress}%」，媒体不可用的项目显示「媒体丢失 / Media missing」。列表视图显示名称、视频、时长、修改时间、状态五列。网格 / 列表的选择在重新打开应用后保持。
- **AC-15 搜索无结果**：在「搜索项目 / Search projects」框输入后实时按名称过滤；没有匹配时显示「没有找到「{query}」相关的项目 / No projects match "{query}"」；清空搜索框恢复完整列表。
- **AC-16 拖入文件**：把文件拖到窗口上时，整页显示遮罩和「松开即可创建项目 / Release to create a project」；拖出窗口后遮罩消失，不创建项目。
- **AC-17 正在创建**：松开文件、点「选择文件 / Choose file」选好文件或点「用示例视频试试 / Try a sample video」后，新建区显示转圈，「选择文件」不可点击；创建成功后提示「已创建项目「{name}」 / Created project "{name}"」并进入编辑器。
- **AC-18 正在打开**：点击某个项目后，该卡片显示转圈和「正在打开… / Opening…」，其他卡片变灰且不可点击，直到进入编辑器或出现 AC-26 的对话框。

**编辑器顶栏**

- **AC-19 已保存**：顶栏品牌后显示「‹ 我的项目 / My projects」和项目名；保存成功后显示「已保存 · {time} / Saved · {time}」约 3 秒再淡出。点击「我的项目」返回首页（有未写入的修改时按 AC-4、AC-24 处理）。
- **AC-20 有未保存的修改**：修改后、开始保存前显示「有未保存的修改 / Unsaved changes」，悬停提示「立即保存（{shortcut}） / Save now ({shortcut})」（macOS 为 ⌘S，其他平台为 Ctrl+S），点击立即保存。
- **AC-21 保存中**：保存请求进行中显示「保存中… / Saving…」。
- **AC-22 保存失败**：保存失败后显示「保存失败，重试中 / Save failed, retrying」，一直显示到保存成功；点击立即重试。
- **AC-23 保存已暂停**：检测到版本冲突后显示「保存已暂停 / Saving paused」和「处理冲突 / Resolve」，悬停说明「项目在另一个窗口或设备上被修改，为避免覆盖已暂停自动保存 / The project was changed in another window or device. Auto-save is paused to avoid overwriting it.」；点击「处理冲突」打开 AC-25 的对话框。

**对话框与提示**

- **AC-24 未保存离开**：桌面端在 AC-4 的情况下弹出对话框，标题「还有修改没有保存 / Some changes are not saved」，说明「自动保存失败，关闭后这些修改会丢失。 / Auto-save failed. These changes will be lost if you close now.」，按钮「重试保存 / Retry save」「放弃修改 / Discard changes」「取消」；重试期间按钮显示「正在重试… / Retrying…」且三个按钮都不可点击，重试成功后继续原来的离开操作。Web 端关闭标签页时只能显示浏览器自带的离开确认框；在应用内返回首页或打开别的项目时，与桌面端相同。
- **AC-25 版本冲突**：对话框标题「项目已在别处修改 / Project changed elsewhere」，说明「「{name}」在另一个窗口或设备上于 {time} 保存过。为避免覆盖对方的修改，自动保存已暂停。 / "{name}" was saved in another window or device at {time}. Auto-save is paused so their changes are not overwritten.」，提示「另存为新项目会保留两边的修改。 / Saving as a new project keeps both versions.」，按钮「用我的版本覆盖 / Overwrite with mine」「另存为新项目 / Save as new project」「取消」。覆盖后恢复自动保存；另存为新项目后进入新项目，原项目不变；取消后保持 AC-23 的状态。
- **AC-26 版本过新**：打开格式版本更新的项目时，停留在首页并弹出对话框，标题「无法打开这个项目 / Can't open this project」，说明「「{name}」是用更新版本的 FlyCut 保存的。请升级后再打开，项目文件不会被改动。 / "{name}" was saved by a newer version of FlyCut. Update FlyCut to open it; the project files are left unchanged.」，只有「关闭」按钮。
- **AC-27 媒体丢失**：进入媒体不可用的项目时，播放器区域显示「找不到这个项目的视频文件 / Can't find this project's video」、「原文件「{file}」可能已被移动或删除。字幕仍可查看、编辑和导出字幕文件。 / The file "{file}" may have been moved or deleted. Subtitles can still be viewed, edited and exported.」和「重新选择文件 / Choose file again」；字幕列表照常可编辑，导出视频不可用；重新选择文件成功后横幅消失、视频可以播放。
