# F-0002 项目数据保存到 Host：产品需求

## 背景

现在转写和校对的结果只在内存里，关掉应用就全丢了；只有设置存在浏览器 `localStorage`，上传给 Host 的媒体 24 小时后自动清理（见 [01-intake.md](01-intake.md)）。立项结论：范围收窄为「单个视频的项目能保存到 Host、关闭后重新打开」，数据模型从一开始支持多视频；拖入视频时自动创建项目。重新打开的入口原定为启动页的「最近项目」列表，交互原型阶段维护者要求改为独立的「我的项目」页面（2026-11-05）。

## 目标用户与竞品

- **口播创作者**：一段 10–60 分钟的口播，转写、校对、粗剪分几次完成，中途会关掉应用。
- **竞品**：剪映草稿自动存在本地，素材引用原文件；Descript、OpusClip 的项目存在云端（具体行为待核实，见立项文档）。
- **我们的不同**：桌面端和 Web 端用同一套 Host 接口和数据格式；桌面端素材不必上传云端。

## 范围

### 做

- **项目数据模型**：项目 → 视频 → 每个视频的转写、字幕修改、编辑结果、样式。模型支持一个项目多个视频，但本需求的界面只处理单个视频。数据带格式版本号。
- **Host 存储与接口**：项目数据存在 Host（`hostConfig.home` 下），通过 RPC 读写；项目里的媒体不受 24 小时自动清理。
- **保存的内容**：
  - 转写结果：句级字幕、字词时间戳、是否有字词时间戳、语言、时长、所用模型（`ModelRef`）；
  - 字幕文本修改、删除与恢复标记、译文（`secondText`）；
  - 字幕样式（主 / 副）、画幅设置。
- **自动保存**：修改后自动保存到 Host（短暂停顿后合并保存，不是每次按键都写）；界面显示「保存中 / 已保存 / 保存失败」；`Cmd/Ctrl+S` 立即保存；保存失败时保留修改并重试。
- **创建项目**：拖入或选择视频时自动创建项目，默认名称为文件名（不含扩展名）。
- **项目首页**：打开应用先进入独立的「我的项目」页面（左侧导航 + 新建区 + 项目卡片网格，参考 OpusClip），按最后修改时间倒序列出全部项目，可搜索、切换网格 / 列表视图，点击进入编辑器；编辑器顶栏显示「我的项目 / 项目名」和保存状态，可返回项目首页。
- **冲突检测**：保存时检查版本号，发现被别处修改过就提示，不静默覆盖。
- **桌面端媒体保存方式**：复制、移动或记录原文件位置，在设计阶段写 ADR 决定。

### 不做

- 项目管理操作（重命名、删除项目、排序）、项目内添加 / 切换 / 移除多个视频（项目详情页）、项目级共享设置：E-02/6。交互原型已一并设计，本需求不实现。
- 崩溃恢复（应用或 Host 异常退出时，尚未写入 Host 的修改如何找回）：E-02/7。
- 项目导入导出、备份迁移：E-02/8。
- 撤销历史的保存：重新打开后从保存时的状态开始，撤销栈为空。
- 设置（语言、模型选择、AI 模型配置）迁移到 Host：仍在 `localStorage`；AI 配置迁移属于 E-08/7。
- Web 端连接 FlyCut Cloud：E-08/6。本需求在 Web 端用开发模式连接本机 Host 验证同一套接口。
- 导出产物（成片、字幕文件）作为项目产出物保存：先保持现状（导出到用户选择的位置）。

## 用户故事

- 作为口播创作者，我想要关掉应用后再打开还能接着校对，而且不用记得手动保存，以便长视频可以分几次做完。
- 作为口播创作者，我想要一打开应用就看到我的全部项目，以便一键回到上次的工作。
- 作为口播创作者，我想要拖入视频就自动有一个项目，以便不用先学「建项目」这一步。
- 作为口播创作者，我想要在两个窗口不小心同时改一个项目时得到提示，以便不会丢掉其中一边的修改。

## 验收标准

除特别注明外，在桌面端（Tauri，本机 Host）下成立，与 ASR Provider 无关；验收至少用内置 sherpa-onnx 和一个 HTTP Provider 各跑一遍 AC-2。

- **AC-1**：当用户拖入或选择一个视频时，系统应在 Host 上创建一个项目（默认名称为文件名，不含扩展名），并把视频加入该项目；创建过程不通过 RPC 传入本地文件路径。
- **AC-2**：当转写完成时，系统应把转写结果（句级字幕、字词时间戳、`hasWordTimestamps`、语言、时长、所用 `ModelRef`）保存到该项目，不需要用户手动保存。
- **AC-3**：当用户修改字幕文本、删除或恢复字幕、修改译文、主 / 副字幕样式或画幅设置后停止操作，系统应在 3 秒内自动保存到 Host，并显示「已保存」；按 `Cmd/Ctrl+S` 时立即保存。连续修改时不应每次按键都写一次。
- **AC-4**：当自动保存失败时（例如 Host 未响应），系统应显示「保存失败」并保留修改、自动重试；在仍有未写入的修改时关闭窗口或打开另一个项目，系统应先尝试保存，仍失败则提示「重试 / 放弃修改 / 取消」，选择取消时停留在当前项目。
- **AC-5**：当用户打开应用时，应进入「我的项目」页面，按最后修改时间倒序列出全部项目（缩略图、名称、视频时长、最后修改时间，转写中 / 媒体丢失等状态），可按名称搜索、切换网格和列表视图；点击某个项目后，应直接进入编辑界面，字幕文本、删除标记、译文、样式、画幅与最后一次保存时一致，不重新转写；编辑器顶栏可返回项目首页。
- **AC-6**：当应用和 Host 都重启（例如重启电脑），并且超过 Host 临时资产的清理期限（验收时把 `assetTtlHours` 调小来模拟）后，AC-5 仍应成立，视频可以正常播放和导出。
- **AC-7**：当项目的媒体不可用时（例如按 ADR 记录的原文件被移动或删除），打开项目应提示媒体丢失并允许重新选择文件；在此期间字幕仍可查看、编辑并导出字幕文件，应用不崩溃。
- **AC-8**：当读到旧格式版本的项目数据时，系统应迁移后打开且不丢内容；当读到比当前程序更新的格式版本时，应拒绝打开并提示升级，且不修改该项目的文件。
- **AC-9**：当同一项目在两个窗口中打开，其中一个已保存后另一个再保存（包括自动保存）时，系统应检测到版本冲突、暂停该窗口的自动保存并提示用户（例如「项目已在别处修改，覆盖 / 另存为新项目 / 取消」），不静默覆盖。
- **AC-10**：在 Web 端（开发模式，`pnpm dev` 连接本机 Host）下，AC-2、AC-3、AC-5 应同样成立，使用与桌面端相同的 RPC 和数据格式；桌面端保存的项目在连接同一 Host 的 Web 端能打开。

## 成功指标

暂无匿名统计（E-08/5 未决定），以下靠维护者自用和用户反馈观察：

- 维护者用一段 20 分钟以上的口播，分至少 3 次打开完成转写、校对、粗剪和导出，期间不丢修改。
- 打开一个 60 分钟视频的项目，从点击到可编辑不超过 3 秒（桌面端，本机 Host）。
- 发布后 30 天内，没有「关闭后字幕丢失」「项目打不开」类的反馈。

## 拆分检查

10 条验收标准；「做」里的各项都服务于「保存并重新打开」这一件事，单独拆出来都无法独立发布。不需要拆分。

## 依赖与影响

- **依赖**：无。
- **影响的现有功能**：
  - 应用增加「我的项目」页面和页面间导航（项目首页 ↔ 编辑器）；`FlyCutCaption.tsx` 的阶段流转（上传 → 转写 → 编辑）改为围绕项目进行；
  - `FlyCutCaption` 新增可选参数 `headerSlot`，`WorkstationHeader` 新增 `slot`，用来放项目面包屑和保存状态（交互原型阶段已加，只是展示位置，不改数据流）；
  - `historyStore` 的初始状态要能从已保存的项目载入；
  - Host 的资产清理要排除项目媒体。
- **需要同步修改的文档**：`docs/architecture-current.md`、`docs/subsystems/cordis-host.md`（新增项目存储插件和 RPC）、`docs/subsystems/frontend.md`（数据来源变化）。
- **ADR**（设计阶段）：项目数据格式与版本迁移；桌面端媒体保存方式。
- **自动保存的写入量**：60 分钟视频的字词时间戳可能有数万条，每次自动保存不能整份重写过大的文件，写入方式在设计阶段定（例如按视频分文件、只写变化的部分）。
- **Epic 需要同步调整**：E-02/7 原为「自动保存与崩溃恢复」，自动保存并入本需求后，E-02/7 收窄为崩溃恢复。E-02 已确认，修改后需要维护者重新确认。
- **对 decisions.md 的影响**：无冲突，落实「项目与数据」小节的前四条，冲突检测做第一版。
