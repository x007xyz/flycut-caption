# F-0015 大文件断点续传与断线恢复：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

## 立项

### 来源

2026-11-05，维护者对批量立项建议回复“其他按你说的做”，明确批准将原 E-08/6 拆为连接会话和续传恢复；本项对应 E-08/9。原话及完整建议见 phase-one-batch-review.md。

### 要解决的问题

Web 用户连接远程 Host 时需要明确的身份与状态，并在网络中断后继续工作，避免上传重头开始、丢失任务状态或重复执行。将连接会话与大文件续传分开可独立交付并分别真实验收。

### 目标用户与场景

处理10–60分钟中文口播的个人创作者，在浏览器连接Cloud托管Host；自部署为次要单用户场景。

### 竞品怎么做

参考 vision.md 中的网页创作工具定位，具体会话及续传策略待核实（2026-11-05）；不以未经验证的竞品内部协议作实现依据。

### 获客价值

支撑Web免安装使用和长素材留存；以真实端到端流程演示，不能把连接成功宣传成阶段一全部功能已完成。

### 优先级

路线图阶段一平台补齐，候选已按维护者同意方向拆分。

### 依赖

F-0014 验收确认；需真实上传会话与完整性协议以及故障注入环境。

### 建议范围

大文件分片上传、完整性校验、暂停/取消/续传、重连核验上传与任务状态、重复操作保护。

#### 不做

Cloud鉴权会话的重复建设、后台永久上传、跨账户或跨Host续传、替代阶段一全部功能验收。

### 规模检查

- [x] 用户可感知且可独立验收。
- [x] 按用户完成的一步拆分，不按前后端分层拆需求。
- [ ] PRD控制约10条AC，技术设计在真实协议明确后评估约两周规模。
- [ ] 外部协议/环境需落实，未落实不能宣称已完成真实验证。

### 不做的代价

用户无法可靠完成远程长素材工作流，断线可能造成重复操作或重传。

### 已知约束与风险

Cloud账号、计费与多租户属于仓库外。凭证不进静态页面、日志或公开链接；服务端仍是单租户且需鉴权反向代理。外部接口未定时PRD明确受阻，不用mock代替真实Cloud验收。

## 产品需求

### 背景

2026-11-05维护者批量确认立项，并明确剪辑建议应先标红/预览、确认后删除，操作历史可回退。本PRD将立项范围落实为可验证行为，不把研究结论或外部服务假设当成事实。所属候选与来源见01-spec.md。

### 目标用户与竞品

10–60分钟中文口播的个人创作者。竞品定位沿用vision.md，具体功能/版本未外部核实均待核实；本PRD以已批准用户任务为依据，不承诺竞品内部协议兼容。

### 范围

#### 做

- 分片完整性、暂停/恢复/取消、网络中断续传，重连核验上传与任务状态。
- 浏览器刷新后可通过同Host/同身份的传输会话找回进度；源文件需用户重新授权选择时明确提示，不假装持有文件。

#### 不做

Cloud鉴权重复建设、跨账户/Host续传、浏览器关闭后保证后台上传、绕过限额、自动重复ASR/导出。

### 用户故事

作为口播创作者，我希望上传长口播中断后继续剩余部分，而不是重传整个素材或重复付费识别。

### 验收标准

桌面端优先，Web开发模式连接同一Host验证共用业务；Cloud连接/续传另需真实远程环境。ASR Provider无关的功能不得按Provider写死分支；字词精确剪切仅看通过校验的实际结果。每个新增界面状态覆盖明暗主题与中英文，关键文案如下；测试名称带F-0015/AC编号。

- **AC-1 协议前置**：F-0014验收确认且真实端点提供上传会话、分片确认/查询、最终完整性校验、取消和过期契约后才能开发集成；未支持端点明确显示“此Host不支持断点续传 / This Host does not support resumable uploads”，不能静默宣称续传可用。

- **AC-2 开始与限制**：选择文件后检查公开的文件大小/类型限制，显示文件名、总大小、目标Host、进度；超限显示原因并禁止开始。服务端再次校验，前端检查不替代鉴权和配额。

- **AC-3 分片确认**：只将服务端确认且内容校验通过的分片计入完成字节，同片重试不重复计数；最终文件大小/内容摘要一致才显示完成并供ASR/项目使用。未合并完的临时文件不能被当成功资产。

- **AC-4 暂停与恢复**：上传中提供“暂停 / Pause”“取消上传 / Cancel upload”；暂停保留会话和已确认分片，继续仅传缺失分片。显示“已暂停 / Paused”，不显示已上传完成；带宽变化不造成超过100%或负进度。

- **AC-5 网络中断**：断线显示“上传已中断，等待重连 / Upload interrupted. Waiting to reconnect.”，恢复鉴权后查询会话和分片状态，不盲目重传所有内容或重复完成操作。重试上限后提供手动重试，不无限循环收费操作。

- **AC-6 刷新与源文件**：刷新后在同Host/身份查询可恢复会话，显示“选择原文件以继续 / Select the original file to continue”。重新选文件须核验内容身份，不只匹配文件名或大小；选错显示“文件不匹配 / File does not match”，不接着写旧会话。浏览器原文件授权不可用时不伪造续传。

- **AC-7 取消与到期**：确认取消后停止后续分片并请求端点清理本次临时上传，不删已保存项目媒体；取消响应丢失先查询状态。会话过期显示“上传会话已过期，请重新开始 / Upload session expired. Start again.”，经用户确认再新建，不能把过期数据冒充可恢复。

- **AC-8 失败与错误**：校验失败、空间/配额不足、权限错误逐项显示原因和可用重试操作；失败分片不确认，已成功部分保留至协议到期。会话过期/无权不可靠重复请求绕过；后台日志不含token或源文件内容。

- **AC-9 任务核验**：完成上传或重连后查询资产/ASR/导出任务状态；同一操作标识重试不得重复创建项目、识别或导出。结果不确定显示“正在核验结果… / Checking result…”并禁用重复启动，不能以超时认定失败后盲目再发。

- **AC-10 实测与隔离**：真实大文件中途断网、刷新、暂停/取消、会话过期分别实测，最终摘要与原文件相同。换Host/账户后不展示或续传旧身份会话；测试配置的限额明确记录，不把模拟分片测试当远程环境成功。

### 成功指标

至少一个真实长口播大文件中断/恢复3次不全量重传、最终摘要一致；刷新重新授权、错文件、重复完成和重连任务均验证无重复副作用。

### 拆分检查

共10条AC，围绕本项用户任务形成可独立验收闭环。技术设计需依据真实调用点/外部协议复核约两周规模；无法一次完成则开发前回Epic拆分，不以多个未完成消费者混合上线。本批远程连接与大文件续传已按维护者确认拆开。

### 依赖与影响

硬依赖F-0014；需要真实服务端续传与幂等任务契约，必要Host传输扩展在本需求内审查但不建设Cloud账号服务。只存非敏感传输会话定位元数据，不把源媒体/业务字幕复制到localStorage。

统一遵守code-standards.md：固定commit逐AC验收，行为改动有Red check；真实模型/接口/素材/导出按改动范围实际验证，未执行列Not run。PRD确认不代表依赖已完成或允许跳过真实验证。
