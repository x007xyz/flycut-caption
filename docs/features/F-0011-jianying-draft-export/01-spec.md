# F-0011 剪映草稿导出：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

## 立项

### 来源

- 已确认 Epic 候选 E-06/6，对应路线图阶段一。批量编写日期：2026-11-05。
- 维护者原话：「是否可以一起确认，调用 subagent 同时处理多个任务，subagent 模型使用 deepseek flash」。本轮只准备可集中审阅的立项，不视为已批准各项产品细节。

### 要解决的问题

FlyCut 完成字幕校对和粗剪后，用户进入剪映仍需重搭切点、字幕和素材关系，无法顺畅继续精剪。

### 目标用户与场景

对照 `docs/10-product/vision.md`：10–60 分钟中文口播创作者，字幕校对、粗剪、导出并继续发布。范围内各操作应让用户能检查结果，不能为了自动化隐去失败或覆盖选择。

### 竞品怎么做

资料来源为已存在的 vision.md 及所属 Epic（读取日期 2026-11-05）。Descript 为文本编辑/校对参考，剪映为后续精剪目标；各产品在本需求的具体版本、限制和行为本轮未外部核实，均待核实，不编造效果或价格。调研项会在研究阶段记录一手来源和日期；功能范围不依赖未经核实的竞品内部实现。

### 获客价值

对应愿景的创作者教程、开源社区与留存渠道：展示真实完成的字幕/粗剪工作流。核心是节省重复劳动、保持原始素材和用户确认权；调研结果不直接当成功能宣传。

### 优先级

P1。按已确认路线图阶段一推进；文档可并行准备，开发/调研仍遵守依赖门禁。

### 依赖

F-0010 调研结论和 F-0005 验收确认后开发。PRD 可以先明确产品行为，具体支持版本、可打包格式和样式能力在研究结论后确认，发生范围变化则重审。

frontmatter 的 depends_on 是脚本门禁；外部接口、真实配置和素材条件也必须在 PRD/研究计划列为前置条件，不能通过省略依赖绕过。

### 建议范围

- 基于已确认的 F-0010 支持矩阵，将 F-0005 的统一剪辑结果和用户字幕写入新的剪映草稿。
- 保存到用户选择的新输出位置，说明依赖原媒体还是包含副本；对媒体缺失、空间不足、不支持版本或样式给清楚反馈。
- 桌面优先，真实剪映打开核验视频切点、字幕时间及可编辑性；明确导出快照，不受导出中继续编辑影响。

#### 不做

覆盖现有用户草稿、自动导入剪映账户、完整复刻所有字幕特效、多轨工程或自由转场、未经研究验证的平台承诺。

## 产品需求

### 背景

2026-11-05维护者批量确认立项，并明确剪辑建议应先标红/预览、确认后删除，操作历史可回退。本PRD将立项范围落实为可验证行为，不把研究结论或外部服务假设当成事实。所属候选与来源见01-spec.md。

### 目标用户与竞品

10–60分钟中文口播的个人创作者。竞品定位沿用vision.md，具体功能/版本未外部核实均待核实；本PRD以已批准用户任务为依据，不承诺竞品内部协议兼容。

### 范围

#### 做

- 从已确认EDL及字幕生成全新可继续编辑的剪映草稿，保持同一次导出快照一致。
- 按F-0010实测支持矩阵限制目标版本、系统、字幕能力和媒体定位，明确降级与缺失资源。

#### 不做

覆盖既有草稿、全版本/CapCut兼容保证、账号上传、自由多轨或全部特效复刻、未经确认的静默样式降级。

### 用户故事

作为口播创作者，我希望粗剪后在剪映继续精剪，切点、字幕和媒体不必重新搭建。

### 验收标准

桌面端优先，Web开发模式连接同一Host验证共用业务；Cloud连接/续传另需真实远程环境。ASR Provider无关的功能不得按Provider写死分支；字词精确剪切仅看通过校验的实际结果。每个新增界面状态覆盖明暗主题与中英文，关键文案如下；测试名称带F-0011/AC编号。

- **AC-1 支持矩阵**：导出入口显示支持的剪映系统/版本和能力范围；全部来源于F-0010真实实测。未知或不支持的目标显示“不支持此草稿版本 / Unsupported draft version”，不得仍生成并宣称可用。

- **AC-2 导出快照**：点击导出时捕获已确认EDL、字幕、样式与媒体身份；临时建议不进入草稿。导出期间继续编辑不影响该草稿，产物显示对应项目/视频和导出时间。

- **AC-3 输出位置**：用户选择新位置，已有同名目录时提供改名/取消，不默认覆盖任何用户草稿。取消选择不创建任务。原始媒体不可修改或删除，RPC不接受任意Host本地路径。

- **AC-4 媒体策略**：开始前明确显示该格式是引用媒体还是复制打包及预计空间。策略须由F-0010证实并在技术设计前列入支持矩阵；复制需用户知晓磁盘占用，引用需提示移动原文件会失联。不以空文件假装媒体齐全。

- **AC-5 导出中**：显示“正在生成剪映草稿… / Creating Jianying draft…”、进度和取消；重复点击不生成多份。取消或失败清理本次临时产物，不删除既有目录；成功前不显示已完成。

- **AC-6 错误状态**：媒体丢失、空间不足、权限错误或格式生成失败时说明原因并可重试；不得留下被当成成功草稿的半成品。源媒体缺失提示重新关联，修复后再导出。

- **AC-7 字幕及切点**：在支持版本内真实打开草稿，媒体保留区间与F-0005已确认结果一致，主/副/双语按支持矩阵仍可编辑；不存在的样式能力须在导出前展示降级清单并由用户接受，否则取消。

- **AC-8 生成成功**：成功后显示“草稿已生成 / Draft created”、可访问输出位置和打开方式说明。Web下载由浏览器保存成可用包装，桌面通过原生保存入口；首发平台依F-0010支持，不把未实测端标通过。

- **AC-9 可搬迁验证**：按声明策略实际移动产物到新目录后打开；引用型正确提示所需媒体位置，打包型验证素材关联不丢。不能用FlyCut播放器成功替代目标剪映打开。

- **AC-10 两段真实素材**：两段原始口播完成字幕和EDL粗剪，真实剪映打开、播放、编辑字幕并继续保存，逐切点/字幕核对；F-0010未给出可用结论时功能验收受阻，不以伪样例宣布完成。

### 成功指标

支持矩阵中每个首发组合至少真实打开一次；两段口播分别核验剪辑与字幕可编辑，失败/取消/重复导出不损伤既有草稿或媒体。

### 拆分检查

共10条AC，围绕本项用户任务形成可独立验收闭环。技术设计需依据真实调用点/外部协议复核约两周规模；无法一次完成则开发前回Epic拆分，不以多个未完成消费者混合上线。本批远程连接与大文件续传已按维护者确认拆开。

### 依赖与影响

依赖F-0010与F-0005完成；具体草稿格式/库许可、打包方式、首发系统版本由研究确认。影响导出插件、媒体包装、保存对话框及说明文档。

统一遵守code-standards.md：固定commit逐AC验收，行为改动有Red check；真实模型/接口/素材/导出按改动范围实际验证，未执行列Not run。PRD确认不代表依赖已完成或允许跳过真实验证。

### 未决问题

支持矩阵、媒体打包方式与样式降级列表待F-0010结论；若与本产品范围不兼容须重审，不自动承诺全平台。
