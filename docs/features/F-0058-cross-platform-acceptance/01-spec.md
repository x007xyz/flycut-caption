# F-0058 Web 与桌面共用自动化验收：需求说明

> 需求说明合并了立项和产品文档，是这个需求的第一个确认点；第二个确认点是测试与验收（调研是调研报告）。

## 来源

E-08/10。维护者（2026-11-10）：「在项目中 添加测试方案，并且要求每个任务都优先使用 自动化测试验收」。

## 要解决的问题

口播创作者在 Web 与桌面都要能修改、保存并重开字幕项目。当前浏览器测试不能证明真实桌面可用；桌面验收依赖临时操作窗口，容易连错应用，也常在验收末尾才发现 Host 或字体资源问题。

## 竞品与获客

内部工程改进，无直接获客目标。[Tauri WebDriver 指南](https://v2.tauri.app/develop/tests/webdriver/)（2026-11-10 核对）列出 WebdriverIO 及 macOS 内嵌驱动方案。

## 优先级与依赖

优先解决影响桌面交付的复验问题。现有项目保存链路与打包命令可用于试点，无新增需求依赖。

## 范围

### 做

- 用 WebdriverIO 让 Web Chrome 与真实 macOS Tauri 窗口运行同一条字幕编辑持久化用例。每端使用真实 Host 和独立的固定项目数据，无需实时 ASR 或付费 API。
- 为不带测试驱动的 macOS 打包产物增加脚本冒烟：启动、等待随包 Host、真实导出中文字幕并断言产物。
- 提供本机命令与 macOS CI 运行入口，记录 Web、桌面 UI、桌面打包冒烟各自的结果。

### 不做

- 不一次性迁移现有 Playwright 用例，不扩大到 Windows/Linux，不自动化剪映和 macOS 原生对话框。
- 不在生产构建注册 WebDriver、测试命令或放宽权限；不改变现有发版闸门。

## 用户故事

- 作为在桌面或 Web 编辑口播的创作者，我希望保存后重开的字幕一致，以便继续上次的编辑。
- 作为维护者，我希望同一条自动化用例在两端给出独立结果，并尽早知道桌面包启动或导出哪里失败。

## 验收标准

- **AC-1**：同一个用例文件在 Web Chrome 与真实 macOS Tauri WKWebView 分别运行时，均能打开各自的预置项目、修改一条字幕、确认真实 Host 保存、离开后重开并断言字幕仍在。测试名称带 AC 编号，分别记录两端结果。
- **AC-2**：macOS 桌面测试按本次构建的绝对路径启动独立标识的测试应用，使用独立数据目录；本机存在旧安装版时仍连接本次启动的实例。生产构建不注册测试驱动或测试权限。
- **AC-3**：启动不带测试驱动的 macOS 打包产物后，随包 Host 就绪；固定短片能导出带中文字幕的 MP4，自动断言音视频轨、合理时长和字幕画面。分别模拟随包 Node 不可用和字体缺失时，冒烟在对应阶段明确失败。
- **AC-4**：文档给出两端与打包冒烟的命令；macOS CI 可运行桌面检查并保存失败日志，三个目标分别出结果。现有 Web Playwright 命令保持可用。

## 成功指标

交付时同一份用例在两个目标各通过一次；两种打包故障均可由脚本指出失败阶段，测试不依赖 Computer Use。

## 规模检查

- [x] 用户能感受到：减少桌面安装包启动、编辑保存及导出回归。
- [x] 可独立交付，不影响其他需求。
- [x] 共 4 条 AC。
- [x] 一个分支完成，限定单条业务用例与单平台打包冒烟。
- [x] 驱动有官方文档支持；先用试点验证本仓库的构建与运行方式。

## 约束、风险与影响

桌面只做外壳，业务仍走现有 Host；测试驱动、数据和权限与生产隔离。CI 不需要用户项目、Keychain 凭据或付费服务。真实原生窗口及第三方应用的补验规则见[自动化验收方案](../../30-engineering/acceptance-testing.md)。

## 待澄清的问题

无；建议先按 macOS 单平台试点范围确认。

## 结论

建议做。先用一条双端用例证明共享方式可行，同时把桌面包启动和导出变成可复跑的检查。
