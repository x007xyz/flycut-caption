## 验收标准

专用行为AC-1起列出，随后界面生命周期AC同样是验收项，不得用共用状态测试代替专用行为验证。桌面端优先，Web复用Host；平台补测项按其指定平台验收。

- **AC-1**：发版流程支持macOS开发者签名、hardened runtime和公证/装订，验证Tauri、Host、sidecar、FFmpeg、Skia原生模块等随包可执行资源签名与加载。

- **AC-2**：Windows产物采用有效代码签名并验证发布者和时间戳，签名失败或缺必要凭据时发布闸门失败，不把未签包当已签产物。

- **AC-3**：证书/私钥只放受控CI秘密和必要临时钥匙串，日志脱敏、作业后清理；不改成关闭系统安全检查的安装指引，不承诺Windows信誉提示立即消失。

- **AC-4**：在无开发环境的真实Mac/Windows安装测试产物，从选择视频、转写到导出走通；只生成测试/候选包，公开发版必须使用pnpm release并另经授权。

- **AC-5**：**构建前置**：不新增产品内签名页面。CI缺证书/公证凭据时说明缺失项并停止相应正式发布步骤，不输出秘密，也不自动购买证书或创建外部账户。

- **AC-6**：**签名与公证中**：构建日志显示各资源签名、公证提交/等待/结果的脱敏状态；超时保留可查询提交标识，重试先查结果，不能重复公证提交冒充已完成。

- **AC-7**：**成功证据**：产物附平台签名验证输出、macOS公证装订验证和哈希，发布者信息与维护者提供证书一致；生成产物不等于获准对外发版。

- **AC-8**：**失败门禁**：嵌套二进制签名无效、公证拒绝、Windows签名/时间戳失败均阻止正式发行，保留错误证据；临时钥匙串/密钥文件在成功或失败后清理，不关闭系统安全策略绕过。

- **AC-9**：**真实使用**：在真实干净Mac和Windows用候选安装包完成AC-4，记录系统安全提示和完整流程；应用既有导入/识别/导出状态检查明暗主题，不为CI日志增加无意义的界面测试。

## 成功指标

两平台真实安装包验证签名有效、可启动与导出；发布秘密不进仓库和日志。

验收记录输入素材、模型/接口/平台版本、命令和结果；版本复盘按实测记录比较。没有埋点不编造线上转化或留存数字。
