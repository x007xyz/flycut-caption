# F-0005 统一时间映射与编辑决策（EDL）：技术设计

## UI / UX

沿用现有字幕删除、恢复、智能剪空白、播放与导出入口，文案和新状态以已确认 PRD 为准。不增加时间线工具。组件通过每个 ClientRuntime 的 history/project store 读取派生状态，不保存第二份独立剪辑结果。

| 状态 / 入口 | 数据与动作 | 验收构造 |
|---|---|---|
| 删除/恢复、智能剪空白 | 发出编辑命令，原子更新 EDL 和显示投影 | 句级、字词级、无效时间戳、重叠空白 |
| 剪辑后预览、进度与统计 | 读取同一 mapping，播放源媒体时跳过删除区间 | `[2,4)` 删除、接点、片尾、连续切点 |
| 字幕及视频导出 | 启动时捕获不可变导出快照 | 启动后继续编辑、主副/双语和全部格式 |
| updating | 现有操作区显示更新中，禁用重复应用和导出 | 挂起计算；原媒体可查看，剪辑预览冻结 |
| empty | 0 时长、空预览、禁用导出；根据撤销栈显示恢复说明 | 全区间删除、重开全删、只剩无字幕媒体 |
| error | 保留最后有效结果和原数据，显示重试/返回项目 | 非法区间、未知时长、新格式、计算失败 |

新增状态进入本地化文件，明暗主题复用现有变量。保存状态/冲突/离开保护复用 F-0002，不把计算完成显示成保存成功。E2E 用真实编辑命令构造正常状态，用可注入纯计算适配器构造等待和失败，不增加生产调试 RPC。

## 技术方案

### 涉及的子系统

遵守已读 `docs/subsystems/frontend.md`、`docs/subsystems/cordis-host.md`、`docs/architecture-current.md`、`docs/subsystems/funasr-tauri.md`、`docs/decisions.md` 与 ADR-0001/0002。已核对 `segmentUtils.ts`、`videoExportSegments.ts`、`timeUtils.ts`、`asrTranscriptUtils.ts`、`useVideoExport.ts`、`subtitle/exportFormats.ts` 和 Host export 插件。

2026-11-08核对：F-0002、F-0003、F-0004已验收。当前项目格式2；以saveVideoEdits按视频保存，项目共享样式另存，恢复副本版本1。EDL及持久历史作为同一视频快照扩展，并将项目格式升为3，保留旧格式只读迁移与备份。

### 方案

**1. shared 中唯一的纯计算核心**

新增 `shared/editing/edl/`：schema/validate、intervals、mapping、subtitleProjection、exportPlan、legacyMigration。前后端共用，不从 shared 反向依赖 src；已有 smartCutBlankCore 引用 src/timeUtils 的空白计算迁入 shared，前端保留兼容导出，算法与阈值不变。

EDL 只存原媒体坐标上的规范化删除区间，保留区间由 `[0, sourceDuration)` 的补集派生。重叠/真正相邻区间取并集，不使用旧导出 1ms 容差吞掉真实空隙。整数微秒作为计算和持久化单位，媒体秒数在入口显式转换；先检查有限、顺序、范围和已知媒体时长，再转换。微秒舍入后零长也拒绝，不裁剪越界输入。数值须安全整数；格式中声明单位，不隐式混用秒与微秒。

结构计划为 `{ version: 1, sourceDurationUs, deleted: [{startUs,endUs}], origin: 'explicit' | 'legacy-export' }`。origin 仅说明迁移来源，不充当用户操作历史。每视频一个 EDL，源媒体身份及 duration 与项目视频绑定，变更媒体必须检查原时间轴兼容性。

无 EDL 的旧项目只走一次兼容迁移；不能把「缺失」随意解释为全片保留。已迁移且 deleted 为空才明确代表全片保留。原转写和 ID 不变；现有 deleted 标记成为 EDL 的编辑显示投影/兼容字段，消费者不得再据它独立推算导出片段。

**2. 映射与命令原子性**

派生保留段 `{ sourceStartUs, sourceEndUs, outputStartUs, outputEndUs }`，前缀和计算输出位置；顺序定位，接点归下一个保留段，最终终点单独处理。源时间在删除区间则返回下一个保留起点，无后续则返回输出终点。空映射返回明确 empty，不返回原视频第 0 秒假装可播放。

删除命令先依据有效句子/字词选择得到原媒体区间，再与已有删除取并集；选择文本、校对文字不生成剪辑。恢复已删除单元时从 EDL 中减去其原区间（重叠删除的最终效果以显式恢复的区间为准），并更新投影。撤销快照包含 EDL 与用户编辑状态，一次命令一次提交；重复应用得到同一结果不新扣时。旧迁移兼容空白必须能在现有空白/删除内容入口被恢复，不能成为界面中不可操作的隐藏区间。

长计算捕获输入 revision 和 route generation；只提交仍匹配的结果，旧任务完成不得覆盖新编辑。updating 期间不允许应用第二个剪辑；撤销/路由切换取消旧任务。失败保留上一次有效快照，不改正式项目。

**3. 字幕投影与格式精度**

字幕只与保留区间求交并平移；每个交集产生稳定派生 cueId（原句 ID + 保留片段 ID），原 ID/时间不写回源数据。原文有可靠 wordIds/时间戳映射时从仍保留字词重建，保留用户校对对应关系，不能把校对文本直接覆盖回原始 ASR。无法将校对后的文本可靠关联到字词时保持句级剪辑，不能按字符比例猜时间。

跨片段 cue 按交集拆分；副字幕复制该句现有译文到各个剩余 cue，不猜译词。Main/Second/Bilingual 只控制文本模式，不改变映射。所有序列化器和烧录/软字幕先接收同一投影结果，再做已有标点和样式处理；序列化器不再各算删除时长。

字幕精度转换只在最终格式边界进行，始终约束在可表示的成片范围内。极短 cue 在格式量化后若不能表示正时长，不扩展到已删除区间；记录被省略 cue 的诊断并在验收中列出。JSON 保留可用的数值时间精度，ASS 毫秒/厘秒边界测试分别验证，不用逐段累加已舍入时长。

**4. 预览与导出共用计划**

替换 segmentUtils 独立推导、预览进度/跳转中的手工减时，以及 buildVideoExportSegments 从字词拼接的分支；包装函数只适配统一核心输出。原媒体查看使用原坐标，剪辑后预览使用 output 坐标，字幕渲染要选对当前模式，不能在原媒体模式套用输出时间。

导出快照包含 EDL、原媒体身份/时长、映射、派生字幕和样式；所有输出由同一捕获 revision 派生。Host 接收版本化编辑计划，独立校验并通过 shared 核心得到保留段，拒绝同时携带互相矛盾的 segments/EDL。保持旧 export.start 输入可识别，新增计划分支用独立字段版本，不静默改旧参数单位；新客户端统一发送新计划。

Host FFmpeg fast path 必须验证恰为完整源区间；当前 hasCuts 只看段数和起点，会把 `[0,end)` 的尾部裁剪漏掉，迁移时将其作为新路径必须修正的回归点。有裁剪时显式 trim/atrim，所有段用统一时间基拼接；无音轨素材不引用不存在的音频流。切点量化基于整条输出时间轴，不能每段分别补帧/补音频包导致累计漂移。记录输出帧率、采样率、编码器延迟，测 AC-5 容差；不只比较计划时长。

WebAV/FFmpeg 显式本地回退保留时也接收同一快照，删除其重复减时逻辑并真实测试。桌面仍只走 Host，不新增回退。导出过程中继续编辑不影响已启动任务；无保留区间由前后端共同拒绝。

**5. 保存与兼容迁移**

项目 edits 中增加版本化 EDL，项目格式取开发时实际最新版本的下一版，不预占与 F-0003 冲突的编号。保存字幕编辑与 EDL 必须作为一个逻辑快照，采用 F-0002 验收后的可靠写入入口；格式变化写 ADR 和迁移测试，未知更新格式拒绝写入。

旧项目迁移不能只运行新补集算法。建立固定 legacy 适配器复现升级前桌面 Host 实际有效保留结果，包括旧 builder 的间隙/容差、旧 Host fast path 对尾段的实际处理；以升级前真实导出及固定 commit 作为对照。先查明旧预览、导出不一致的样本，兼容以已确认的「原视频导出效果」为准，并在报告说明预览纠正。缺少可信媒体时长或规则不能判定的项目报错，不凭猜测迁移。

将旧有效保留区间补集写为 legacy-export 删除区间，不更改字幕正文和原时间；相同格式只迁移一次。迁移前备份，成功验证后提交版本号；连续重开 3 次区间不变。新编辑从该 EDL 继续，不再次读取 deleted 字段重算隐式空白。

F-0004 已上线时临时恢复副本也必须包含对应 EDL/编辑 revision，并按快照 schema 迁移；F-0003 已上线时按视频保存，不受其他视频或共享样式变化覆盖。这是开发前兼容检查，不能依赖它们尚未验收的提案实现。

### 备选方案与取舍

| 选定 | 备选 | 理由 |
|---|---|---|
| 原媒体删除区间为真源，派生保留段 | 保留/删除各存一份 | 避免互补集合不一致；合法范围内并集可幂等 |
| shared 纯计算 | 仅前端计算后端直接信任 | Host 可验证，CLI/后续建议也可复用 |
| 整数微秒、边界才格式量化 | 全链路毫秒或浮点逐段相加 | 保留亚毫秒空隙，不累计格式舍入误差 |
| 旧实际导出兼容适配器 | 把所有旧项目套新语义 | 满足已确认的升级不改变成片，明确区别迁移与新编辑 |

## 架构决策

[ADR-0005 统一原媒体编辑决策与派生时间映射](../../20-architecture/adr/0005-unified-edit-decisions.md) 已随本需求验收接受。新操作删除规则已由 PRD 确认，设计与存储实现由 04 的测试证据覆盖。

## 自行决定的事项

- 以规范化删除并集存储，保留区间只派生；用整数微秒避免不同调用点重复舍入（AC-1–5）。
- 显式恢复删除项从区间集合减去对应范围；包括旧迁移空白在内均需可从现有编辑入口恢复（AC-6、AC-9）。
- 新导出快照采用版本化输入，Host 验证媒体后重新派生保留区间；旧接口语义不变（AC-5）。
- 兼容迁移以旧实际 Host 输出为准，不能把新 fast path 修复倒推成旧行为（AC-7）。

## 风险与回退

- 音视频帧量化可能导致多接点累计误差；验收前必须实际测量，不能把 PRD 容差自行放宽。
- 旧导出与预览可能矛盾；迁移维护旧成片，报告列明具体样本，不能隐瞒新预览与旧预览的差异。
- F-0003/F-0004 可能先合入；实施前统一项目格式和事务入口，不能开第二套存储或恢复真源。
- 保存升级后旧程序应拒绝写入；不能只回退二进制。迁移备份可人工恢复，但不能覆盖升级后的新编辑。
- 非法字幕/时长不是可容忍的空区间；读取失败必须保留原文件并报告。

## 验证计划

- 每项提交带对应 AC、检查和 Verification。全量执行 `pnpm lint`、`pnpm tsc -b --noEmit`、`pnpm check:host`、`cargo check --manifest-path src-tauri/Cargo.toml`、`pnpm test`、`pnpm test:architecture`、`pnpm build`；相关既有测试包括 `pnpm test:smart-cut`、`pnpm test:sentence-grouping`。若动 Tauri 外壳，追加 `pnpm build:funasr-sidecar` 及桌面子系统要求。
- 区间测试覆盖无删/全删/首尾/相邻/重叠/亚毫秒空隙、接点和最终终点、非法输入不裁剪；性质验证幂等、长度守恒、保留内部双向映射。行为改动做 Red check，证明恢复旧实现后针对行为的断言失败，而不是编译失败。
- 迁移对照固定升级前 commit 和实际 Host 导出，覆盖单段从 0 起但提前结束、容差合并、字词删除、无字幕媒体；逐区间/声画标记比较，重开 3 次不累计。原始文件/转写不可变，迁移中断后重试不损坏项目。
- `tests/e2e/features/F-0005.spec.ts` 按 AC 命名，覆盖新增状态、明暗与中英文，shot 截图；等待/错误可注入，正常删除、撤销与导出走真实状态。`pnpm e2e:evidence F-0005` 生成截图和本地录屏。
- 浏览器及 `pnpm tauri:dev` 各实际操作主流程；两段真实未剪辑口播验证剪辑、主副字幕、保存重开及实际成片。内置与 HTTP Provider 已有转写分别回归，未配置的明确 Not run。
- 另生成带声画标记的固定 CFR 测试素材，探测输出视频帧、音频帧、采样率和编码延迟，测总时长及每个接点，验证 AC-5 误差不累计；对纯字幕解析结果检查 SRT/VTT/JSON/ASS 精度和正时长，不只查字符串。无音轨、静音和字幕为空的边界分别实测。
- 60 分钟项目连续 20 次删除/撤销，以 1 万字幕/字词编辑单元为记录基准，目标普通单次更新不超过 200ms；报告列出硬件、单元数和耗时。若超出，先剖析并优化，不通过显示半更新状态达标。验收绑定固定 commit，未执行项列 Not run。

## AC-11/12补充设计

- 每视频的editing快照包含version 1 EDL与仅剪辑相关的持久历史；历史记录只保存EDL与删除标记，不保存文字/译文/样式。历史回退根据当前原文重新投影，不能覆盖后来的校对。
- 待确认建议保存在history store临时层，包含基准标识、区间、预览开关；不进入自动保存、恢复副本或导出快照。基准变更后确认拒绝并提示重新分析；取消只清建议。
- 复用字幕面板增加操作历史入口，加载、空、错误、预览和确认回退状态按AC-12文案。回退创建新记录，普通undo/redo与持久历史分开。
- 时间轴标出临时删除范围并显示文字标签，播放器能切换临时/已确认EDL；任何导出始终取正式EDL。
- 原格式无EDL时根据旧实际Host导出规则生成legacy-export补集；迁移不伪造用户历史，补上可恢复的兼容区间。新转写默认explicit全片保留。
- 浏览器与Host消费者均用shared核心产生映射及字幕投影。Host新计划独立校验时长/区间，旧export.start参数仍保持旧语义。

| AC | 补充覆盖 |
|---|---|
| AC-11 | 临时建议层、标记、预览、过期检查、确认/取消隔离 |
| AC-12 | Host持久剪辑记录、历史预览、二次确认回退、失败保留当前版本 |

## 实施核对（2026-11-09）

- 纯核心合并在 `shared/editing/edl/index.ts`，而非拆成多个小模块；映射按保留段顺序扫描。1 万编辑单元的本机基准及已执行检查见 03 和 04。
- 同步的纯区间计算一次提交，不引入无必要的异步计算器；updating 用于需要等待 Host 保存的历史回退，建议通过基准内容校验阻止过期应用。
- Host 和 FFmpeg 适配器共享全局视频 filter 生成器，显式 fps 量化后才做输出尾部约束；不能仅以总时长替代逐帧和接点音频验证。
- 实现清单勾选表示代码、测试和文档已经交付。浏览器、真实 WebAV、真实 Host/本地 FFmpeg 和 Tauri 桌面导出闭环均已实测；发布包签名/公证与外部 Provider 仍未执行，具体证据和限制见 04。
