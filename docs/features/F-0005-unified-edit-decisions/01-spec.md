# F-0005 统一时间映射与编辑决策（EDL）：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

## 立项

### 来源

- 已确认的 Epic E-06/1：「统一时间映射与编辑决策（EDL）：保留 / 删除区间，字幕与导出共用；现有删字幕剪视频、智能剪空白迁移到 EDL」。
- 已确认路线图阶段一第 5 项，在崩溃恢复之后。
- 维护者原话（2026-11-05）：「继续下一项 PRD」。按路线图顺序进入本候选，具体范围仍通过本立项确认。

### 要解决的问题

口播创作者删掉字幕对应片段或应用智能剪空白后，希望预览、成片和导出的字幕表达同一个剪辑结果。当前时间映射与导出片段计算分散，后续新增去静音、去口癖时容易对同一段素材重复计算出不同的时间轴；重新打开项目也需要准确保留剪辑结果。

### 目标用户与场景

对照 vision.md：处理 10–60 分钟中文口播的个人创作者。删除口误或空白后预览，再导出视频和中英字幕，在剪辑点附近核对字幕、音画和时长；关闭后重开继续剪辑，结果保持一致。

### 竞品怎么做

资料来源为项目 vision.md 与 E-06 的现有分析（读取日期 2026-11-05）。Descript 是文档中列出的文本剪辑参考；剪映是后续精剪与草稿交换目标。其内部 EDL 数据结构及精确时间边界规则未核实，不作为本需求的实现依据或对外承诺。

本次以自己的已有操作为兼容基线，不照搬第三方内部格式。

### 获客价值

主要是剪辑准确性与信任，支撑内容平台「删文字即剪视频」教程和后续去静音/去口癖效果演示。发布后用户可直接感知预览、视频和字幕保持一致；不单独建设推广渠道。

### 优先级

P1，按文字剪辑底座。统一的结果是 E-06/2 去静音、E-06/3 去口癖规则层及剪映草稿导出的前提，按已确认路线图在持久化底座之后推进。

### 依赖

- F-0002：项目数据保存、重新打开与格式迁移。其测试验收确认前不可开发。
- 不将 F-0003/F-0004 设为硬依赖；单视频即可交付用户价值。开发前应核对它们是否已经上线，以兼容当时的多视频/恢复快照格式，不擅自修改已经确定的共用契约。
- 不依赖 F-0001：本需求不改识别质量；字词级剪切只在已有字词时间戳通过校验时成立。

### 建议范围（待确认）

- 让现有删字幕剪视频和智能剪空白产出同一份相对原媒体的保留/删除区间；字幕、预览跳转与视频导出共用时间映射。
- 明确原时间与剪辑后时间的映射，合并重叠删除区间，防止重复扣时；不移动原始字幕时间戳来伪造新的原始转写。
- 主、副字幕一起映射，导出的字幕与成片对齐；跨剪辑边界的字幕处理和全部内容被删除的状态在 PRD 具体定义。
- 沿用现有操作入口和默认剪辑策略；单纯校对文字或修改译文不能意外改变剪辑区间。撤销/重做同时还原编辑决策与显示结果。
- 保存 EDL 并在重开项目后复现；旧项目迁移后保持原有删除效果，重复打开不再次累计剪掉时长。原媒体不改写。
- 桌面端先交付并真实导出验证；Web 连接同一 Host 验证相同编辑结果和字幕导出。
- 不做新的 VAD 去静音、停顿压缩、切点余量/淡入淡出、去口癖、AI 建议、剪映草稿格式、自由时间线编辑、变速、转场或多视频合并导出；这些各自属于后续需求。

### 规模检查

- [x] 用户能感受到：同一次剪辑在预览、导出视频和字幕中一致，保存重开不改变结果。
- [x] 可以单独发布：现有两种剪辑操作迁移后即可用，不等后续智能剪辑功能。
- [x] 预计 AC 约 10 条以内：围绕删除、空白、映射、字幕、撤销、持久化、迁移与异常状态组织；PRD 再检查。
- [ ] 预计两周左右能完成：跨预览/字幕/导出/持久化，需设计阶段列明调用点和回归成本后评估，不预先承诺。
- [x] 没有待选模型或重大算法不确定性；时间区间和边界行为要在 PRD 确认，数据结构与数值精度在技术设计验证。

### 不做的代价

每个后续剪辑功能都要适配多套时间计算，难以证明预览与导出一致；时间错位和旧项目重复剪辑的风险随功能增加。

### 已知约束与风险

- decisions.md 已规定所有剪辑操作共用一份编辑决策，建议需用户确认后应用，字词级剪切必须使用通过校验的时间戳，不得按字数均分。
- 兼容迁移可能改变项目格式，需 ADR、迁移测试和版本过新拒绝写入规则；不能悄悄改 F-0002/F-0003 的字段含义。
- 音视频帧与字幕毫秒精度不同，PRD 必须定义可测的边界和容差；不能以「共用函数」替代真实成片验证。
- 全删、边界字幕、连续/重叠删除与撤销是重点回归路径；格式失败时不得把项目当作完整保留或空视频直接导出。
- 原始媒体保持不变，复用现有 Host 导出，不引入新的原生业务命令或外部上传。

### 待澄清的问题

无额外产品方向问题。请确认上述最小范围：统一现有剪辑结果与持久化，本次不改变智能剪空白的检测策略，也不加入后续 VAD/去口癖功能。具体切点、字幕跨边界和全删行为在 PRD 中提出供维护者审阅。

### 结论

建议做，按上述范围立项；维护者确认后进入 PRD。当前仅提交立项，不提前创建 PRD 或开始开发。

## 产品需求

### 背景

立项于 2026-11-05 获维护者确认：统一现有删字幕剪视频、智能剪空白的剪辑结果及持久化；新的 VAD 去静音、去口癖和剪映草稿导出留给后续候选。

当前 `segmentUtils.ts` 与 `videoExportSegments.ts` 分别计算时间映射和导出片段。后者无删除时保留全片，有删除时按剩余字幕区间拼接，可能顺带去掉未选中的空白。本 PRD 将新操作的删除语义明确为「只删除用户选择或确认的区间」，并要求旧项目按原导出效果迁移，避免因升级而改变既有剪辑。

### 目标用户与竞品

处理 10–60 分钟中文口播的个人创作者，希望删文字后预览与成片一致，导出的中英字幕跟着剪辑走。竞品定位沿用立项引用的 vision.md；内部 EDL 格式及精确切点规则未核实，不作为实现依据。本次用户价值是可预期的剪辑结果，不增加新的智能分析功能。

### 范围

#### 做

- 每个视频一份相对原媒体时间轴的编辑决策；预览、进度定位、统计、字幕和 Host 导出共用同一剪辑结果。
- 迁移现有句级/字词级删除和智能剪空白；新增操作只删除明确选择或确认的区间，未被删除的片头、片尾、句间空白均保留。
- 保留原始媒体及原始转写时间轴，原文、译文和字词 ID 不因时间映射被重写；只派生剪辑后显示和导出时间。
- 撤销/重做、Host 保存、重开项目与旧项目兼容迁移。
- 桌面先交付，Web 开发模式连接同一 Host 验证相同剪辑与导出结果；字幕文件现有格式继续支持。

#### 不做

- VAD、新的静音检测、停顿压缩、切点余量和淡入淡出；现有智能剪空白算法及阈值保持不变。
- 去口癖、AI 剪辑建议、剪映草稿导出、配音、长转短。
- 多轨、变速、转场、自由拖动剪辑边界、新增手工时间线工具及多视频拼接。
- 推测被删原文对应的译文字词，或自动重译；字词剪辑后的译文需要用户校对。

### 用户故事

- 作为口播创作者，我想只删掉选中的口误，保留没有选择的停顿与片头片尾。
- 我希望预览、成片与导出字幕使用同一时间轴，方便继续精剪和发布。
- 我希望升级与重新打开项目后，之前完成的剪辑不变，撤销也能恢复完整结果。

### 验收标准

除特别注明外，桌面 Tauri + 本机 Host、Web `pnpm dev` + 同一 Host 均成立，与 ASR Provider 无关。字词级操作仅在通过校验的真实字词时间戳存在时成立，不按字数均分时间。新增或变更界面状态须覆盖明暗主题和中英文。

- **AC-1 明确删除与统一统计**：当用户执行句级删除或具备有效时间戳的字词删除时，系统应将选中单元对应原媒体区间标为删除，其余区间保留；重复/重叠删除不重复扣时，相邻删除可合并。例：10 秒视频删 `[2,4)`，保留 `[0,2)` 和 `[4,10)`，成片时长 8 秒；即使第一句在第 1 秒开始，片头也不能被顺带删除。原时长应等于保留时长加删除并集时长；校对文字、修改译文或字幕样式不改变剪辑区间。单纯选中但未执行删除不得改变成片。

- **AC-2 智能剪空白兼容**：当用户通过现有入口应用智能剪空白时，检测方式与阈值不变，现有确认流程得到的空白区间进入同一编辑决策。与已经删除的区间重叠时按并集处理；重复应用同一结果不再缩短视频。未应用的分析不得改变项目或导出。用相同输入比较迁移前后的分析候选区间应相同，不把新增 EDL 当作启用 VAD。

- **AC-3 预览与双向定位**：当用户播放剪辑后预览或在其进度条跳转时，应按保留区间顺序播放并跳过删除区间；显示时长、当前位置与 AC-1 统计一致。切点采用左闭右开区间，剪辑后恰好在接点的时间定位到下一保留片段起点，最终终点定位到最后保留片段末尾。原时间落在删除区间时，应定位到之后最近的保留起点；之后无保留则定位到成片终点。删除完毕无保留内容时进入 AC-9，不播放已删除内容。

- **AC-4 主副字幕映射**：当预览或导出剪辑后字幕时，字幕只在与保留区间相交的时间显示；完全被删的字幕不出现，未删除原文和副字幕共用对应的输出时间段。跨多个保留片段的字幕按交集拆成多个 cue，不跨越已删除内容计时；有效字词时间戳可确定被删文字时，原文显示剩余字词，不能保留已删除的原文字词。没有可靠字词时间戳时不推断句内文字与时间的分配，维持句级剪辑能力。译文保留用户现有文本，在该句剩余的各段显示，整句删除时一起移除；不伪造逐词翻译对齐。所有输出 cue 非负、结束大于开始、不超出成片时长；不同格式只按其精度舍入，源字幕时间不被改写。

- **AC-5 视频与字幕导出一致**：当用户导出剪辑视频和对应 SRT/VTT/JSON/ASS 字幕时，应使用导出启动时同一份不可变剪辑快照，期间继续编辑不改变该次任务。编码前各消费者的目标保留区间/时长一致，字幕按 AC-4 映射；烧录字幕也使用该映射。以带可识别声画标记的 CFR 验收素材实测，输出总时长相对目标的误差不超过 1 个输出视频帧加 1 个输出音频帧；各剪辑接点的声画标记及字幕目标相对输出的偏差不超过对应输出帧量化误差，不随切点数量累计漂移。字幕文件格式自身舍入误差单独列出（毫秒格式最多 1ms，ASS 最多 10ms）。桌面用真实 Host 导出并在播放器核对；Web 的 Host 路径同测，现有显式本地回退路径若保留，也必须消费同一快照并单列实测结果，不能悄悄换计算规则。

- **AC-6 撤销与重做**：当用户撤销/重做一次删除或智能剪空白应用时，字幕删除显示、EDL、保留时长和预览定位应作为一次编辑共同恢复；不能只恢复文字而留下剪辑。撤销后在曾被删除的片段中播放，应能听到并看到原内容。剪辑操作历史随项目持久化，重开后仍可选择已确认历史版本回退；回退前展示目标时间和剪辑变化并二次确认，回退提交为新的历史记录，不擦除原历史。历史包含完整剪辑决策及恢复必要的删除显示信息，不等于持久化播放器位置、输入法状态或所有文字校对撤销栈。并发冲突、缺失源媒体或历史损坏时应保留现状态并明确失败，不假装回退成功。

- **AC-7 保存重开与迁移**：当剪辑保存到 Host 后重启并打开项目，系统应复现相同的保留区间、预览、字幕映射和导出结果；重复保存/打开不重复应用删除。旧项目迁移以升级前实际视频导出保留区间为兼容基线，包括旧规则隐式删除的空白，不能只复制 deleted 标记后按新规则重新推算。迁移前后以测试素材逐区间对比，并保留原始转写及用户修改；旧行为的删除来源不可确定时可标记兼容区间，不捏造用户操作历史。后续新删除从迁移后的 EDL 继续操作。格式升级须可迁移，更新格式被旧程序打开时拒绝写入。

- **AC-8 计算和保存状态**：当剪辑正在计算/应用时，现有操作区域显示「正在更新剪辑… / Updating cuts…」，禁用重复应用和启动导出；原始媒体仍可查看，但剪辑后预览不得播放半更新状态。计算成功后一次性更新剪辑与显示，恢复操作；保存状态沿用 F-0002，保存失败不会显示已保存，离开保护继续生效。计算失败时沿用 AC-10 的错误处理，不丢弃最后一次有效结果。

- **AC-9 无保留内容**：当所有媒体区间均被删除，剪辑后时长显示 0，预览显示「没有可播放的内容 / No content to play」及「撤销上次操作可恢复内容。 / Undo the last action to restore content.」；预览播放和视频/字幕导出按钮不可用，编辑区仍允许恢复删除项，现有撤销/重做是否可用按真实历史显示。若当前撤销栈为空，提供「操作历史 / Edit history」入口选择持久化剪辑版本，或说明「请在编辑区恢复已删除的内容。 / Restore deleted content in the editor.」。删除全部字幕但仍有未删除的无字幕媒体区间时不算全删，仍允许导出剩余媒体；没有任何字幕时字幕导出不可用并提示「没有可导出的字幕 / No subtitles to export」。不生成空视频或非法时间戳文件。

- **AC-10 非法剪辑数据与失败**：当读取或应用的数据包含非有限时间、倒置/零长区间、超出源媒体范围、无法识别的版本或媒体时长未知时，系统应保留项目原数据，不静默裁掉越界部分或当作全片导出。显示「无法更新剪辑 / Couldn't update cuts」和「剪辑数据或媒体时长无效，原项目未被此操作覆盖。 / The cut data or media duration is invalid. This operation hasn't overwritten the original project.」，提供「重试 / Retry」「返回项目 / Back to projects」。有上一次有效内存结果时可查看，错误解决前禁用导出；无有效结果则不进入可编辑剪辑预览。对于响应丢失导致保存结果不确定的情况，沿用 F-0002 的结果核验与失败提示，不错误宣称未保存或重复提交。

### 成功指标

- 两段真实未剪辑口播分别完成句级/有效字词级删除及智能剪空白，预览与导出在可辨识切点一致；素材来源沿用现有测试资产，不新增许可不明素材。
- 带声画时间标记的固定验收素材覆盖片头/片尾、单次删除、连续删除、重叠删除、多接点与全删，满足 AC-5 的帧级容差并记录实际输出参数和测量值。
- 旧项目样本升级前后逐区间一致，连续重开 3 次不出现二次扣时或字幕累计漂移。
- 使用 60 分钟字幕项目连续执行 20 次删除/撤销，记录更新耗时；性能目标与具体输入规模在设计中给出，不能通过异步显示不一致结果换取速度。

### 拆分检查

修订后共 12 条 AC，围绕「现有操作产生统一剪辑结果，并在全部消费者一致使用」这一可独立发布闭环；不引入新的分析器或时间线工具。跨子系统改动较多，设计必须清点消费者和旧格式迁移路径，再判断能否约两周一次完成；若需多次发布，开发前回 Epic 拆分，不留下部分消费者继续使用旧时间映射的混合状态。

### 依赖与影响

### 2026-11-05 范围修订：待确认预览与剪辑历史

维护者要求“先标记后删除”及“操作历史记录可以随时回退”。新增以下 AC，整份 PRD 退回 review，原技术设计暂停；本轮范围以此为准，具体新增交互待批量 PRD 审阅。

- **AC-11 待确认建议预览**：VAD、规则及语义建议先进入临时建议层，时间轴待删除区间标红，并有「待确认删除 / Pending deletion」文字/图标；不能只靠颜色区分。提供「预览剪辑效果 / Preview proposed cuts」和「当前已确认版本 / Current confirmed cuts」，前者用临时 EDL 试听/播放，后者回到正式已确认结果；明确显示「预览，尚未应用 / Preview, not applied」。逐条/批量确认前，正式 EDL、字幕删除标记、项目历史和导出不变，禁止把临时预览冒充正式成片。确认时重新校验编辑基准，版本不符标「建议已过期，请重新分析 / Suggestions are outdated. Analyze again.」。取消/拒绝仅移除建议；确认成功原子提交剪辑与历史，失败保留原剪辑及待确认建议并允许重试。

- **AC-12 持久化历史界面**：确认剪辑、直接手工删除/恢复和历史回退都写入同一项目的视频剪辑历史，包含操作类型、时间和变化摘要。界面显示「操作历史 / Edit history」，每行有「预览 / Preview」和「回退到此版本 / Restore this version」。预览历史不修改项目；回退前显示「回退剪辑？ / Restore these cuts?」及「当前剪辑将被所选版本替换，回退操作也会记录到历史中。 / The selected version will replace the current cuts. This restore will also be recorded.」，确认/取消明确。加载中显示「正在读取操作历史… / Loading edit history…」，空状态「暂无剪辑记录 / No cut history yet」，失败显示「无法读取操作历史 / Couldn't load edit history」与重试；回退中禁用重复操作，失败显示「回退失败，当前剪辑未改变 / Couldn't restore. Current cuts are unchanged」并保留可读历史。保存结果不确定时先核验，不错误宣称未写入。

原拆分检查的10条更新为12条（仍属于同一剪辑决策闭环），设计需重新评估持久化历史的存储及规模；不将所有功能的撤销栈持久化混入本次。F-0004 明确不保护撤销栈的边界保持，该处指崩溃恢复副本，不妨碍本需求在 Host 保存已确认剪辑历史。
