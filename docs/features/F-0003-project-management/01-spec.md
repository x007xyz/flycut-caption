# F-0003 项目管理：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）和产品文档（02-prd）合并而成，内容未改；两者都已由维护者确认。

## 立项

### 来源

- Epic 候选 **E-02/6**（[E-02 项目与字幕编辑](../../10-product/epics/E-02-subtitle-editing.md)，2026-11-05 确认）：「项目管理：项目列表，新建 / 重命名 / 删除项目，项目内添加 / 切换 / 移除多个视频，项目级共享设置」。
- 维护者原话（2026-11-05）：「按顺序来」，并选择按路线图顺序。路线图阶段一第 3 项（[roadmap.md](../../10-product/roadmap.md)）。
- 维护者 2026-11-04 的要求（E-02 讨论时）：「一个项目里面应该有多个视频，方案类似于 opusclip web端和 桌面端 都通过和后端交互把数据保存下来」。
- F-0002 的 PRD 把这些操作明确列为「不做，留给 E-02/6」；交互原型（[F-0002 ux.md](../F-0002-project-persistence/ux.md)）已画出卡片菜单、重命名、删除、排序和项目详情页，展示组件已在 `src/components/Project/` 里，但没有接数据。

### 要解决的问题

F-0002 做完后，项目能保存和重新打开，但只能「拖入一个视频 = 一个项目」，并且项目建好之后什么都改不了：

- **一个系列的几段视频没法放在一起。** 口播创作者一期内容常分几段录（开场、正文、补录），现在每段各成一个项目，首页上分散排列，找起来靠记名字。
- **项目名改不了。** 默认名是文件名（例如 `IMG_4821`），首页上一排看不出是哪一期。
- **项目删不掉。** 试做的、转写失败的项目会一直留在首页，Host 上占的空间也不会释放。
- **只能按修改时间看。** 项目多了以后找不到旧项目，只能靠搜索。
- **同一系列的设置要每段重新调。** 字幕样式在每个视频上单独保存，同一期的几段要各调一遍，容易不一致。后面的口癖词表（E-06/3）、术语表（E-04/3）、样式预设（E-03/5）也都需要「项目级」这一层才有地方放。

### 目标用户与场景

- **口播创作者**（[vision.md](../../10-product/vision.md)）：做系列内容、一期分几段录的人；一周产出几条视频、首页项目逐渐多起来的人。
- 典型场景：录完一期的 3 段口播，拖进同一个项目，逐段转写校对，字幕样式只调一次；做完后给项目改名「第 12 期 · 剪辑工作流」，删掉之前试做的空项目。

### 竞品怎么做

资料为产品公开说明和使用印象，具体行为待核实（2026-11-05）：

- **OpusClip**：网页端按项目组织，一次上传对应一个项目，项目下是生成的多个短片；有项目列表和删除。是否支持一个项目放多个源视频：待核实。
- **Descript**：一个项目（Project）里可以有多个 Composition 和多段素材，项目放在工作区（Drive）的文件夹里，可重命名、移动、删除。
- **剪映**：一个草稿就是一个时间线，可以导入多段素材拼在一起；草稿列表支持重命名、删除、复制。没有「项目下多个独立成片」这一层。
- **我们的不同**：项目下的每个视频各自转写、各自导出，适合「一期多段」的口播；项目级共享字幕样式，后续再共享口癖词表和术语表；桌面端和 Web 端是同一套 Host 接口。

### 获客价值

间接，主要是留存：项目多了以后还好管理，用户才会长期用。对应 vision.md 的留存指标。项目级共享的样式、词表，以后可以在内容平台教程里作为「系列内容怎么批量做字幕」来介绍。

### 优先级

P0（[decisions.md](../../decisions.md#产品定位与优先级)：转写 + 添加字幕的底座）。现在做，是因为路线图阶段一排在 F-0002 之后，而且 E-02/8（导入导出）、E-03/5（样式预设）、E-04/3（术语表）、E-06/3 的项目级词表都依赖它。

### 依赖

- **F-0002**（项目数据保存到 Host）：本需求在 F-0002 定下的数据模型、`projects` 插件和 RPC 上扩展（[F-0002 02-design.md](../F-0002-project-persistence/02-design.md) 实现清单第 1 项写明「E-02/6 只能在此基础上扩展」）。
- 按依赖门禁，F-0002 的测试报告确认之前，本需求可以写立项、PRD 和设计，不能进入开发。

### 规模检查

- [x] 用户能感受到：重命名、删除、一个项目放多段视频都是直接可见的操作
- [x] 可以单独发布：不需要等其他需求
- [ ] 预计验收标准不超过 10 条左右：**有风险**。行为上至少有重命名、删除（含 Host 上的媒体和文件）、排序、添加视频、切换视频、移除视频、项目详情页、项目级共享样式、多视频下的冲突检测，已经接近 10 条；界面状态（加载、空、出错、确认框）另算
- [ ] 预计两周左右能做完：**有风险**。项目管理操作和多视频是两块：前者主要是 RPC + 已有的展示组件；后者要改编辑器「当前视频」的上下文、自动保存的粒度、导出和媒体链接都按视频走
- [x] 没有重大技术不确定性：数据模型在 F-0002 已支持多视频；冲突检测是项目级还是视频级，F-0002 设计里已经留了口子（误报多再细化到视频级），在设计阶段定

两项有风险，问题 3、4 的回答（回收站、新建空项目）又加大了范围。维护者 2026-11-05 决定不拆、整体做（见待澄清问题 1）；PRD 阶段按「用户能完成的一步」组织验收标准，开发时按设计的实现清单分段提交，先做项目管理操作，再做多视频。

### 不做的代价

项目只能越积越多、改不了名、删不掉；一期多段的内容只能拆成多个项目；样式预设、术语表、项目级口癖词表都没有落脚的地方，E-02/8、E-03/5、E-04/3 无法开始。

### 已知约束与风险

- **已拍板的决定**（[decisions.md](../../decisions.md#项目与数据)）：一个项目多个视频，可以添加、切换、移除；字幕样式、口癖词表、术语表等可以项目级共享；只有用户删除视频或项目时才删除媒体；并发修改用版本号检测、不静默覆盖。本需求要落实其中「添加、切换、移除」和「项目级共享」两条，以及「删除时才删除媒体」。
- **删除不可撤销**：删除项目或移除视频会删掉 Host 上的项目数据和复制进来的媒体。按 F-0002 的 ADR-0002，桌面端只记录原文件位置，删除时**不能**删用户的原文件；对话框要说清楚这一点（原型里已有「原始文件不受影响」）。
- **共用契约**：要扩展 `shared/projects.ts` 和 `RpcMethods`，不能改 F-0002 已有字段的含义；数据格式有变化时按 F-0002 的格式版本和迁移机制走，并写 ADR。
- **编辑器的「当前视频」**：现在编辑器的 stores（`historyStore` 等）只装一个视频，切换视频时要先保存当前视频，再载入下一个；离开保护沿用 F-0002 的规则。
- **平台**：桌面端先发；Web 端用开发模式连本机 Host 验证同一套接口，和 F-0002 一样。
- **隐私**：数据仍在用户本机的 Host 目录，没有新增上传。

## 产品需求

### 背景

F-0002 让项目能保存到 Host、关闭后重新打开，但只能「拖入一个视频 = 一个项目」，项目建好后不能改名、不能删除，也不能再往里放视频。立项结论（[01-spec.md](01-spec.md)，2026-11-05 确认）：按 Epic E-02/6 原文整体做，不拆分。范围包括：项目管理操作（重命名、删除进回收站、恢复、排序、新建空项目），以及一个项目放多个视频（项目详情页，添加、切换、移除视频，项目级共享字幕样式）。回收站保留 30 天；移除单个视频不进回收站；画幅仍按视频保存。

### 目标用户与竞品

- **口播创作者**：做系列内容、一期分几段录的人；一周产出几条、首页项目越来越多的人。
- **竞品**（资料为公开说明和使用印象，待核实，见立项文档）：Descript 的项目可以放多段素材，项目可以重命名、移动、删除；剪映的草稿可以重命名、删除、复制，但没有「一个项目下多个独立成片」这一层；OpusClip 按项目组织，是否支持一个项目放多个源视频待核实。
- **我们的不同**：项目下每个视频各自转写、各自导出，适合「一期多段」；字幕样式在项目级共享；桌面端和 Web 端用同一套 Host 接口。

### 范围

#### 做

- **新建空项目**：首页新建区增加「新建空项目」，建好后进入项目详情页再添加视频。拖入视频自动建项目的方式保持不变。
- **重命名项目**：在首页卡片菜单、列表视图和项目详情页里修改项目名称。
- **回收站**：删除项目时先移到回收站；回收站里可以恢复、彻底删除、清空；保留 30 天，到期由 Host 自动彻底删除。彻底删除时删掉 Host 上的项目数据和复制进 Host 的媒体，**用户的原始文件始终不删**。
- **排序**：首页按最近修改、创建时间、名称排序，和搜索、网格 / 列表视图一起使用，重新打开应用后保持。
- **项目详情页**：列出项目里的全部视频（缩略图、名称、时长、转写状态、媒体是否丢失），可以添加视频、打开某个视频编辑、移除视频。
- **添加、切换、移除视频**：往已有项目里添加视频；在编辑器里切换到同一项目的另一个视频；从项目里移除视频（确认后直接删除，不进回收站）。
- **项目级共享字幕样式**：主、副字幕样式存在项目级，项目里的视频默认跟随；单个视频可以改成单独设置，也可以恢复跟随项目。
- **多视频下的并发修改**：两个窗口改同一项目的不同视频时都能保存；改同一个视频时沿用 F-0002 的冲突处理；项目在别处被移到回收站时提示用户。
- **数据格式升级**：F-0002 保存的项目（格式版本 1）升级后能打开且不丢内容，按 F-0002 的格式版本与迁移机制，并写 ADR。

#### 不做

- 项目文件夹、标签、收藏、置顶。
- 在项目之间移动或复制视频；调整项目内视频的顺序（按添加时间排列）。
- 复制项目（F-0002 冲突对话框里的「另存为新项目」保持不变，不在菜单里新增「复制」）。
- 批量操作：多选删除、多选导出、批量转写。
- 后台转写：一个视频转写时切换到另一个视频继续工作。本需求里转写进行中不能切换或移除这个视频（见 AC-30）。
- 项目级共享口癖词表、术语表、样式预设，分别由 E-06/3、E-04/3、E-03/5 加进来；本需求只做共享字幕样式这一项。
- 画幅放到项目级：仍按视频保存。
- 合并导出：把项目里的多个视频拼成一个成片导出。导出仍是一次一个视频。
- 崩溃恢复（E-02/7）、项目导入导出（E-02/8）。
- Web 端连接 FlyCut Cloud（E-08/6）：和 F-0002 一样，Web 端用开发模式连接本机 Host 验证。

### 用户故事

- 作为做系列内容的口播创作者，我想要把一期的几段视频放进同一个项目，以便在一个地方逐段转写、校对和导出。
- 作为口播创作者，我想要同一个项目里的视频共用一套字幕样式，以便同一期的几段字幕看起来一致，不用每段重调。
- 作为口播创作者，我想要给项目改一个看得懂的名字，以便在首页一眼找到「第 12 期」。
- 作为口播创作者，我想要删掉不要的项目，误删了还能找回来，以便放心清理首页。
- 作为口播创作者，我想要先建一个空项目再往里加视频，以便提前把一期内容的框架搭好。

### 验收标准

除特别注明外，在桌面端（Tauri，本机 Host）下成立，与 ASR Provider 无关。F-0002 的 AC-1 到 AC-27 在本需求完成后仍然成立（回归），下面不重复。

#### 行为

- **AC-1 新建空项目**：当用户在首页点击「新建空项目」时，系统应在 Host 上创建一个不含视频的项目，名称为「未命名项目 / Untitled project」（允许重名），并进入该项目的详情页（AC-26 的空状态）。
- **AC-2 重命名**：当用户在首页卡片菜单、列表视图的行菜单或项目详情页修改项目名称并保存时，系统应把新名称（去掉首尾空格，1–200 个字符）保存到 Host；首页、详情页、编辑器顶栏都显示新名称，重新打开应用后保持。重命名不改变项目的最后修改时间以外的内容。
- **AC-3 移到回收站**：当用户删除一个项目并确认时，系统应把它从「我的项目」移到「回收站」，项目的字幕、剪辑结果和媒体都保留；首页的项目数量随之减少。
- **AC-4 恢复**：当用户在回收站里恢复一个项目时，系统应把它放回「我的项目」，打开后字幕、剪辑结果、样式和视频与删除前一致。
- **AC-5 彻底删除**：当用户在回收站里彻底删除一个项目、清空回收站，或项目在回收站里超过 30 天时，系统应删除 Host 上该项目的数据和复制进 Host 的媒体；**用户的原始文件（桌面端按 ADR-0002 只记录位置的文件）不被删除或修改**。到期删除在 Host 运行时进行，验收时把保留期限调小来模拟。
- **AC-6 排序**：当用户在首页选择「最近修改 / Last modified」「创建时间 / Date created」「名称 / Name」时，项目应按所选方式排列（前两种从新到旧，名称按当前界面语言的字母顺序），与搜索结果同时生效；所选排序在重新打开应用后保持。
- **AC-7 打开项目**：当用户在首页点击一个只有一个视频的项目时，应和 F-0002 一样直接进入编辑器；点击一个有多个视频或没有视频的项目时，应进入项目详情页。
- **AC-8 添加视频**：当用户在项目详情页添加一个视频（选择文件或拖入）时，系统应把视频加入该项目，状态为「未转写 / Not transcribed」，创建过程不通过 RPC 传入本地文件路径（与 F-0002 AC-1 相同）；可以一次选择或拖入多个文件，每个文件成为一个视频。
- **AC-9 打开视频**：当用户在项目详情页打开某个视频时，应进入编辑器并载入该视频最后一次保存的字幕、删除标记、译文和画幅，以及它的字幕样式（跟随项目或单独设置），不重新转写；未转写的视频进入编辑器后照现有流程转写，转写结果保存到这个视频。
- **AC-10 切换视频**：在编辑器里，当用户从顶栏切换到同一项目的另一个视频时，系统应先保存当前视频（有未写入的修改时按 F-0002 AC-4、AC-24 处理），再载入目标视频，效果与 AC-9 相同；撤销历史随视频切换清空。
- **AC-11 移除视频**：当用户从项目里移除一个视频并确认时，系统应直接删除这个视频在 Host 上的字幕、剪辑结果和复制进 Host 的媒体，不进回收站，原始文件不受影响；移除最后一个视频后项目保留为空项目。正在编辑器里打开的视频被移除后，回到项目详情页。
- **AC-12 共享字幕样式**：在一个项目里，当用户在某个跟随项目的视频上修改主 / 副字幕样式时，系统应把修改保存为项目样式，同一项目里其他跟随项目的视频打开后显示同样的样式；新加入的视频默认跟随项目样式。F-0002 保存的单视频项目升级后，原视频的样式成为项目样式，视频保持跟随。
- **AC-13 单独设置样式**：当用户把某个视频改成「单独设置 / Custom for this video」后，修改它的样式不影响项目样式和其他视频；选择「恢复跟随项目 / Follow project style」后，它改用当前的项目样式，单独设置的样式被丢弃（先弹确认）。画幅不受这两种设置影响，始终按视频保存。
- **AC-14 多窗口编辑不同视频**：当同一项目在两个窗口中打开、分别修改不同的视频时，两边的修改都应保存成功，不提示冲突，任一窗口重新打开都能看到两边的修改。两个窗口改同一个视频时，按 F-0002 AC-9 检测冲突。两个窗口改同一份项目样式时，也按 F-0002 AC-9 提示冲突，不静默覆盖。
- **AC-15 项目在别处被删除**：当编辑器里打开的项目在另一个窗口被移到回收站或彻底删除时，系统应在下一次保存时暂停自动保存并显示 AC-32 的提示，不把修改写进回收站里的项目，也不重新创建项目。
- **AC-16 数据格式升级**：当读到 F-0002 保存的项目（格式版本 1）时，系统应迁移后打开，字幕、剪辑结果、样式、画幅和媒体都不丢失；迁移后 F-0002 的旧版本程序打开它时，按 F-0002 AC-8 提示版本过新并且不修改文件。
- **AC-17 Web 端**：在 Web 端（开发模式，`pnpm dev` 连接本机 Host）下，AC-1 到 AC-13 应同样成立，使用与桌面端相同的 RPC 和数据格式；桌面端创建的多视频项目在连接同一 Host 的 Web 端能打开、切换视频。
