# F-0055 崩溃收集与匿名统计调研：需求说明

## 来源

- 已确认的 [E-08/5](../../10-product/epics/E-08-platform.md) 候选；本需求仅细化候选，不代表相关功能已完成。
- 维护者原话（2026-11-06）：「那先进入 需求的立项确认，先把所以 需求都立项确认」。本轮先完成所有剩余候选的可审阅需求说明，未将此指令当作尚未写成内容的预先批准。

## 要解决的问题

维护者缺少崩溃和使用情况数据，但不清楚是否值得增加收集及怎样避免上传用户内容。

目标用户沿用 [VISION](../../10-product/vision.md)：以10–60分钟中文/中英混排口播的个人创作者为先，访谈与Agent场景仅按本候选明确范围支持。

## 竞品与获客

来源为项目 [VISION](../../10-product/vision.md) 与所属Epic（读取日期2026-11-06），只用作问题与渠道背景。本需求的竞品具体版本、效果、价格和限制本轮未外部核实，均为待核实，不作为验收依据。获客沿用创作者教程、开源社区与Agent生态；仅在真实验收后展示本需求闭环，研究不宣传为现有功能。

## 优先级与依赖

- 优先级：持续支撑，随依赖需求排期。全量立项不改变 [ROADMAP](../../10-product/roadmap.md) 的阶段顺序和未排期项。
- 硬依赖：无脚本需求依赖。前置需求验收/调研报告已确认后才能进入受门禁阶段；可以提前审阅本说明。
- 前置研究决定模型、服务、质量门槛或支持矩阵时，以其经维护者确认的结论为准；结论改变本需求范围/AC须回到需求评审，不能借设计阶段自行扩大。
- 真实模型、授权素材、API凭据、目标平台、证书或Cloud环境按本需求专用标准准备。缺少外部条件须报告阻塞，不以文档已批准代替验证。

## 范围

### 做

崩溃收集与匿名使用统计：是否做、收集什么、如何征得同意。

具体可观察行为以以下研究问题为界；复用现有Host、Provider、项目数据和统一时间映射。

### 不做

不建设Cloud服务端、多人账号与计费，不公开发布或代办证书采购；不借平台需求改变业务确认门禁。

## 用户故事

作为使用FlyCut的口播创作者，我希望先得到有证据的选型与适用边界，以便解决上述场景中的重复劳动与不确定性，并保留对素材和正式修改的控制。

## 要回答的问题

调研只交付报告、原始证据与必要ADR，不实现生产功能。研究引用的一手资料须注明URL、访问日期、版本与许可；不能访问的资料明确待核实。

- **Q-1**：需要回答哪些可行动的问题（激活、导出失败、崩溃）？不收集数据/本地导出诊断/自愿远程上传三种方案的收益和成本是什么？

- **Q-2**：拟收集字段是否可能包含字幕、媒体、文件路径、API Key、token或可关联身份，逐字段最小化、脱敏和保留期限如何制定？

- **Q-3**：哪些开源或托管方案可用，许可、部署、费用、地区和数据控制条件如何？研究时查一手资料并注明日期，不预先接入SDK。

- **Q-4**：首次同意、拒绝、撤回、查看/导出/删除数据与离线时的行为怎么设计；不接受统计是否完整保留核心功能？

- **Q-5**：给出做/不做建议和显式同意文案草案，任何实施都另立需求确认；研究本身使用脱敏模拟事件，不自动采集真实用户数据。

## 成功指标

得到字段级数据清单、数据流、退出/删除路径与明确做/不做建议，不产生真实遥测上传。

报告说明结论可信度、未测平台/场景和何时需要重评；由维护者确认后才算完成。
