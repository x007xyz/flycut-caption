# F-0044 精彩片段评分调研：调研报告

> 调研日期：2026-11-09。检索方式：Exa 网页检索、arXiv / NeurIPS / CVPR 页面、GitHub 仓库元数据与源码、Hugging Face 数据集元数据。检索不是穷尽的；没有写成“已核实”的内容按待核实处理。
>
> 结论先行：用“句子 ID + 分维度评分 + 可核对的理由”做 30–90 秒中文口播候选，在工程上可行；但本轮没有找到可直接复用的中文口播评测集，也没有运行任何模型或评分实验。建议 F-0045 只做有条件试点：先建独立许可的评测集，再决定是否产品化。评分只表示推荐顺序，不表示传播效果或爆款概率。

## 1. 要回答的问题

1. **Q-1**：30–90 秒中文口播候选如何按话题、句子边界生成，评分如何解释开头吸引力、完整性、上下文独立性和信息密度？
2. **Q-2**：建立许可可用的原始长视频与人工标注切片参考集，记录标注分歧，避免用同一素材调参又评测；前 k 条命中率、边界完整率与重复率如何计算？
3. **Q-3**：比较几种可用已配置文本模型的质量、成本、长视频分批与时间映射，模型必须返回存在的句子 ID，非法范围如何拒绝？
4. **Q-4**：推荐理由是否与片段原文一致，是否出现断章取义或伪造观点；长录制与已剪辑素材分别有什么局限？
5. **Q-5**：给出可验收的推荐阈值、失败与低置信策略，以及是否值得实施的结论，不承诺评分等于真实传播或爆款概率。

## 2. 评估标准

| 维度 | 要看什么 | 本调研的处理 |
|---|---|---|

从这些材料能得到的稳定结论是：

- “精彩”不是单一客观量。事件、情绪、观点、叙事完整性和个人偏好会给出不同答案（TRINITY、Mr. HiSum、PHD-GIFs 都从不同角度支持这一点）。
- 长视频上可行的做法不是逐帧分类，而是先切成语义段落，再在段落/句子层面打分（SVHighlights 的 TF-SELECTOR 是最直接的证据）。
- 公开基准大多是非商用许可，且以英文、体育、影视或短视频为主；**没有找到一个可直接用于中文 30–90 秒口播的、许可可商用的公开基准**。这一点是“未找到”，不是“已证明不存在”。

## 4. Q-1：候选生成与评分设计

### 4.1 输入与句子 ID

候选生成只依赖现有的句级字幕数据：每条 SubtitleChunk 有文本、开始/结束时间，可选字词时间戳。给每条句子分配稳定 ID，例如 s_0001、s_0002，按时间排序，不改写原文。

- 模型只看到句子 ID、文本、可选说话人和相对位置；**不让模型输出秒数**。
- Host 在模型返回后用句子表把 ID 映射回时间；时间映射失败就拒绝该候选，不让模型“猜一个时间”。
- ASR 没有标点时，先按停顿（例如大于 0.6 秒）和连接词补句界，标为低置信；没有可靠句界时不开放自动候选，只显示“转写质量不足”。
- 字词时间戳只用于切点微调，不用于把一句话切成半句。没有通过校验的字词时间戳时，退回句级切点。

### 4.2 话题分段

目标是把长转写切成“一个话题讲完”的段落，分段边界必须落在句子边界上。可用两条路线，按成本和可解释性选择：

1. **嵌入路线**：对句子做多语言句向量，计算相邻句子相似度，在相似度低谷切分；再按最小段落长度合并过短段落。优点是本地、便宜、稳定；缺点是对隐含转折不敏感。
2. **LLM 路线**：把带 ID 的句子列表给模型，要求只返回段落起止 ID 和一句话题名；模型不返回时间。优点是能识别“下面讲第二个问题”这类话语标记；缺点是有成本，且需要校验 ID。

无论哪条路线，都保留一个全局话题表（topic map），后续局部打分时把话题名和相邻段落摘要作为上下文。话题短于 30 秒时与相邻话题合并；话题长于 90 秒时在子话题边界再切；找不到子话题就用句子窗口切，不硬造话题。

### 4.3 候选窗口

候选窗口由句子区间组成，满足以下硬约束：

- 时长 30–90 秒；以句子开始时间为起点、句子结束时间为终点。
- 至少 2 句，最多约 12–14 句；有效语音覆盖率不低于 80%（扣除长静音）。
- 只支持单说话人口播；检测到多说话人重叠时标记“超出范围”，不强行评分。
- 优先从一个话题的第一句开始、在话题最后一句结束；话题不足 30 秒就合并，超过 90 秒就在子话题边界切。
- 不跨广告、片头、口播招呼、订阅引导；这些段落先由规则剔除，再进入候选。

窗口枚举可以用“每个句子作为起点，向后扩展到 90 秒”的方式，得到所有合法区间；再按下面的规则去重和限流：

- 时间 IoU 大于 0.5，或文本嵌入余弦大于 0.90，视为重复；保留分数更高的。
- 每个话题先最多保留 1 条；需要更多时用 MMR（最大边际相关性）在话题间做多样性选择。
- 默认输出前 10 条；不足 10 条就返回实际数量，不用低质量片段补齐。

### 4.4 评分维度与 rubric

四个维度各 0–5 分，分数是“这段素材在该维度上的可编辑性”，不是“爆款概率”。每个维度都必须给出证据句子 ID；没有证据就降置信或返回“上下文不足”。

| 维度 | 要回答的问题 | 0–5 分锚点（从低到高） | 证据要求 |
|---|---|---|---|
| **开头吸引力 hook** | 前 1–2 句能不能让陌生观众愿意继续看？ | 0 纯招呼/寒暄；1 平铺话题；2 有问题、反差或明确收益；3 具体利害/数字/冲突；4 强观点或悬念且马上给信息；5 开头就给出可感知的 payoff，不需要等很久 | 引用第 1–2 句；说明是问题、反差、数字、故事开场还是强观点；不能只写“很吸引人” |
| **完整性 completeness** | 这段有没有把一件事讲完？ | 0 半句/半词；1 只有 setup；2 有观点但没有收束；3 有完整句子和结论；4 有小结构（setup → 展开 → 收束）；5 有 setup → 冲突/例子 → payoff 的完整小弧线 | 引用最后 1–2 句；检查结尾是否停在“然后/但是/所以/这个”等悬空连接词上 |
| **上下文独立性 context independence** | 不看前文能不能听懂？ | 0 必须看前文；1 关键代词/人名/事件未解释；2 部分依赖前文；3 大致能懂但有一个未解释指代；4 自足，必要的背景在片段内；5 完全自足，且不显得像补课 | 引用首次出现的人名/概念/指代；列出“未解释指代”风险 |
| **信息密度 information density** | 单位时间有没有新信息，而不是 filler？ | 0 几乎全是语气词/重复；1 信息稀疏；2 有一些信息但推进慢；3 正常口播密度；4 信息密度高且能跟上；5 高密度但有例子/停顿帮助理解 | 统计主张、例子、数字、步骤；标出口癖、重复、空转；不能只看字数 |

初始权重建议为 hook 30%、completeness 25%、context independence 25%、information density 20%。这是产品假设，不是论文结论；权重只能在 dev 集上调，测试集冻结后不能改。总分只用于排序，界面必须同时显示四个分项和理由，避免一个不可解释的 0–100 分。

### 4.5 可解释性与输出 schema

模型输出必须是严格 JSON；示意结构如下（字段名可在设计阶段调整，但“只用句子 ID”不变）：

    {
      "candidates": [
        {
          "start_sentence_id": "s_0012",
          "end_sentence_id": "s_0018",
          "scores": {
            "hook": 4,
            "completeness": 3,
            "context_independence": 4,
            "information_density": 3
          },
          "confidence": 0.72,
          "evidence": [
            {
              "sentence_id": "s_0012",
              "quote": "原文字句，必须逐字来自转写",
              "supports": "hook"
            }
          ],
          "rationale": "为什么选这段、为什么不是更高分；只能陈述转写里的事实",
          "risk_flags": ["unresolved_reference"]
        }
      ]
    }

约束：

- start/end 必须是存在的句子 ID，且 start 在 end 之前，区间连续。
- 引句必须是所引句子的精确子串（允许首尾空白和标点归一化）；不允许改写、拼接或翻译后冒充原文。
- 不允许输出秒数、任意文本范围或“大约从第 3 分钟开始”。
- 证据不足时允许返回 insufficient_context，而不是编一个理由。
- 每条候选要有“为什么不是更高分”的一句话，帮助用户判断边界和取舍。
- 置信度是模型自评 + 校验结果的组合，不能单独代表质量；界面要把它解释成“这条建议有多可靠”，不是“有多好看”。

### 4.6 排序与用户可见行为

排序分数 = 加权质量分 + 多样性调整 - 重复惩罚。多样性调整只在同一批候选内做，不改变单条候选的分项分。界面按“推荐顺序”展示，不按“爆款概率”展示；每条卡片显示：

- 句子边界对应的时间范围；
- 四个分项和总分；
- 一句理由 + 引用的原文；
- 置信度或“上下文不足”标记；
- 用户可把边界拖到相邻句子边界，不能拖到句子中间。

用户确认后才进入 F-0045 的短片产出；评分本身不自动应用、不自动发布。

### 4.7 主要失败模式

- 转写断句错误：把半句当一句，导致候选从半句开始；用标点、停顿和字词时间戳做二次校验，失败则降级。
- 长静音/音乐/掌声：有效语音覆盖率低，候选为空或边界漂移；先做 VAD 和语音覆盖率过滤。
- 广告、片头、订阅引导：规则剔除；模型也可能把它们当“强开场”，需要在提示词里明确排除。
- 重复内容：同一观点反复讲；用文本相似度和话题覆盖去重。
- 多说话人/重叠：超出首版范围；检测到就提示，不评分。
- 模型过度自信：所有候选都给 4–5 分；用分项锚点、反例和“必须给出为什么不是更高分”约束，必要时做分数分布检查。
- 理由编造：引句不存在或理由引入转写外事实；用精确子串校验和人工抽检拦截。

## 5. Q-2：独立评测集与指标

### 5.1 数据来源与许可

本轮没有找到可直接使用的公开中文口播评测集，因此评测集需要自建。建议优先级：

1. **创作者书面授权**：与 3–5 位口播创作者签评测素材许可，明确允许内部标注、模型评测、结果展示的范围；保存许可文本、日期、素材清单。素材不进入公开仓库，只存哈希和索引。
2. **FlyCut 自制/委托录制**：同一主题、不同说话人、不同录制条件，便于控制变量；需要出镜人授权。
3. **CC BY / CC BY-SA 公开视频**：逐个视频核验许可证和署名要求；不能只看平台标注。避免 NC、ND（禁止演绎）和来源不明的搬运视频。
4. **UP 主自己发布的切片**：只能作为辅助参考，不能作为唯一 ground truth。已发布切片可能经过重剪、加字幕、改顺序、补拍，和原始长视频的句子边界不一致；它反映的是“发布选择”，不是“独立可看的完整片段”。

不使用 Mr. HiSum、SVHighlights、QVHighlights 的数据做产品评测；它们的许可不允许商业使用。论文中的数字只作为方法背景，不作为 FlyCut 的质量基线。

### 5.2 规模与组成

建议分两阶段：

- **试点**：12 条长视频，每条 30–60 分钟，3 位标注者；目标是验证标注协议和指标是否稳定，不用于最终 go/no-go。
- **决策集**：30 条以上长视频，至少 100–200 条参考切片；按主题、说话人、录制质量、是否有 B-roll 分层。每个视频 5–10 条参考切片，允许“没有足够好片段”的视频存在，避免逼标注者凑数。

范围：中文单人口播，30–90 分钟为主；知识分享、课程、访谈式独白、个人 vlog 各占一部分。排除多说话人重叠、音乐压过人声、低于 10 分钟的素材；这些另立场景，不在本轮结论里。

### 5.3 标注协议与分歧

每位标注者独立看完整视频（可加速），按句子边界标 5–10 条 30–90 秒片段；每条给：

- start/end 句子 ID；
- 四个维度 0–5 分；
- 一句“为什么值得剪”；
- 置信度（确定/可接受/勉强）；
- 标签：must include / acceptable / reject；
- 可选：如果这段需要前文才能懂，标出缺少的上下文。

标注者先一起标 2–3 条校准视频，统一“完整”“独立”“密度”的理解；校准后各自独立，不互相看答案。争议片段由第三人裁决只用于解决协议问题，不把裁决结果当成唯一真值。

分歧要记录，不要强行合并：

- 两两匹配：时间 IoU 大于 0.5 视为同一片段；否则算不同选择。
- 选择一致性：把每个视频的候选窗口做成 0/1 矩阵，计算 Krippendorff's alpha（或 Fleiss' kappa）；分维度用 ICC 或 ordinal alpha。
- 共识集：至少 2/3 标注者选中的片段；同时保留“单人独有”的片段，作为歧义集。
- 报告分歧率、典型分歧原因（边界差 1 句、对 hook 理解不同、需要背景知识、价值判断不同）。如果试点 alpha 很低，先修协议，不急着调模型。

### 5.4 切分与防泄漏

- 按**视频**切分，不按片段切分；同一视频的所有参考片段只能在一个 split。
- 进一步按创作者/系列切分，避免同一人、同一话题的近重复内容跨 split。
- 试点：约 30% dev、50% test、20% holdout；决策集可调整为 40% dev、40% test、20% holdout。holdout 只在最终确认时看一次。
- 提示词、权重、阈值、候选窗口参数只在 dev 上调；test 冻结后只跑一次。若看了 test 再改，test 作废，改用 holdout 或重新采集。
- few-shot 示例只能来自 dev；不能把 test 的参考片段放进提示词。
- 记录每次实验的提示词哈希、模型版本、参数、评测集版本；报告里写清楚有没有污染。

### 5.5 指标定义

设视频 v 的参考片段集合为 R_v，模型前 k 条为 P_v(k)，时间 IoU 阈值为 0.5。

**前 k 条命中率（Hit@k）**：

    Hit@k = (1/|V|) * sum_v 1[存在 p in P_v(k), r in R_v，使 IoU(p, r) >= 0.5]

按视频宏平均，报告 95% bootstrap 置信区间（按视频重采样）。同时报告 Hit@1、Hit@3、Hit@5，以及随机基线：对每个视频枚举所有合法句子窗口，随机抽 k 条，计算期望命中率。随机基线很重要，因为不同视频的候选数量不同。

**排序质量（nDCG@k）**：参考片段按 must include=2、acceptable=1、reject=0 给相关性；按模型排序算 nDCG@k。它比 Hit@k 更能区分“第一条就中”和“第十条才中”。

**边界完整率**：

- 结构完整率：前 k 条中，start 是句子开始、end 是句子结束的比例；按设计应为 100%，低于 100% 就是实现 bug。
- 参考覆盖率：对匹配上的参考片段 r，计算模型片段覆盖 r 的时长比例；取平均。
- 边缘误差：匹配对的两端绝对误差之和除以 2，单位秒；报告中位数和 90 分位，避免被长尾拉偏。

**重复率**：

    Duplicate@k = 2 / (k*(k-1)) * sum_{i<j} 1[IoU(p_i,p_j) >= 0.5 或 cos(text_i,text_j) >= 0.90]

同时报告“话题覆盖数”：前 k 条覆盖了多少个不同话题；避免 10 条都在讲同一件事。

**理由一致性**：

- 引句有效率：引句能在所引句子中找到精确子串的比例；目标 100%。
- 引用 ID 有效率：所有引用的句子 ID 都存在且属于该片段；目标 100%。
- 主张支持率：人工判断理由中的每个主张是否被所引句子支持（支持/部分/不支持）；报告支持与部分支持的比例。
- 伪造引句率：引句不存在或被改写后仍冒充原文的比例；目标接近 0。
- 断章取义率：理由虽然引用了原文，但省略了改变语义的上下文；需要人工看前后各 1–2 句。

**人工可用率**：创作者或标注者看前 5 条，判断“可直接用 / 小修后可用 / 不可用”；报告可用比例。这个指标比 Hit@k 更接近产品价值，但主观性更强，必须和分歧一起报告。

### 5.6 统计与报告

- 主指标用视频级宏平均，不按片段数加权，避免长视频/多片段视频主导。
- 模型对比用配对 bootstrap（同一视频上比较两个模型），报告差值、95% CI 和效应量；不要只报一个点估计。
- 分层报告：主题、说话人、录制质量、有无 B-roll、视频时长；如果某个分层明显低于随机基线，不能用一个总平均掩盖。
- 报告所有失败样例的 ID 和错误类型；不要只展示成功案例。
- 标注分歧作为结果的一部分，不藏到附录。共识集和歧义集分别算指标。



## 6. Q-3：规则、嵌入与 LLM 评分对比

### 6.1 三种评分路线

| 路线 | 输入/信号 | 优点 | 缺点 | 成本与隐私 | 适用位置 |
|---|---|---|---|---|---|
| **规则基线** | 句子长度、标点、疑问句、数字、转折词、口癖比例、停顿时长、话题位置、重复度 | 确定性、零模型成本、离线、可解释；适合做兜底和快速筛选 | 无法判断语义完整性、反讽、上下文依赖；容易被“标题党式”疑问句骗到；不同领域要调阈值 | 几乎为零；完全本地 | 所有环境的默认兜底；先过滤明显广告/招呼/空转；为 LLM 缩小候选池 |
| **嵌入/重排** | 多语言句向量、话题分段、候选与“独立可看片段”查询的相似度、MMR 多样性、可选 cross-encoder | 比规则懂语义；本地可跑；成本可控；适合召回和去重 | 不能稳定判断“讲完了没有”“开头是否抓人”；需要选模型和许可证；中文口播领域需要验证 | 中等；可本地；模型许可需逐个核实 | 话题分段、候选召回、重复检测、LLM 前的粗排 |
| **LLM 评分** | 带 ID 的转写、全局话题表、候选窗口、评分 rubric | 能综合语义、结构、上下文和理由；能输出可读解释；适合最终排序 | 成本/延迟高；可能编造引句、过度自信、受提示词影响；长视频要分批；不同模型差异大 | 高；通常云端；必须告知发送内容 | 最终排序与理由；只对粗排后的 20–40 条候选调用，避免对全量句子逐条打分 |
| **混合（建议）** | 规则过滤 + 嵌入分段/召回 + LLM 精排 | 成本可控，质量上限高，失败可回退 | 工程复杂度最高；需要评测每一层的贡献 | 中高；可配置本地/云端 | 目标方案；先做规则基线，再逐步加嵌入和 LLM |

结论：不建议只用规则，也不建议一上来让 LLM 读完整长视频逐句打分。建议“规则召回 → 嵌入分段/去重 → LLM 对少量候选精排”的混合路线。这样既能把成本压在可控范围，也能在模型失败时退回可用结果。

### 6.2 模型输出契约与非法范围拒绝

模型必须返回**存在的句子 ID**，不能返回时间戳。Host 负责把 ID 解析成时间，并做以下校验；任何一条不通过都不能静默接受。

| 校验 | 触发条件 | 处理 | 错误码（建议） |
|---|---|---|---|
| ID 存在 | start/end 不在当前视频的句子表里 | 拒绝该候选；要求模型重试一次；仍失败则丢弃 | UNKNOWN_SENTENCE_ID |
| 顺序 | start >= end | 拒绝；不允许自动交换 | INVALID_RANGE_ORDER |
| 连续性 | 区间中间缺句，或跨到未提供的句子 | 拒绝；模型只能引用提示词里出现的连续区间 | NON_CONTIGUOUS_RANGE |
| 时长 | 解析后的时长 < 30 秒或 > 90 秒 | 拒绝；不自动裁剪，避免切半句 | DURATION_OUT_OF_RANGE |
| 覆盖率 | 片段内有效语音 < 80% | 拒绝或降置信；先做 VAD 检查 | LOW_SPEECH_COVERAGE |
| 重叠 | 与前一条候选时间 IoU > 0.5 | 保留分数更高的一条；另一条标记重复 | DUPLICATE_OVERLAP |
| 引句 | 引句不是所引句子的精确子串 | 去掉该引句；理由降级；连续失败则拒绝候选 | QUOTE_NOT_FOUND |
| 分项缺失 | 缺少四个维度中的任何一个 | 该维度记 null，置信度降低；不能用平均分补 | MISSING_DIMENSION |
| 额外时间 | 输出里出现 start_time/end_time 或秒数 | 忽略时间字段；记录违规；不按模型时间执行 | TIMESTAMP_NOT_ALLOWED |
| 越界事实 | 理由出现转写中没有的人名、数字、因果 | 标为未支持；人工复核；不进入高置信推荐 | UNSUPPORTED_CLAIM |
| 证据不足 | 模型返回 insufficient_context | 保留为“低置信/不建议”，不强行凑候选 | INSUFFICIENT_CONTEXT |

处理流程：

1. 要求模型输出严格 JSON；用 JSON schema 做第一层校验。
2. 用句子表做第二层语义校验：ID、顺序、连续性、时长、重叠、引句。
3. 校验失败时，把具体错误码和允许的 ID 范围回传给模型，只重试一次；不要无限重试。
4. 重试仍失败：丢弃该候选，回退到规则/嵌入排序；在日志里记录错误码、模型、提示词哈希，不记录完整转写。
5. 对用户展示“这条建议不可用/低置信”，不要显示一个看似正常但实际非法的片段。

### 6.3 长视频分批与时间映射

60 分钟口播不可能一次塞进所有模型上下文，也不应该这样做。建议：

- 先做全局话题表：只给模型话题标题和起止句子 ID，不要求逐句评分。
- 按话题块分批，每块控制在约 15–20 分钟转写；块之间重叠 1 句，避免边界丢句。
- 局部调用只返回该块的候选；Host 把局部候选映射回全局句子 ID，再做全局去重和重排。
- 如果某块没有合格候选，返回空，不用相邻块的内容硬凑。
- 超过 2 小时或超过预算时，明确标“部分覆盖”，不能把未处理部分当作“没有精彩片段”。

时间映射规则：

- 句子 ID 是唯一跨批次稳定的键；时间只从当前视频的句子表读取。
- 模型返回的 ID 必须属于该批次提供的 ID 集合；跨批次引用一律拒绝。
- 如果转写被编辑过（用户改字、删句），句子 ID 要版本化；旧候选引用旧版本 ID 时标失效，不静默映射到新句。
- 对已剪辑素材，先用 EDL/保留区间把源时间映射到成片时间；评分只针对源转写，展示时再映射到成片。

### 6.4 成本与质量记录

每个实验必须记录：

- 模型 provider、modelId、版本/日期、上下文长度、是否支持结构化输出；
- 提示词哈希、温度（建议 0 或很低）、最大输出 token、重试次数；
- 输入/输出 token、每 60 分钟素材的调用次数、墙钟时间、失败率；
- 每 60 分钟素材的成本（按实际账单或公开单价换算，写清单价来源和日期）；
- 非法 JSON、非法 ID、时长越界、重复、引句失败的比例；
- 隐私：转写是否离开本机、接收方、是否取得用户授权。

不要用“大概几分钱”代替实测。成本公式：

    每小时成本 = (输入 token 数 / 1M * 输入单价) + (输出 token 数 / 1M * 输出单价) + 重试成本

token 数用实际 tokenizer 对同一批转写测量，不用字数估算。中文一个字大约对应多少 token 因 tokenizer 而异，本轮不写死。

### 6.5 对比实验的 arm

建议至少跑五个 arm，同一提示词、同一候选集、同一评测集：

| Arm | 做法 | 目的 |
|---|---|---|
| A. 规则 | 只用规则分排序 | 下界和兜底；证明 LLM 是否真的带来增量 |
| B. 嵌入 | 句向量话题分段 + 候选与查询相似度 + MMR | 看语义召回/去重能到哪一步 |
| C. 小模型 LLM | 已配置文本 Provider 的小/快模型，temperature 0，JSON schema | 成本/延迟优先方案 |
| D. 大模型 LLM | 同一 Provider 的大/强模型，同一提示词 | 质量上限方案 |
| E. 混合 | B 召回 + D 精排，只对 20–40 条候选调用 | 建议的产品方案 |

具体 modelId 由部署配置决定，本轮没有调用，不能声称哪个模型更好。实验时必须把实际 modelId 和版本写进结果表；换模型后不能复用旧结论。

## 7. Q-4：理由一致性、断章取义与素材局限

### 7.1 什么叫“理由与原文一致”

一条推荐理由要通过四层检查：

1. **引用存在**：引用的句子 ID 在转写里存在，属于该片段。
2. **引文精确**：引号里的文字是所引句子的精确子串；允许空白/标点归一化，不允许改写、概括、翻译后冒充原文。
3. **主张被支持**：理由里的每个事实性主张（谁、做了什么、数字、因果）都能在引用句及其相邻句中找到依据；不能引入转写外知识。
4. **不断章取义**：引用没有省略改变语义的否定、条件、转折、对象或时间。必要时同时引用前后各 1 句。

建议的指标：

- 引用 ID 有效率（目标 100%）；
- 引文精确率（目标 100%）；
- 主张支持率（支持 + 部分支持的比例，建议门槛 ≥ 0.90）；
- 伪造引句率（建议 ≤ 0.02）；
- 断章取义率（人工抽检，建议 ≤ 0.05）；
- 理由可读性/有用性（1–5 分，作为辅助）。

这些阈值是验收建议，不是本轮实测结果。

### 7.2 常见错误

- **伪造引句**：模型把大意写成引号，或把两句拼成一句。用精确子串校验可以直接拦住大部分。
- **断章取义**：只引“所以我不建议任何人做 X”，省略前面的“如果你没有 Y 条件”。要求引用前后句，或让模型输出“缺失上下文”标记。
- **过度因果**：把“我后来成功了”说成“因为用了这个方法”。理由只能陈述转写明确说出的因果，不能补常识。
- **数字/人名错误**：ASR 同音字、英文缩写、金额、日期最容易错；这些主张必须引用原文，人工抽检优先看。
- **反讽/否定**：模型可能把反话当正面观点；中文口播里“不是说……而是……”结构要特别检查。
- **标题党式 hook**：开头有“你绝对想不到”，但正文没有 payoff；hook 分要高，但 completeness 分要低，不能互相抵消。
- **长录制上下文丢失**：分块后模型不知道前一块的人物和承诺；全局话题表和跨块摘要必须带上。
- **已剪辑素材缺少 setup**：成片可能已经剪掉铺垫，片段本身“独立”但观点不完整；这类素材要单独分层评测。

### 7.3 长录制与已剪辑素材的局限

| 素材类型 | 优势 | 局限 | 评测处理 |
|---|---|---|---|
| **长录制（30–120 分钟原始口播）** | 上下文完整，能判断“这段话是否真的讲完”；能看到铺垫、例子、收束；适合作为主评测集 | 转写长、token 成本高；话题漂移、广告、重复、跑题多；分块会丢跨块上下文；ASR 错误累积 | 主评测集；分层按话题/时长；用全局话题表 + 分块；报告“部分覆盖”比例 |
| **已剪辑素材（发布过的切片/成片）** | 更接近用户最终想发的东西；边界干净、字幕/音乐/包装完整；可作为“用户实际选择”的参考 | 已经经过人的选择，存在选择偏差；可能重排、补拍、删上下文；参考切片之间可能重叠；不能代表“从原始长视频里发现”的难度 | 辅助参考，单独报告；不作为唯一 ground truth；与长录制分开算指标，不能混在一起得出一个总命中率 |
| **UP 主自己发布的切片** | 真实发布行为，能反映创作者偏好；有标题/封面/发布时间等弱信号 | 发布选择受平台、流量、剪辑能力影响；不等于“片段本身完整”；可能一个长视频发多条互相重叠的切片 | 作为偏好/校准数据，不作为质量真值；用来分析“创作者偏好”而不是“客观精彩” |

结论：主评测集应该是**有授权的原始长录制 + 独立人工标注**；已发布切片可以作为第二参考集，用来观察创作者偏好和真实使用场景，但不能替代人工标注，也不能把“发布过”当成“高质量”。

## 8. Q-5：阈值、失败策略与结论

### 8.1 建议的 Go / No-Go 门槛

以下阈值是**验收建议**，需要维护者在报告确认时一并确认；它们不是本轮实测结果，也不是从论文抄来的“行业标准”。阈值的设计原则是：先保证结构和许可，再要求相对规则基线有真实增量，最后才看体验和成本。

| 门槛 | 建议阈值 | 说明 |
|---|---|---|
| 结构合法 | 前 5 条 100% 句子对齐；非法 ID 接受率 0；半句切点 0 | 这是硬门槛；不满足直接 No-Go 或先修实现 |
| 独立评测 | 至少 30 条授权长视频、100 条以上参考切片；视频级/创作者级切分 | 没有独立评测集不能给 Go |
| 质量增量 | Hit@5 ≥ max(2 × 随机基线, 规则基线 + 0.10 绝对提升)，且 95% CI 下界高于规则基线 | 相对门槛，避免拍脑袋的绝对分数 |
| 排序质量 | nDCG@5 ≥ 规则基线 + 0.05，且 CI 不跨 0 | 防止只靠一条幸运命中 |
| 边界 | 参考覆盖率 ≥ 0.85；边缘误差中位数 ≤ 3.0 秒 | 句子对齐是结构门槛，这里是和人工参考的贴合度 |
| 重复 | 前 10 条两两重复率 ≤ 0.20；话题覆盖 ≥ 0.60 | 防止 10 条都在讲同一件事 |
| 理由 | 引用 ID 有效 100%；主张支持率 ≥ 0.90；伪造引句 ≤ 0.02；断章取义 ≤ 0.05 | 可解释性是产品差异点，不能只看分数 |
| 可用性 | 前 5 条中至少 1 条“可直接用”，或 ≥ 50% “可直接用/小修后可用” | 由创作者/标注者盲评；阈值可按试点调整，但必须在 test 前冻结 |
| 成本/延迟 | 在 02-design 确定的单条视频预算内；报告中给出每 60 分钟实测成本与 P95 延迟 | 本轮不写死金额；没有预算就不承诺产品化 |
| 分层 | 任一主要分层（主题/时长/录制质量）不得低于随机基线 | 防止总平均掩盖某个场景完全不可用 |

判定：

- **GO**：结构、独立评测、许可、分层全部通过，质量/排序/边界/重复/理由/成本中至少 5 项通过，且没有主要分层低于随机基线。可以进入 F-0045 的设计与实现。
- **CONDITIONAL GO（有条件试点）**：质量/理由通过，但成本或延迟超预算。只对规则/嵌入粗排后的 20–40 条候选调用 LLM；先在小范围用户试用，不默认开启。
- **NO-GO**：质量不优于规则基线，或理由支持率 < 0.80，或重复率 > 0.30，或无法取得独立许可评测集，或结构合法率不达标。暂停 F-0045，不把“能跑”当成“值得做”。

### 8.2 失败与低置信策略

- **模型输出非法两次**：丢弃该批 LLM 结果，回退规则/嵌入排序；界面标“AI 暂不可用”，不显示空列表。
- **候选不足 k 条**：返回实际数量，并说明“没有找到足够多的高置信片段”；绝不为了凑数降低门槛或编造片段。
- **转写质量低**（缺标点、字词时间戳缺失、ASR 置信度低）：关闭自动评分，提示“转写质量不足，先校对字幕”；规则基线也只能给粗略建议。
- **话题分段失败**：退回固定句子窗口；界面说明“按句子窗口推荐”，不假装有话题理解。
- **长视频超出预算**：分层处理并标“部分覆盖”；未处理部分不参与排序，不能当作“没有精彩片段”。
- **多说话人/重叠**：标“超出当前范围”；不强行按单人口播评分。
- **低置信候选**：仍然可以显示，但必须带“低置信/建议人工确认”标记，排序靠后，不进入默认前 3。
- **用户反馈“没有一条可用”**：记录视频 ID、候选 ID、原因；作为下一轮评测的失败样例，不立即在线调参。
- **模型/Provider 不可用**：保留上次结果或规则结果；不静默清空；告知用户重试。

### 8.3 不把评分等同于传播或爆款

- 产品文案使用“推荐分”“剪辑优先级”“可看性”，不使用“爆款概率”“上热门概率”“病毒指数”。
- 评分的目标是“帮创作者更快找到完整、独立、可剪的片段”，不是预测播放量、完播率或平台推荐。
- 评测的 ground truth 是人工“愿不愿意剪/能不能独立看”，不是播放数据。播放数据有平台分发、账号基础、发布时间、封面标题等混杂因素，不能拿来当评分标签。
- 如果未来要做“传播效果校准”，必须单独立项：拿到有授权的发布结果数据，控制账号/题材/时间等变量，明确选择偏差，并单独报告；不能把本轮评分直接改名为“爆款预测”。
- 界面首次出现评分时给一句解释：分数只反映片段本身的剪辑友好度，不代表平台表现。

### 8.4 逐条回答

**Q-1 结论**：可行。以句级 SubtitleChunk 为唯一时间基准，先做话题分段，再枚举 30–90 秒的句子对齐窗口；评分拆成 hook、completeness、context independence、information density 四个 0–5 分维度，每个维度引用句子 ID 和原文。开头吸引力看前 1–2 句是否给出问题/反差/利害/payoff；完整性看是否有 setup 和收束；上下文独立性看人名、指代、事件是否在片段内解释；信息密度看单位时间的新信息、例子、数字和 filler 比例。总分只用于排序，界面必须展示分项和理由。这个设计有论文和开源实现的间接支持（SVHighlights 的段落化、supoclip 的 unit ID、publikclip 的句子吸附），但**没有在中文口播上实测**。

**Q-2 结论**：需要自建许可评测集。建议 12 条试点、30 条以上决策集，3 位标注者，按视频/创作者切分，至少 100–200 条参考切片；记录 Krippendorff's alpha/ICC 和分歧集，不强行合并。Hit@k 按视频宏平均、IoU 0.5 匹配；边界用结构完整率、参考覆盖率和边缘误差；重复率用时间 IoU 或文本余弦；理由用引句精确率、引用 ID 有效率、主张支持率和断章取义率。公开的非商用数据集不能用于产品评测。**本轮 Not run**，因为没有授权素材和标注。

**Q-3 结论**：建议规则/嵌入/LLM 三条路线都做基线，最终采用混合：规则过滤和兜底，嵌入做话题分段/召回/去重，LLM 只对 20–40 条候选精排。模型必须返回存在的句子 ID，Host 负责时间映射；非法 ID、逆序、非连续、时长越界、重叠、引句不匹配都要拒绝，重试一次后回退。长视频按话题分块、1 句重叠、全局话题表和全局重排；成本按实际 tokenizer 和账单测量。**本轮没有调用任何模型，Not run**。

**Q-4 结论**：理由可以与原文一致，但必须用“精确引句 + 句子 ID + 主张级校验”约束，不能只让模型自由写一段解释。主要风险是伪造引句、断章取义、过度因果、数字/人名错误、反讽和长视频上下文丢失；已剪辑素材还有选择偏差和缺少 setup 的问题。长录制适合做主评测集，已发布切片只能做辅助参考。**本轮没有做人工一致性实验，Not run**。

**Q-5 结论**：建议 **CONDITIONAL GO**，不是无条件产品化。先做独立评测集和规则基线，再跑混合方案；只有结构、许可、质量增量、边界、重复、理由和成本门槛都满足，才进入 F-0045。失败时回退规则/嵌入，候选不足不凑数，低置信明确标注，长视频标部分覆盖。评分只代表剪辑友好度，不代表传播或爆款概率。**本轮没有实测数字，不能给出“已达到”结论。**

### 9.2 具体计划

**E0：离线 schema 与校验演练（0.5 天，不需要模型）**

- 取 3 条已有转写（可用项目 demo 素材，需确认许可），手工构造 10 个候选区间。
- 用 JSON schema 和句子表检查：ID 是否存在、区间是否连续、30–90 秒、引句是否精确、重叠是否去重。
- 产出：校验规则表、错误码样例、失败用例；不调用模型。
- 通过标准：所有非法样例都被拒绝，合法样例不被误杀。

**E1：标注试点（2–3 天，12 条视频，3 位标注者）**

- 按 5.1 取得授权，按 5.3 标注；先校准 2–3 条，再独立标。
- 算 Krippendorff's alpha / ICC、共识集、分歧原因；检查 30–90 秒候选是否足够、句子边界是否稳定。
- 产出：标注协议修订、试点指标、失败样例；不用于最终 go/no-go。
- 通过标准：协议可执行；标注者能在合理时间内完成；分歧可解释。若 alpha 过低，先修协议。

**E2：决策集对比（5–8 天，30 条以上视频）**

- 跑 A 规则、B 嵌入、C 小模型、D 大模型、E 混合五个 arm；同一候选集、同一提示词、temperature 0。
- dev 上调提示词/权重/阈值；test 只跑一次；holdout 最后看。
- 产出：Hit@1/3/5、nDCG@5、边界覆盖率/边缘误差、重复率、理由支持率、成本/延迟、分层结果。
- 通过标准：按 8.1 的 Go/No-Go 表判定；没有达到就写 No-Go 或 Conditional，不硬拗。

**E3：错误分析与红队（2 天）**

- 抽取 30 条失败/低置信样例，按错误类型归类：ASR、边界、上下文、hook、理由、重复、模型过度自信。
- 构造 10–20 条“陷阱”样例：反讽、否定、数字、同音字、跨段指代、广告、重复观点、已剪辑素材。
- 产出：失败样例库、提示词修订建议、是否需要在 F-0045 加“人工确认/低置信”交互的结论。

## 10. 对后续需求的影响

- **F-0045 推荐片段列表**：可以在本报告确认后进入设计，但必须按“有条件试点”处理：只展示建议，不自动应用；每条带句子边界、四个分项、理由、置信度；低置信/非法结果回退规则；用户确认后才生成短片。不要把“评分”做成“爆款预测”。
- **F-0046 竖屏导出**：不依赖评分质量，可继续按原计划设计；但如果 F-0045 的片段元数据要存源句子 ID/时间范围，导出侧要能接受“源时间 → 成片时间”的映射。
- **F-0049 批量导出**：不依赖评分算法；批量任务应复用 F-0045 已确认的片段，不在导出阶段重新评分。
- **F-0050 标题/简介/标签**：可以复用本报告的“引用原文、不要编造”原则；标题生成不能把评分或标题当成传播承诺。

## 11. 结论可信度、未测范围与重评条件

**可信度：**

- 论文/仓库事实：较高。关键论文的来源、数据集规模、许可证和开源实现文件已核对；引用日期为 2026-11-09。
- 方法设计：中等。候选生成、评分维度、校验和指标有多个实现/论文的间接支持，但没有在中文口播上验证。
- 质量结论：低。本轮没有跑模型、没有标注、没有 Hit@k；不能声称“效果可用”。
- 中文场景：低。没有找到中文 30–90 秒口播的公开基准；中文 ASR 断句、同音字、口癖、中英混排都未测。
- 许可结论：关键数据集/代码已核对；个别仓库（如 PHD-GIFs 数据、部分学术代码）许可证未逐文件核实，使用前要再查。

**未测平台/场景：**

- 中文单人口播的真实 ASR 质量、标点恢复、字词时间戳；
- 多说话人、访谈、重叠说话；
- 已剪辑素材、带 B-roll/音乐/包装的成片；
- 2 小时以上长录制、直播回放；
- 桌面端与 Web 端的实际延迟/成本；
- 不同文本 Provider、不同模型、不同上下文长度；
- 用户真实接受度、留存、发布行为；
- 任何传播/播放效果。

**何时需要重评：**

- 出现可用的中文口播公开基准，或 FlyCut 自建评测集完成；
- 更换评分模型、提示词、ASR 模型或断句逻辑；
- 产品从“建议”变成“自动应用”；
- 支持多说话人、已剪辑素材、竖屏导出等新场景；
- 距本次调研超过 6 个月，或论文/仓库有重大更新；
- 维护者决定把评分用于对外宣传、定价或平台效果承诺（这时必须重新做独立验证，不能沿用本报告）。
