# F-0001 中文口播转写质量基准：需求说明

> 2026-11-05 流程调整：由原立项（01-intake）改名而来，内容未改。

## 来源

- Epic 候选 **E-01/1**（[E-01 转写](../../../10-product/epics/E-01-transcription.md)，2026-11-05 确认）：「中文口播转写质量基准：补充真实口播样本（单人单机位、10–60 分钟，许可可入库或可复现下载，含至少 2 段未剪辑的原始录制）、人工校对的逐字参考文本（保留语气词和口误）、输出字错率、字词时间戳误差、语气词召回率（嗯 / 啊 / 呃 / 额等是否被原样转写）和短词时间戳误差的评测命令、各 Provider 对比结论」。
- 维护者原话（2026-11-05）：「直接立项 E-01/1」。
- 路线图阶段一第 1 项（[roadmap.md](../../../10-product/roadmap.md)）。

## 要解决的问题

所有剪辑和字幕能力都建立在转写上，但我们现在**判断不了转写准不准**：

- 测试素材主要是新闻发布会，接近口播的只有 `zh-podcast-3min`（3 分钟，播客对谈）和刚加入的 `bili-BV1Rex26dEWF`（20 分钟单人口播，但已粗剪过、画面烧录字幕）。没有一段未剪辑的原始口播录制。
- `tests/media/baselines/*.json` 是 SenseVoice 自己的输出，只能看结果有没有变化，不能算字错率。例如 `zh-podcast` 基线里「视频号」被识别成「视频好」，但没有参考文本就统计不出这类错误有多少。
- 去口癖（E-06/3、E-06/7）要求 ASR 原样转写语气词，逐字高亮（E-03/2）和字词级剪切要求字词时间戳准确，这两项都没有量化数据。
- 不同 Provider / 模型之间没法客观比较，E-01/2「默认模型推荐」无从下手。

## 目标用户与场景

- **口播创作者**（[vision.md](../../../10-product/vision.md)），单人、单机位、室内，一次录 10–60 分钟，录完导入 FlyCut 转写后粗剪。
- 这个需求本身是内部调研，用户感受不到；它决定的是用户能感受到的东西：字幕要改多少处、去口癖能找出多少、剪辑点会不会吞字。

## 竞品怎么做

- 剪映、Descript、Gling 等都不公开转写准确率，只给「智能识别」的结果；Descript 有逐字（verbatim）转写模式，保留 um、uh 供删除（来源：产品官网功能介绍，具体效果待核实）。
- 公开的中文 ASR 评测（如 AISHELL、WenetSpeech 等测试集）多是朗读或新闻语料，和口播的口语、语气词、语速差别大，不能直接代表口播场景。
- 我们的不同：用真实口播素材、逐字参考文本，同时评测语气词召回和字词时间戳——这两项是剪辑类功能最关心、竞品也不公开的指标。

## 获客价值

间接。评测结论可以写成公开文章（「中文口播转写哪个模型最准」），对应 vision.md 的内容平台渠道；默认模型选得好，直接影响用户第一次转写的体验和激活率。

## 优先级

P0（[decisions.md](../../../decisions.md#产品定位与优先级)：转写 + 添加字幕是底座）。现在做，是因为阶段一的去静音、去口癖、逐字高亮都依赖它的结论，而且它不依赖任何其他需求。

## 研究问题

调研阶段（02-research）要回答：

1. 内置 sherpa-onnx 支持的模型系列（sidecar 里有 SenseVoice、Paraformer、Whisper、Zipformer CTC、FireRedASR）、FlyCut Cloud、FunASR Provider 在中文口播上的**字错率**各是多少。
2. **语气词召回率**：嗯 / 啊 / 呃 / 额 / 那个 / 就是 等是否被原样转写；有没有模型会自动删掉语气词。
3. **字词时间戳误差**：整体误差和短词（单字语气词）误差；是否需要 E-01/6 强制对齐校准。
4. **长音频**：60 分钟素材能否稳定跑完，耗时和内存。
5. 结论：哪个模型可以作为桌面端默认推荐，「可用标准」怎么定义（给 E-01/2 用）。

交付物：样本清单与获取方式、逐字参考文本、评测命令（例如 `pnpm eval:asr`）、对比报告。

## 不做的代价

默认模型只能凭感觉选；去口癖、逐字高亮做完才发现 ASR 不转写语气词或时间戳不准，返工整条剪辑线。

## 已知约束与风险

- **素材许可**：未授权的素材只能本地测试、不能入库（`tests/media/` 已 gitignore）。基于未授权素材写的参考文本也属于衍生内容，是否入库需要判断。维护者自己录的素材没有这个问题。
- **参考文本有偏差风险**：如果先用某个模型的输出再人工修改，人工容易漏改，结果会偏向那个模型。需要逐字听写或至少两遍校对。
- **字词时间戳的参考值**：人工逐字标时间成本很高。可以用强制对齐工具生成参考时间戳再抽查，但这样测到的是「和对齐工具的差距」，要在报告里说明。
- **Provider 覆盖**：FlyCut Cloud 需要服务地址和 API Key；FunASR Provider 需要单独安装 Python 环境。拿不到的只能标「未测」。
- **与已有决定**：不冲突。评测只读识别结果，不改 Provider 协议；遵守「字词级剪切只看通过校验的字词时间戳」。

## 文字参考确认方式调整（2026-11-08）

维护者原话：「把精校文案作为 确认版本」。按此明确指令，两段COSCUP视频同目录的精校文案直接作为本轮已确认的文字参考，替代原先等待逐句听校的前置条件；不再等待处理模型分歧。该指令不表示人工听校已实际发生，也不批准把原ASR时间戳当独立真值。评测报告保留精校文本源于SenseVoice的偏差说明，时间误差与默认推荐仍需对应证据和报告验收。
